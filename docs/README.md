## 개발·발표 문서 읽는 순서

요구사항 → WBS → 시스템/시퀀스 → IA → API → ERD 순으로 전체 목표에서 상세 계약으로 내려간다. 입력 타입·검증 책임은 API/ERD와 함께 확인한다. 발표에서는 각 문서의 요약·도식을 사용하고 상세 계약은 개발 기준으로 참조한다.

| 요청 산출물 | 기준 문서·역할 |
| --- | --- |
| 요구사항 정의서 | [요구사항](요구사항.md) — ID·수용 조건·요구/구현 상태 |
| WBS | [작업 분해](planning/작업_분해_WBS.md) — 공수·의존성·요구사항/검증 추적 |
| 시스템 구성도·시퀀스 다이어그램 | [시스템과 주요 시퀀스](specifications/시스템_구성과_주요_시퀀스.md) — 처리·배포 경계와 3개 핵심 흐름 |
| IA | [관리자 화면 구조](specifications/관리자_화면_구조.md) — 메뉴 계층·업무 이동·화면/API 연결 |
| API 명세서 | [API](specifications/API_명세서.md) — 현행 8경로와 초기/후속 목표 |
| ERD | [데이터 모델](specifications/데이터_모델_ERD.md) — 현행 물리 관계·목표 논리 계약 |

7종 자료는 기존 6개 문서에서 관리한다. API/ERD의 Exa 공통 세부 타입·프로필은 [미결정 계약](specifications/뉴스_입력과_검증_책임.md#미결정-계약과-결정-조건)에 결정 담당과 완료 조건을 남긴다.
