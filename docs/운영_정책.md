# 운영 정책 · 개인용 Telegram 뉴스레터

- 기준: 2026-11-05, Asia/Seoul. 기본 목표는 월~금 중 한국 거래일 아침08:00 하루1회이며14/16시는 선택·기본 꺼짐이다. 사용자 결정에 따라 한국 휴장 평일에도 모든 가격·뉴스 알림을 발송하지 않는다. 구현·제공처 허용 확인과 구분한다.

아침1회를 위한 제품 설계는 **월~금 중 한국 거래일07:50 수집 시작/뉴스 발행 기준 고정 →07:58까지 검사·편성 저장 목표 →08:00 발송**이다.07:00 준비라는 초기안은 이 기준으로 대체한다.07:50에 종목/설정 버전을 고정하고 ETF 종가·Finnhub 목록·공식 발표를 수집한다. 뉴스는 당일07:50 이전 발행분 중 미전달 최대96h 중 중요도 우선·같은 점수에서 최신순이며 기준 이후 발행분은 다음 한국 거래일 후보로 넘긴다. 발송 직전 추가 재수집은 기본 범위에 두지 않는다. 제공처에서 늦게 수록해 이번 목록에 없었던 기사까지 확보했다고 가정하지 않는다.

07:58은 편성 완료 목표이지 별도 전송 예약이 아니다. DB에 준비됨/부분 준비/실패와 사유를 저장하고08:00에 준비된 편성만 보낸다. 정상 가격에 뉴스 실패 안내를 붙일 수 있으나 준비된 편성이 전혀 없으면 발송 보류·실패 기록으로 처리한다. 안전한 일시 실패 재시도는08:10 마감과 기존 송신 정책을 따르고, 성공 여부 불명인 전송을 다시 보내지 않는다. worker 구현·격리 검증과 실제 정시 수신 인수는 구분하며11/4 08시 제공처 표본 관측과도 별개다.

오전 가격은 전날 달력 날짜가 아니라 최근 완료 한국 거래일이다. **한국 휴장 평일과 주말에는 아침·오후 가격/뉴스 알림을 모두 발송하지 않는다.** 휴장일은 정상 건너뜀으로 기록하고 휴장 안내만의 Telegram 알림도 보내지 않는다. 휴장 중 새 미국 뉴스는 다음 한국 거래일에 미전달 최대96h·중요도 우선·전체3건 기준으로 선정하며 밀린 날짜별 알림을 몰아서 보내지 않는다. 오후 두 슬롯은 사용자가 각각 켠 경우에만 처리하며 휴장 시 생성하지 않는다. 발송일의 한국 개장 여부는 준비 시점과 전송 직전에 확인하며, 개장 여부를 확인할 수 없으면 발송을 보류한다. 특수 개장일에는 거래소 달력을 우선하고 오후 가격은 해당 시각이 정규장 중인지/마감 후인지도 확인한다.

마감 후 밀린 편성을 몰아서 보내지 않는다. 전역 일시 중지는 수집/이력 조회와 발송을 구분하며 전송 직전 서버에서 재확인한다. 해제해도 만료된 편성을 재전송하지 않는다.

## 뉴스 중요도

11/5 사용자 결정에 따라 최신순 단독 선정을 대체한다. 제목에서 시스템위험100·통화정책95·물가90·고용85·GDP/성장80·정부/무역정책75·주요기업실적60·시장전반50·기타 적격20점 중 최댓값을 사용한다. 공식 자체 발표는5점 가산(최대100)한다. 점수→동점이면 공식 출처→최신시각→안정 ID 순서며 선정 점수·이유·규칙버전을 남긴다. 링크 확인 요청 예산도 같은 중요도순으로 쓴다. 이는 설명 가능한 초기 휴리스틱이며 실제 가격 영향이나 투자 추천을 뜻하지 않는다. 출처/권리·미래/96h 초과 제외·기발송/사건 중복·전체3건 상한은 계속 적용한다. [구현·유료1건·실측](../tasks/logs/2026-11-05_뉴스_중요도와_로컬_실행.md).

## 가격·등락률·지연

- 시장은 KRX(`J`), 통화는 KRW다. ETF 시장가격과 지수 포인트·NAV·총수익률을 구분한다.
- 오전/마감 가격 변동률은 비수정 정규장 종가를 직전 한국 거래일 비수정 종가와 비교한다. 오후는 장중 가격을 전 거래일 비수정 종가와 비교한다. Decimal로 `(가격 / 직전 종가 - 1) * 100` 계산 후 표시 반올림한다.
- 분배락/분할 등 사건이 있는 날에는 가격 변동률임을 표시한다. 공급자 조정 기준의 전일비·기준가격 수익률을 혼합하지 않는다. 분할로 직접 비교가 부적절하거나 기준을 대조할 수 없으면 등락률은 확인 불가로 두고 가격/사유만 표시한다. 분배금을 더한 투자 총수익률은 계산하지 않는다.
- 모든 값에 거래일·출처·실제 가격 기준시각(확인 가능 시)·조회시각·지연 여부를 남긴다. REST 조회시각을 체결시각으로 대체하지 않는다.
- 일봉이 날짜만 제공하면 실제 가격시각은 미제공으로 남기고 달력의 예정 마감시각을 별도 필드로 기록한다. 이는 장중 신선도 통과나 실제 확정시각 관측을 뜻하지 않는다. KIS 휴장일의 개장 판정은 `opnd_yn`을 대조하며 `tr_day_yn` 단독으로 판단하지 않는다. [11/3 실측 근거](../tasks/verification/market/국내_ETF_API_표본_검증.md).
- 장중 가격은 제공처 기준시각으로 5분 이내인 값만 정상 표기한다. 더 오래됐거나 기준시각을 확인할 수 없으면 `현재가 확인 불가`로 표시하고 오래된 값을 현재가로 보내지 않는다. 이 5분은 제품 신선도 기준이며 KIS 제공 지연을 검증한 수치가 아니다. REST에 필요한 시각이 없으면 체결 조회 등 보완 경로를 인수하기 전 장중 자동 전송을 활성화하지 않는다.
- 16시에도 당일 확정 종가가 없으면 과거 종가를 당일 종가로 대체하지 않는다. 종목별 실패는 확인 불가로 표시하고 정상 종목은 전달하되 전체를 정상 성공으로 집계하지 않는다. 전 종목 실패 시 가격 본문 대신 데이터 장애 상태를 기록/알린다.

## 뉴스·자동 발송

일반 뉴스 제목·원문 링크와 BLS·BEA·Federal Reserve Board 자체 발표 AI 요약을 합쳐 전체 최대3건 선정한다. 일반 뉴스는 허용 RSS/API의 원제·매체·발행시각·원문 링크만 전달하고 본문 수집·AI 번역/요약은 초기 제외한다. 공식 발표는 직접 RSS/API/페이지 수집을 기본으로 하며 페이지별 권리 표시를 검사한다. 일반 뉴스는 Finnhub Free general 본인 개인용 채택이며 개인 이용 조항에 따라 별도 이메일 없이 진행한다. 본인1명 제한·링크/보존 삭제·worker 기술 검증 후 자동 전송한다. Google 경유 미해결·HEAD 확인 실패는 별도 사유를 기록한다. Exa는 초기 필수 경로에서 제외한다. 기관 원문 텍스트/수치에 출처·원문 링크·AI 요약 표시를 붙인다. 최근24시간 후보와 직전 성공한 아침 호 이후 미전달 최대96시간 후보를 중요도순으로 선정한다. 최신성만으로 중요도가 높은 후보를 밀어내지 않는다. 오래된 건은 발행일을 명시하고 새 뉴스처럼 표시하지 않는다. 휴장/실패 후에도 전체 상한 3건은 유지한다. 정상 0건과 제공처 실패를 구분한다.

권리·시각·근거·중복·수치 검사를 통과한 후보만 짧은 사실 요약·출처·원문 링크로 보낸다. 불확실 후보는 제외하고 관리자에 사유를 남긴다. 후보 제외/뉴스 수집 장애는 가격 보고를 막지 않으며 `적격 뉴스 없음`과 `뉴스 수집 실패`를 구별한다. 기사 표현 전체·이미지·유료벽 우회는 하지 않는다. 개인 이용도 제공처·원매체의 허용 범위 확인이 필요하며 권리 미확인은 자동 발송 대상에서 제외한다.

매회 사람 승인은 요구하지 않는다. worker가 활성 설정·허용 수신자 1명·검사 결과·예산·마감·데이터 신선도를 전송 직전에 확인한다. 생성 시점의 종목/설정 버전을 고정하고 전송 전 비활성·일시 중지는 다시 확인한다. Telegram에서 승인/설정 명령은 제공하지 않는다.

## 전송·중복·보안·비용

- 본인과 봇의 1:1 chat만 allowlist로 설정한다. 봇 토큰·chat 식별자는 서버 설정에 두고 브라우저/공개 로그에 노출하지 않는다.
- X 글 수 규칙을 폐기하고 Telegram 메시지 제한 안에서 코드로 분할한다. 편성은 수신자+KST 날짜+슬롯 유일 키, 조각은 편성+순번 유일 키와 DB 원자 점유를 사용한다.
- 호출 전 시도 저장, 성공 시 message_id 저장. 전체 성공/부분 성공/실패/결과 불명을 구분한다. 429는 retry_after와 마감에 따라 처리한다. 네트워크 timeout처럼 성공 여부 불명은 자동 재송신하지 않는다. 수신과 DB 기록의 원자성을 가정하지 않는다.
- 관리자 정적 화면과 API 모두 Lightsail + Tailscale Serve로 비공개 접근한다. 본인 계정·기기만 허용하고 Funnel/공개 관리자 포트는 사용하지 않는다. Google 로그인·세션은 유지한다. [배포 근거](research/비공개_배포.md)를 따른다.
- 변경 API에는 인증·CSRF·revision·감사를 적용한다. 한도 10은 서버 트랜잭션으로 검사한다. 브라우저는 KIS·Finnhub·OpenAI·DB에 직접 접근하지 않는다.
- 월 예산 50,000원 유지. 이전 X 비용 견적은 폐기된 기준이며 새 제공처/서버/AI 비용은 재산정 전이다. 예상 비용 초과 시 유료 수집·생성을 차단하고 관리 화면에 표시한다.

기본 아침1회는 KIS 신청/인증·3종목 종가·이용 조건·뉴스 권한·모의/장애/중복·본인 수신·백업 복원을 인수한 뒤 자동 발송을 켠다. 선택14시는 장중 응답/실제 시각/지연 기준, 선택16시는 당일 확정 종가를 각각 추가 인수한 뒤 켤 수 있다. 현재는 제품 정책 확정이며 실제 예약/송신은 미설정이다. 이전 미국 거래일5일 기준과 승인 필수/PM 차단 코드는 새 정책의 합격 근거가 아니다.
