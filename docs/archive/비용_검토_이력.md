## 콘텐츠·발행 방식

아침 스레드는 `지수 → 뉴스[1] → 뉴스[2] → 뉴스[3] → 핵심 정리·출처 링크`로 구성한다. 뉴스가 적으면 해당 글을 생략한다. 각 뉴스 글에는 출처명·번호를 남기고 실제 원문 링크는 마지막 글 한 곳에 모은다. 기사와 링크의 대응 관계는 관리자 화면에서도 확인할 수 있어야 한다.

마지막 글의 링크·출처명·핵심 정리가 길이 제한을 넘으면 부가 정리를 줄이고, 그래도 넘으면 우선순위가 낮은 기사를 제외한 새 버전을 검증·승인한다. 출처를 누락하거나 링크를 숨기지 않는다. 제공처 조건이 기사별 별도 링크를 요구해 이 형식을 허용하지 않으면 해당 제공처의 채택을 보류한다. 자동으로 유료 글을 늘려 예산안을 우회하지 않는다.

기업 뉴스는 한 사건을 원문 링크와 함께 한 글로 작성한다. 길면 부가 설명을 줄이고 핵심 근거·수치·단위·기간을 보존할 수 없으면 보류한다. 기존 사건 선정·후속은 다음 아침 검토·중복 금지를 유지한다. 개발·테스트에는 관리자 승인, 안정화 후에는 검증 통과 자동 게시를 적용한다.

아침 07:30 정보 기준·08:00 목표·09:00 마감, 기업 뉴스 운영일 09:00~17:30 30분 확인·18:00 마감은 유지한다. 5분 발행 작업은 reviewed의 승인 후보 또는 auto의 검증 통과 후보를 처리한다. 기업1건이 게시되거나 예약되면 당일 한도를 적용하고 이후 후보는 다음 아침 검토로 넘긴다. 명확한 미게시·철회 시 예약 해제와 부분 게시·성공 불명의 복구 원칙을 유지한다.

## 월 예산

**약 2.1만 원은 정액 요금이나 최저 보장 금액이 아니라 사용량 가정의 부분 견적**이다. 월 총 상한 30,000원과 정상 운영 계획 24,000원 이하를 유지한다.

월 아침/기업 운영일 각 22일, 아침 5개 글·기업 1개 글을 가정한다. URL 포함은 하루 2개, 일반 글 4개다. 정상 생성 응답으로 ID를 확인할 수 있어도 보수적으로 일반 게시물 조회를 글당 1회 잡는다.

X와 AI 단가는 [조사한 비용표](../research/월_비용.md)를 따른다. 기업 발행 감소에 따른 AI 절감은 실측 전이라 추가로 차감하지 않았다. 1,500원은 현재 환율 조회값이 아니라 계산 가정이며 세금·수수료·청구 환율은 실제 결제로 재확인한다.

월 3만 원까지 약 8,613원이 남지만 지수·뉴스 공개 이용료·시험·재시도·정정·전기료·추가 백업은 아직 포함하지 못했다. 현재는 데이터 사용권 미확인이므로 완성된 운영 총액을 2.1만 원으로 확정하지 않는다. 22일보다 운영일이 많거나 출력·조회량이 늘면 비용도 증가한다. 유료 데이터가 필요하면 잔여 예산으로 가능한지 확인하고 임의 구독하지 않는다.

요청 전 확정 비용·미정산 비용·새 요청 비용을 확인하고 총 30,000원 초과 예상 시 중단한다. 24,000원부터 경고한다. 정상 생성 응답의 ID를 보존해 불필요한 재조회를 줄이며, 필수 결과 확인·검증을 생략해 절약하지 않는다. 자동 충전은 사용하지 않는 구성을 기본으로 한다.

## 로컬 운영 준비와 검증

- PC는 아침 준비 전부터 기업 뉴스 종료까지 전원·네트워크가 필요하다. 절전·재부팅·접속 실패를 기록하고, 재시작 후에도 마감 지난 글을 자동 게시하지 않는다.
- 작업 스케줄러와 Streamlit은 같은 영속 SQLite를 사용한다. 승인 버전·한도 예약·게시 상태를 저장하고 중복 실행을 막는다.
- 기존 관리자 로그인 원칙을 유지한다. 원격 공개 접속은 초기 구성에 포함하지 않는다. 외부 접속·도메인·추가 호스팅이 필요하면 비용과 구현 범위를 다시 검토한다.
- DB는 일관 사본으로 일일 백업하고 기존 보유 별도 매체 등으로 복원 가능한 사본을 보관한다. 실제 백업 경로·용량은 구현 시 정하며 Git에 원문·키·운영 DB를 넣지 않는다.
- API 권한·자료 이용 조건·한글 길이·원문 링크 대응·하루 1회 한도·PC 재시작·예약 지연·DB 복원을 시험한다. 실제 외부 게시 검증은 해당 게시 건에 대한 별도 명시적 승인 후 수행한다.

이 결정은 이전의 기업 하루 최대 2회, 기업 사건당 최대 2개 글 추천, 단일 유료 VM 추천, 기사별 URL 배치를 변경한다. 기존 조사표의 2회·VM 금액은 비교 이력으로 보존하며 현재 구현 기준은 이 문서와 갱신한 설계서를 따른다.

## 결론

2026-10-23 [yfinance](../research/ETF_가격_데이터.md) 채택에 따라 지수용 일반 조회료·라이브러리 사용료는 계획상0원이며 유료 웹 검색료는 기본 구성에 더하지 않는다. 이전 검색안의 월22일·하루2번 도구료 $0.44(약799원)와 약22,185원 견적은 비교 이력이다. 현재 X·AI·로컬 구성의 부분 견적은 약21,387원이며 공개 자료 이용 비용까지 확정된 총액은 아니다.

이 문서는 변경 전 편성의 비교 견적이다. 이후 사용자가 [초기 비용 절감 구성](../research/월_비용.md)을 선택했으며 현재 기준은 기존 PC·기업 하루 1건·아침 링크 통합, 가정 부분 견적 **21,387원**이다. 아래 2회·VM 금액을 현재 운영 구성으로 적용하지 않는다.

현재 최대 편성에 가까운 사용량으로 URL을 담은 X 게시를 지속하고 $7 VM을 운영하면, **지수·뉴스 이용료를 제외해도 월 약 4.8만 원**이다. 환율 여유와 세금 가정까지 포함하면 약 5.8만 원이다. 따라서 월 3만 원으로 운영 가능하다고 결론 내릴 수 없다. 무료 데이터의 공개 게시 권한도 별도 해결해야 한다.

이는 매일 최대량을 반드시 게시한다는 뜻이 아니다. 실제 선정 기사가 적으면 줄어든다. 추가 발행 수를 줄이거나 게시 방식·배포안을 바꾸는 것은 제품 변경 대안이며 현재 요구사항을 임의 변경하지 않는다.

## 계산 가정

- 아침 운영일 22일·기업 운영일 22일을 각각 가정한 비교용 월이다. 실제 달력의 두 운영일은 다를 수 있다.
- 달러당 1,500원은 **현재 환율 조회값이 아닌 계산 가정**이다. 계획 환산은 환율 여유 10%와 세금 10%를 가정해 `1,500 × 1.1 × 1.1 = 1,815원/USD`로 계산한다. 실제 세금·환율·카드 수수료는 결제 시 대조하며 수수료는 여유금에서 별도 고려한다.
- 정상 시나리오는 아침 5개 글(기사 URL 포함 3개+기타 2개), 기업 뉴스 2건을 각 1개 글로 게시한다. URL 포함 110개·기타 44개·전체 154개다.
- 증가 시나리오는 기업 2건을 각 2개 글로 게시한다. URL 포함 110개·기타 88개·전체 198개다. 추가 글에 URL을 반복하면 그 글도 URL 단가를 적용해야 한다.
- 게시 결과 조회는 전체 게시물당 일반 read 1회로 보수적으로 잡는다. 다른 리소스·추가 확인·중복 실행 호출은 별도다. URL 게시 응답 자체에 담긴 ID만으로 완료하면 조회 수가 줄 수 있다.

## 대안 1 · 아침 출처 링크를 한 글에 모으기

아침을 `지수 → 뉴스1 → 뉴스2 → 뉴스3 → 핵심 정리·출처[1][2][3]`로 배치한다. 뉴스 글에 출처명·번호를 남겨 마지막 글의 원문 링크와 연결한다. 단축 URL·이미지에 URL을 숨기는 방식은 제안하지 않는다.

아침의 URL 포함 글을 3개에서 1개로 줄이면 월 22일 기준 `44 × ($0.200−$0.015) = $8.14`를 줄인다. 링크를 없애는 대신 배치를 바꾸는 제안이며 기존 ‘기사별 요약과 링크’의 표현 방식이 달라진다. 독자는 출처 글까지 이동해야 한다. 출처·저작권 표기 조건이 기사별 직접 링크를 요구하면 적용할 수 없다. 3개 URL의 가중 길이·언론사명·정리 문장이 한 글에 들어가는지는 실제 예시로 확인하고, 넘치면 추가 글 비용을 다시 계산한다.

기업 뉴스는 각 사건의 원문 링크를 유지한다. 하루 2건을 유지하면 월 X는 URL 66개 $13.20 + 일반 88개 $1.32 + 일반 조회 154개 $0.77 = **$15.29**다.

## 무료 클라우드는 대안인가

[GitHub Actions](https://docs.github.com/en/billing/concepts/product-billing/github-actions)는 공개 저장소 표준 runner 무료·비공개 포함량 내 무료가 가능하다. 그러나 [예약 실행](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#onschedule)은 시각 보장이 없고, 원격 DB와 사이트가 필요하다. 비공개에서 5분 승인 확인을 매번 실행하면 기존 조사 가정 2,904분으로 무료 2,000분을 넘길 수 있다. 따라서 단순히 VM을 Actions로 바꿔 전체 비용을 $0 처리하지 않는다.

[Supabase Free](https://supabase.com/pricing)는 DB 500MB와 1주 비활동 휴면 조건이 있다. 무료 사이트·DB·예약 작업을 연결하면 유료 구독을 줄일 수는 있으나 3개 서비스의 인증·연결·백업·지연을 관리해야 한다. 이 프로젝트에서 단순함을 우선하면 기존 PC 시험 후 필요할 때 클라우드로 이전하는 순서를 추천한다. PC를 켜둘 수 없다면 무료 조합의 실제 지연과 사용량을 검증한 뒤 대안을 선택한다.

## 추천

선택한 초기 구성은 **아침 출처 링크 한 글 + 기존 PC + 기업 뉴스 하루 최대 1건**, 약 **2.1만 원의 부분 견적**이다. 사용자가 이 안으로 구성하도록 요청해 편성·실행 기준에 반영했다. 하루2건 유지안은 약 2.96만 원으로 여유가 적어 채택하지 않았다.

더 적은 비용으로 학습·연동 검증을 먼저 하려면 아침만 로컬 시험(약 1.2만 원)을 제안할 수 있다. 공개 게시를 시작하기 전 단계의 수집·초안·승인·dry-run은 X 생성 비용 없이 검증할 수 있다. 이는 실제 게시까지 포함한 완료 기준을 달성했다는 뜻은 아니다.

어떤 안이든 지수·뉴스 공개 이용료가 유료로 확정되면 그 비용을 더해야 한다. 따라서 **총 3만 원을 보장하는 확정안은 아직 없지만**, 링크 글 수와 서버 구독을 줄이면 현재의 5.8만 원 가정에서 상당 부분 절감할 수 있다.
