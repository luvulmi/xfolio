## 만들 기능

React·TypeScript 관리자 → FastAPI → PostgreSQL과 별도 Python worker를 연결한다. worker는 지수/뉴스 수집 → Luna 분석·한국어 생성 → Python 검증 → 모드/정확한 버전 확인 → 정시 X 게시 → 결과·비용·장애 기록을 수행한다. Docker·AWS에 배포하며 중요한 오류는 Telegram Bot으로 통지한다.

| 편성 | 내용·발행 시각 KST | 최대량 |
| --- | --- | --- |
| 아침 브리핑 | 최근 완료 미국 거래일의 두 지수 종가·등락률 1글 + 중요한 두 지수 관련 뉴스·출처·원문 링크. **08:00 목표**, 정보 기준 07:30 | 1호 최대 3글, 뉴스 최대 2건 |
| **18시 추가 뉴스** | 낮 감시에서 확보한 서로 다른 새 중요 사건을 모아 **18:00에 발행**. 발견 즉시 게시하지 않음 | KST 날짜당 최대 2건, 사건당 1글 |

하루 최대 5글은 의무량이 아니다. 같은 사건 재게시·반복 AI 총평·전용 출처 모음 글을 제외한다. 아침 미선정 기사를 이유 없이 저녁에 자동 이월하지 않는다. 두 지수와 관련된 거시·정책·시장·업종·중요 구성기업 사건을 같은 기준으로 평가하고 고정 다섯 기업 감시는 하지 않는다.

아침은 새로운 완료 미국 거래일 종가가 있을 때만 1호를 발행한다. 저녁은 KST 날짜가 미국 거래일인 날에만 운영한다. 휴장 없는 정상 주간에는 월요일 아침은 생략하고 토요일 아침에 금요일 종가를 발행하며, 토요일 저녁은 운영하지 않는다. 휴장·특별 휴장·서머타임은 거래소 달력을 적용한다.

## 뉴스·콘텐츠의 필수 조건

- 개발 뉴스 경로는 **Marketaux 한 곳**이다. 지수는 yfinance `^GSPC`·`^NDX`, 생성 모델은 `gpt-6-luna`를 유지한다.
- 후보는 확정된 새 사실·두 지수 관련성/영향·근거·최신성·중복으로 선정한다. 회사/지수 이름 일치만으로 합격시키지 않는다. 분석가의 예상·주가 전망·목표가·루머·일상 홍보·가격 등락 나열은 제외한다. 회사가 공식 발표한 가이던스 변경은 발표 사실로만 다루며 미래 실현을 단정하지 않는다.
- 주체·변화·시점과 숫자의 단위·기간·비교 기준·조건을 원자료에 연결한다. 제목만으로 추측하거나 근거 없는 인과·가격 예측·매매 지시를 만들지 않는다.
- 모든 글은 출처·원문 링크와 실제 X 가중 길이를 확인한다. 원문·요약의 공개 이용, 외부 AI 전송·보관 조건을 충족한 입력만 실제 처리한다.
- Marketaux의 검색 범위·근거·Free 완전 수집·공개/AI 권한과 지수 공개 이용은 여전히 검증 대상이다. 제공처 선택을 운영 적합성 합격으로 표시하지 않는다.
- 뉴스 선정은 [고정 사례](../../../tasks/verification/news/뉴스_선정_고정_사례.md)의 채택·제외·중복·후속·보류 기대값으로 시험한다. 합성 사례 통과와 실제 뉴스의 검색 품질·사실 정확도·권한 검증을 별도로 판정한다.

| 자료 상태 | 처리 |
| --- | --- |
| 아침 필수 두 지수 누락 또는 뉴스 수집 partial/failed | 아침 호 보류·사유 기록, 중요한 최종 실패는 Telegram |
| 정상 수집 후 아침 적격 뉴스 0/1/2건 | 지수 1글 또는 뉴스 포함 최대 3글. 0건은 범위를 한정해 표시 |

| 저녁 필수 수집 구간 불완전·근거 충돌·마감/한도 위반 | 저녁 편성 보류·원인 기록·조치가 필요한 오류 통지 |

## 관리자·운영 범위

1단계 입력은 [뉴스 입력/검증 책임](../../specifications/뉴스_입력과_검증_책임.md)의 허용 fixture·사전 검토된 사실/관련성으로 고정한다. AI는 초안을 작성하고 코드 검사 후 운영자가 문장 근거·조건·관련성/새 사실을 확인한다. 일반 뉴스의 의미 정확성을 코드 통과로 대체하지 않는다. 확인 항목은 정확한 버전의 승인 감사에 저장하며 실제 자동 사실 추출·실자료 운영 적합성 검증은 후속이다.

| 메뉴 | 기능·단계 |
| --- | --- |
| 대시보드 | 1단계. 오늘 진행·승인 대기·조치 필요·비용 요약과 상세 진입 |
| 콘텐츠 검토 | 1단계. 목록/상세, 출처·허용 근거·완성 게시글·검증 결과, 정확한 버전 승인/보류 |
| 발행 내역 | 1단계. 글별 결과·ID·원버전·승인/전송 이력·부분 성공/결과 불명 |
| 수집 현황 | 후속. 수집 구간·완주·지수/기사·채택/제외/중복 이유 |
| 운영 현황 | 후속. 실행·장애/알림·비용의 상세 조회 |
| 설정 | 후속. 시각·한도·모드·연결 상태의 읽기 전용 조회 |

화면 2개와 API 8개는 상한이 아니다. 기존 8API를 재사용하고 필요한 조회를 확장한다. [IA·와이어프레임](../../specifications/관리자_화면_구조.md)에서 메뉴와 목록/상세 화면을 구분한다. 웹 편집·설정 변경은 후속 기본 범위에도 포함하지 않는다.

[API 명세](../../specifications/API_명세서.md)는 기존 8경로와 발행 조회2개를 더한 1단계 목표10경로를, [ERD](../../specifications/데이터_모델_ERD.md)는 현행8테이블·실제FK3개와 JSON 참조/목표 감사 구조를 구분한다. 명세 작성으로 신규 API나 저장 코드가 구현된 것은 아니다.

Google 로그인·단일 운영자 허용 목록을 FastAPI에서 확인한다. 프론트 버튼과 독립적으로 API 권한·세션 만료·CSRF·버전 경쟁을 검사한다. React는 DB·공급자·Telegram 비밀을 갖지 않는다. 문안 편집·직접 게시·재생성 UI·다중 사용자/권한·복구 화면은 제외하고 CLI로 제한 복구한다.

2026-10-28 사용자 위임으로 다음 상세 범위를 확정했다. 승인 대상은 **아침 최대 3글 또는 저녁 최대 2글의 편성 전체 버전**이다. 저녁의 X 글은 서로 독립되지만 개별 승인하지 않는다. 정상 0건인 저녁은 승인할 게시 버전을 만들지 않는다. [화면·승인 API 계약](../../../tasks/verification/admin/관리자_화면과_승인_API.md)

잘못된 초안은 전체 보류 후 운영자 CLI에서 기존 허용 근거로 문안을 수정하거나 기사를 제외해 새 버전을 만드는 것을 제품 목표로 한다. CLI 새 버전 기능은 후속이므로 1단계에서는 해당 편성을 보류·생략한다. 기능 도입 후 동일 검증과 재승인 후 원래 발행 창에서만 처리한다. 저녁 17:45 이후에는 새 기사·사실·근거를 추가할 수 없으며 정정·충돌이 발견되면 해당 편성을 보류한다. 첫 외부 전송 시도 이후에는 편성 버전을 교체하지 않고 부분 성공·결과 불명 복구 절차를 따른다.

## Telegram 운영 알림

자동 검증/승인 처리 예외와 잘못된 버전의 발행 시도, 제공처 quota/credit 소진·월 예산 경고/초과 예상, 최종 수집 실패·X 부분 성공/결과 불명 등 **조치가 필요한 상태**를 개인 chat 하나에 발신한다. 같은 장애는 중복 억제하고 알림 자체의 실패도 DB/관리자에 남긴다.

알림은 원인 코드·run/job ID·중단 상태·관리자 링크만 담고 키·기사 본문·민감한 HTTP 응답을 보내지 않는다. Telegram에서 승인·예산 변경·게시 명령은 받지 않는다. VM/worker 전체 중단의 외부 생존 감시는 후속이며 자체 알림이 이를 감지한다고 보장하지 않는다.

## 2주 완료 범위와 제외

5~6주차 **15시간씩 총 30시간**의 목표는 기존 인증/DB/API를 재사용한 3메뉴, 허용 AM 입력→검토/승인→아침 예약→강제 모의 전송→결과 확인의 **로컬 통합 MVP**다. 정상/중복/부분 성공/결과 불명·기한·예산 검증과 실행 문서를 포함한다. 허용 실자료 fixture가 없으면 정상 제품 E2E는 대기이며 합성 자료로 대체 합격시키지 않는다.

6메뉴 전체·낮 감시/18시·Telegram·CLI 수정/복구·Docker/AWS·실제 연동 인수는 [후속 WBS](../../planning/작업_분해_WBS.md)의 기준 약 20시간을 별도 배정한다. 합산 예상은 50~78시간이며 외부 준비 대기·auto 관측은 별도다. 30시간을 초과하면 미완료를 이관하고 핵심 검사를 생략하지 않는다.

개발은 dry_run→reviewed, auto는 기존 최소 5미국 거래일·장애 시험 뒤 활성화한다. auto 판정 코드·오류 알림은 MVP에서 시험하지만 2주 종료를 무인 운영 합격으로 보지 않는다. 실제 X 게시와 Telegram 시험 발송은 해당 사용자의 명시적 승인 범위에서 수행한다.

월 총비용 상한은 **50,000원**을 유지한다. AWS 고정비와 예상 사용료를 선반영하고 초과 예상 유료 요청은 차단한다. 1GB VM 적합성과 도메인·백업까지 포함한 예산은 배포 전 확인한다. RDS/ECS·Redis/Celery/SQS·Terraform·S3/CloudFront·고급 차트·실시간 알림 화면·완전 자동 CD는 MVP에서 제외한다.
