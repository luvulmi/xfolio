# 뉴스 입력과 검증 책임

> 2026-10-29 일정 정정: 5~6주차30시간은 중간 개발 목표이며 7주차 추가 개발·통합 검증, 8주차 초 기능 마무리를 계획한다. 단계는 기능 범위이고 달력상 2주 마감과 동일하지 않다. 시간·의존성은 [개발 범위·단계](../../planning/개발_범위와_단계.md)와 [WBS](../../planning/작업_분해_WBS.md)가 기준이다.


- 기준: 2026-10-29, Asia/Seoul
- 상태: **1단계 설계 확정·구현 전**. 사용자의 입력/검증 책임 확정 요청에 따라 30시간 범위에서 구체화했다. 제공처 권한·실뉴스 품질 합격을 뜻하지 않는다.
- 연결: [요구사항](../../요구사항.md) · [2주 범위](../../planning/개발_범위와_단계.md) · [API](../../specifications/API_명세서.md) · [ERD](../../specifications/데이터_모델_ERD.md)

## D01. 1단계 입력 방식

**허용된 실자료 fixture + 사전 검토된 사실/선정 정보 → AI 한국어 초안 → 코드 검사 → 운영자 의미 대조 → 정확한 편성 버전 승인**으로 정한다. 웹 기사 업로드·검색 UI·범용 자동 사실 추출은 만들지 않는다. 준비한 입력은 서버 측 fixture loader/도메인 함수로 전달하며 브라우저에서 승인 상태·권한·근거·시각을 입력받지 않는다.

Marketaux는 제품의 개발 뉴스 제공처다. 그러나 현재 수집 모델의 title/description/snippet을 자동으로 AI 전송·영속 저장해도 된다는 뜻은 아니다. 입력의 수집·저장·AI 전송·요약 이용 범위를 확인해야 한다. 제목만으로 새로운 사실이나 관련성을 추정하지 않는다. 허용 발췌에 주체·행위·시점·필수 조건이 없으면 해당 기사를 제외한다.

권한 확인된 Marketaux fixture가 없으면 해당 제품 경로의 정상 통합은 대기다. 기존 BLS CPI는 별도 기술 검증 경로로 유지하며 Marketaux 대체 제공처로 자동 편입하지 않는다. 합성 자료는 차단/선정 계층 시험에만 사용하고 `synthetic=false`로 바꿔 승인하는 우회를 금지한다.

| 입력 종류 | 식별 | 사용과 제한 |
| --- | --- | --- |
| 허용 실자료 fixture | `data_origin=permitted_fixture`, `synthetic=false` | 원래 출처·버전·시각과 사용 검토 기록 유지. 1단계 정상 제품 통합용, 전송은 격리 환경의 mock만 |
| 합성 fixture | `data_origin=synthetic_fixture`, `synthetic=true` | 순수 선정/차단 시험. 제품 승인·발행 예약은 계속 거절 |
| 실제 수집 | `data_origin=live_capture`, `synthetic=false` | 후속 실수집 인수. 권한/완주/시각 검증은 동일 |
| 권한 불명 또는 거절 | `unverified` / `denied` | 해당 용도의 저장·AI·게시 진행 금지. 확인된 최소 메타데이터만 허용 범위에서 기록 |

`data_origin`은 내용의 출처, `transport_mode=mock/live`는 송신 방식이다. 둘을 `synthetic` 하나로 표현하지 않는다. 1단계는 별도 DB/schema·시험 계정 식별자·강제 mock adapter를 사용하고 실제 X 자격 증명을 연결하지 않는다. 전송 방식은 서버 구성에서 고정하며 승인 API가 바꾸지 못한다.

과거 fixture는 원래 시각을 오늘로 덮어쓰지 않는다. 정상 시간 경계 시험은 격리 테스트의 clock 주입으로 원래 운영일을 재현하고, 실제 현재 시각과 시나리오 시각을 결과에 구분한다. 제품 HTTP API에 시각 변경 옵션을 추가하지 않는다. 실제 시각으로 재생해 마감이 지났다면 정상적으로 차단되어야 한다.

## D02. 지원 사실과 표현

기존 선정 유형 `macro`, `earnings`, `acquisition`, `sector_policy`, `official_guidance`는 유지하되 **사전 검토된 근거가 있는 입력만** 지원한다. 유형 이름을 지원한다는 것이 그 유형의 임의 기사를 자동 분석할 수 있다는 의미는 아니다. `analyst_opinion`, 루머, 확정 사실 없는 전망·홍보·가격 나열은 제외한다.

- 한 뉴스는 하나의 사건·사실 버전에 속하고, 생성 문장은 각각 `claim_id`와 근거 위치에 연결한다. 회사의 가이던스는 발표 사실로만 서술한다.
- 숫자는 원자료의 단일 수치와 단위·기간·비교 기준을 보존한다. 숫자가 없는 확정 정책/거래 사실도 근거와 사건 시점·필수 조건이 있으면 가능하다.
- 1단계 일반 문안에서는 단위 환산·자체 합산·비율 재계산·범위 수치·표/차트 해석을 추가하지 않는다. 지원할 수 없는 숫자 형식을 임의 반올림하거나 문맥을 제거해 우회하지 않는다. 지수 등락률 계산은 기존 별도 지수 규칙을 따른다.
- 인과 추정·가격 전망·매매 지시·입력에 없는 새 사실을 추가하지 않는다. 조건부 사실이면 해당 조건을 함께 유지한다.
- 한국어 문안의 표현은 자유롭지만 근거 주장 범위를 벗어나면 승인하지 않는다. 의미 정확성을 코드만으로 증명했다고 표시하지 않는다.
- 출처/원문 URL은 생성 모델이 만드는 문자열을 신뢰하지 않고 서버가 검증된 입력에서 조합한다. 길이는 완성 글 전체로 계산한다. 현재 CPI 전용 길이 함수를 일반 기사에 사용하지 않으며 A04에서 일반 URL/문자 대응 검증기를 구현해야 한다. 미지원 문자는 차단한다.

## D03. 입력 계약 v1 · 목표

아래는 서버 내부 입력 계약이다. 현재 Python 모델과 동일하다고 가정하지 않는다. API에 원문 저장용 POST를 추가하지 않는다.

| 영역 | 필수 필드·규칙 |
| --- | --- |
| 출처 | `provider`, 공급자 원래 `article_id`, 충돌을 피한 `source_id=provider:article_id`, 출처명, 인증정보 없는 http(s) `source_url` |
| 자료 범위 | `text_scope`, 허용 `evidence_text`, `content_version=SHA256(evidence_text UTF-8)`; 본문 전문은 필수 아님 |
| 시각 | timezone 포함 `published_at`, `retrieved_at`, 선택 `updated_at`; UTC로 저장. 정밀도·원래 시간대 메타데이터 보존, 발행 미상은 후보 제외 |
| 수집 | `collection_run_id`, provider/query_version/scope, 조회 창, required/completed queries와 페이지 완료 근거, complete/partial/failed |
| 이용 검토 | 용도별 collection/storage/ai_transfer/summary_publication, `reviewed_by`, `reviewed_at`, `expires_at`, `policy_reference`, 해당 source_id/content_version/text_scope |
| 주장 | `claim_id`, subject/action/event_type, certainty, period 또는 event_time, 선택 value/unit/comparison_basis/conditions, `evidence_span`, `evidence_position` |
| 사건 | 검토된 subject_id/event_type/period_or_transaction, `event_key`, `fact_version`; 새 사실이면 이전 사실 버전·차이·이유 |
| 관련성 | related, reason, evidence_ref, importance(critical/material/routine/uncertain), impact_scope(market/sector/company) |
| 사전 검토 | `review_id`, 운영자 식별자·검토 시각, 검토한 source/content/fact 버전. AI가 자체 생성한 reviewed=true는 인정하지 않음 |
| 재현 정보 | `schema_version=reviewed_news_input_v1`, data_origin, synthetic, fixture_loaded_at(해당 시), generation_mode(mock/live) |

`evidence_span`이 해시를 계산한 허용 텍스트 안에 존재해야 한다. 위치는 문단/문장 식별자로 함께 남긴다. 같은 문장이 여러 번 나오면 위치로 구분한다. 숫자가 근거 안에 존재한다는 검사만으로 주체·단위·부정·조건까지 정확하다고 판단하지 않는다.

현재 DB의 `rights_verified`는 빠른 판정용 파생값이다. 운영자가 유효한 정책 근거로 남긴 상세 이용 검토를 대신하지 않는다. 최초 처리·승인·송신 직전에 같은 버전/용도의 검토 유효기간을 재확인한다. AI/브라우저는 권한을 승격하지 못한다. 신규 제공처나 이용 범위의 실제 허용 여부는 조사 과제다.

## D04. 책임 분담

| 단계 | 책임 주체 | 확인/생성 | 이 단계가 보장하지 않는 것 |
| --- | --- | --- | --- |
| 입력 준비 | 운영자·서버 loader | 허용 자료, 출처/시각/수집 구간, 사실·사건·관련성의 사전 검토 | 실시간 자동 수집의 포괄성 |
| 한국어 초안 | AI 또는 명시한 생성 대역 | 제공된 claim_id·근거에 대응하는 한국어 문장, 출력 schema | 이용 권한·사실의 진실성·중요성 확정·게시 허가 |
| 기계 검사 | Python | 구조·필수 값·해시·시간·출처 연결·주장ID·수치 대응·완성 길이·중복·예산 | 자유 문장의 의미가 모두 근거와 일치한다는 보증 |
| 의미 검토 | 인증된 운영자 | 문장별 근거 지지·조건/부정/단위 보존, 관련성·중요성·새 사실 | 코드 차단을 무시한 승인 |
| 승인 | FastAPI + PostgreSQL | 현재 버전/revision·기계 통과·사람 확인·기한·모드·권한·중복·전체량 예약 | 실제 게시 성공 |
| 송신 | worker | 동일 버전·승인 유효성·자료 유효성·시간/한도·점유 재확인, 글별 전송 전 기록 | timeout을 확실한 실패로 단정 |

1단계 일반 검증 프로필은 `reviewed_news_v1`, AM 조합은 `am_reviewed_v1`로 정한다. 현재 `bls_cpi_v1`/`bls_cpi_pm_v1`과 분리하며 기존 시험 경로를 범용으로 이름만 바꾸지 않는다. `validated`는 **기계 검사 완료·사람 승인 대기**다. 이 프로필은 reviewed 전용이며 auto 승인으로 승격할 수 없다.

기계 검사가 통과해야 검토/승인 후보가 될 수 있지만 사람의 의미 검토는 별도로 필요하다. 사람이 체크한 사실만으로 코드 검사를 true로 바꾸지 않는다. `validation_passed`와 세부 검사 결과가 서로 다르면 차단한다.

## D05. 승인 시 확인과 감사

검토 상세의 전체 승인 전에 다음 세 항목을 확인한다. 이것은 사용자 권한 확인 대화가 아니라 제품 운영자의 검토 기록이다.

1. `evidence_support`: 각 문장의 주장이 연결된 원자료로 뒷받침된다.
2. `conditions_preserved`: 부정·단위·기간·비교 기준·예외 조건이 보존됐다.
3. `relevance_and_novelty`: 두 지수 관련성·중요성·기존 사건 대비 새 사실이 적절하다.

승인 요청의 `review_checks`가 세 항목을 정확히 포함해야 한다. API가 세션에서 운영자, 서버에서 시각, DB에서 현재 버전/hash를 얻어 결정 감사 이벤트에 기록한다. 클라이언트가 감사 주체/시각/hash를 정하지 않는다. 지수만 있는 AM도 수치·출처·거래일·정상 뉴스0건의 근거를 동일 항목으로 확인한다.

보류 요청에는 이 확인을 요구하지 않고 사유를 받는다. 승인·보류가 바뀌거나 새 버전이 생성되면 기존 의미 확인을 새 승인으로 재사용하지 않는다. 1단계는 웹/CLI 문안 수정이 없으므로 문제 편성은 보류·생략한다. 버전별 입력 검토와 최종 문안 승인은 서로 다른 감사 기록이다.

## D06. 시간·0건·실패 처리

- AM 정보 창은 이전 기준 이후부터 당일 07:30까지다. 사전 근거는 07:30까지 확보하고 편성 작성 목표 07:45·발행 목표08:00·신규 전송 마감09:00을 유지한다. 정보 확보 마감과 편성 생성 시각을 혼동하지 않는다.
- 운영일·지수 계산·지수 정정 예외는 기존 [운영 정책](../../운영_정책.md)을 따른다. 두 지수는 같은 완료 미국 거래일이어야 한다.
- 수집 창/필수 질의가 complete이고 지수가 정상일 때만 뉴스0건 AM을 만들 수 있다. fixture 목록이 비었다는 이유만으로 complete를 생성하지 않는다. 모의 수집 완주는 fixture 범위의 선언이며 실제 제공처 완주 판정과 구분한다.
- 근거 불충분/미지원 기사는 제외 사유를 남긴다. 필수 수집 불완전·필수 지수 누락·정정 충돌은 편성 보류다. 이미 승인한 사실을 무효화한 정정은 기사 제외로 우회하지 않는다.
- 후속 PM의 17:30/17:45/18:00/18:10 규칙은 변경하지 않는다. 1단계는 PM 자동 수집/발행을 완료했다고 표시하지 않는다.
- 원문 유효성 재확인이 불가능하면 신규 송신을 보류한다. 격리 fixture 시험은 모의 유효성 응답을 사용하고 실제 재조회 성공으로 기록하지 않는다.
