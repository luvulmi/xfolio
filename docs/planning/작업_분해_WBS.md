전체 목표 기준은 **79시간(N22+M3+A30+B20+C4)**, 예상 **79~126시간**이다. 이전60시간 안의 단일 경로 뉴스6시간을 공식 다중소스22시간과 다우3시간으로 바꾸어19시간 늘었다. 기존 자산 재사용을 전제한 하한이며4기관 구현 완료를 보장하지 않는다.

현재 가용시간 가정60시간과 **기준19시간 차이**가 있다. 선택지는 ① 위59시간 핵심경로+여유1시간을 우선하고 B20시간은 이후 진행 ② 8주차 초까지 추가 개발시간을 확보해 B기능도 포함하는 것이다. 추가 시간 확보는 사용자 미확정이다. 20기업 실제 확대는10기업 결과 후 수행하며, 설정/시험 범위를 넘어서는 운영 인수는 추가 재산정한다.

외부 승인·권한 대기와 auto의5미국 거래일 관측은 작업시간과 별도다. 범용 표/PDF 파싱·복잡한 재무 계산·웹 편집은 기본 합계 밖이다. C01과 핵심 안전 검증을 삭제해 일정에 맞추지 않으며8주차 후반은 신규 개발 대신 검증/발표로 남긴다.

## 추적 규칙

작업 상태·예상 시간 기준은 이 문서 하나에서 관리한다. 작업별 시험 계약과 실행 근거는 tasks/verification 및 tasks/logs에 기록하고 여기서 링크한다. GitHub Issues로 전환하면 항목 ID를 이슈에 매핑하고 상태를 중복 유지하지 않는다. 이번 요청은 기획 산출물까지이며 A/B 작업 구현을 실행한 것이 아니다.
