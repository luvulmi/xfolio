# WBS · 개인용 뉴스레터 전환

- 기준: 2026-11-03, Asia/Seoul. [기획서](../프로젝트_기획서.md)의 확정 기능을 기준으로 **앞으로 필요한 개발·검증 공수**를 재추정했다. 사용자 요청에 따라11/29 전체 완료를 목표로 하며, 실측이나 완료 기록은 아니다.
- 아침08시 서비스가 우선이며14/16시는 선택·기본 꺼짐이다. 선택 기능도 개발 범위에 남기되 T09로 분리한다.
- 기존 BLS·인증·DB·시험 코드를 재사용하되 새 국내 ETF/자동 전송의 완료 근거로 대신하지 않는다. [전환 전 WBS](../archive/2026-11-01_X_공개_게시_이전안/planning/작업_분해_WBS.md)는 이력으로 보존한다.

Finnhub는 본인 개인용으로 채택한 상태다. 별도 이메일 회신 대기는 작업에 넣지 않는다. KIS 신청·발급정보 로컬 등록은 완료했다(11/3 사용자 확인). 인증 시세·이용 조건 인수는 남아 있다.

## 날짜 산정 기준

- **착수11/3 · 최종 완료/발표11/29**, 평일 하루 **5h**(예: 집중 작업3h + 구현/검증2h)로 계획한다. 기존 하루3h·주15h·12월 종료 일정은 이 안으로 대체한다.
- 11/3~11/27의 평일19일로 **95h**를 확보한다. 기존 개발/검증82h에 추가 지연 대응7h와 발표/인계 준비6h를 배정한다. 5주차 잔여20h, 6~8주차 각25h다.
- `환산 작업일 = 시간 ÷ 5`. 같은 날 여러 작업은 선행 작업을 끝낸 뒤 시간을 나눠 쓰며 하루 합계5h를 넘지 않는다. 토·일 개발은 기본 용량에 넣지 않는다. 11/28은 미사용 보충일,11/29는 최종 발표/완료 확인일이다.
- 기존82h는 **아침70h + 오후6h + 결함 여유6h**다. 추가7h를 합쳐 결함/지연 대응 여유는 총13h이며 같은 시간을 중복 집계하지 않는다. 최종 발표/운영 인계 준비6h는 별도로 추가했다.
- 공수에는 기능 시험·운영 문서가 포함된다. API 신청 처리/관측 시각 대기는 실제 달력에 영향을 주므로 T01을 즉시 시작한다. 실자료07:50/08:00·14/16시 확인은 해당 평일에 예약하고 능동 작업시간만 공수에 산입한다. 외부 처리 완료를 보장하지 않는다.

## 실제 진행 상태와 의존성

- T01은 [공개3종목 식별](../../tasks/verification/market/국내_ETF_API_표본_검증.md)만 확인했다. 신청/발급정보 등록은11/3 사용자 확인 완료다. 인증 종가 인수가 늦으면 날짜를 미루되 T02 합성 계약·T03·T05 화면 fixture·T06 모의 작업은 먼저 진행할 수 있다.
- T03은 [Finnhub 표본·링크/필터 시험](../../tasks/verification/news/Finnhub_시장뉴스_표본과_개인_전달.md)을 완료한 재사용 자산으로 반영했다. 운영 어댑터·공식 발표 확장·DB 기발송 제외·통합 편성은 미완료다. 11/4 08시1회 관측은 별도 제공처 시험이다.
- T02~T09 제품 인수는 완료 처리하지 않았다. FR-06은 이전 승인 기능의 이력으로 신규 구현 대상에서 제외한다. 현재 요구사항 연결은 [요구사항 표](../요구사항.md#요구사항-목록과-수용-조건)를 함께 유지한다.
- 비용은 T08에서 실제 구성으로 재산정하고 T04의 예산 차단을 검증한다. 이전 X 비용을 재사용하지 않는다.
