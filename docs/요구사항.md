## 만들 기능

시장·뉴스 수집 → AI 분석·한국어 콘텐츠 생성 → 원자료 대조·검증 → 개발·테스트 관리자 확인 또는 안정화 후 자동 발행 → X 게시 → 결과 조회를 연결한다. 초기 개발은 주당15시간·총30시간을 계획 기준으로 삼는다. [개발 일정](../tasks/plans/개발_일정.md)

| 편성 | 내용 | 최대량 |
| --- | --- | --- |
| 아침 브리핑 | 최근 완료 미국 거래일의 두 지수 종가·등락률 요약 1개 글 + 최우선 미국 거시·정책·시장/업종 뉴스와 원문 링크 1개 글 | 거래일당1호, 뉴스 최대1건·스레드 최대2개 글 |
| 추가 기업 뉴스 | 두 지수 중 하나 이상에 속하는 관찰 기업의 중요한 실적·회사 전망·확정 사업 변화 | 관찰 기업10개, 하루 최대2건·한 사건1개 글 |

영어·한국어 기사 입력을 허용하고 한국어로 게시한다. 뉴스 연동은 제공처1곳으로 시작하며 두 언어를 동시에 제공하는 곳만 선택해야 하는 조건은 아니다. 아침은 시장·업종에서 확인된 최우선 변화 1건을 충분히 설명하고 반복되는 AI 총평은 생략한다. 추가 뉴스는 기업 개별 사건으로 구분한다. 밤사이 발표된 미게시 기업 소식도 추가 뉴스 후보가 될 수 있다.

## 뉴스 선정 기준

- 아침은 확인된 새 발표·결정·시장 사건을 해설·전망보다 우선한다. 같은 등급은 시장 전체 중요성 → 새 사실의 최신성 순으로 비교한다. CPI·PCE·고용·GDP, 주요 정책 확정 변경, 거래·결제 운영 변화 등을 높은 중요도 범주로 시작한다.
- 업종 공통의 규제·수요/공급·비용/공급망·사업 구조 변화는 아침 후보다. 여러 기업 이름이 등장하거나 업종명이 붙었다는 이유만으로 개별 기업 사건을 업종 전체 뉴스로 보지 않는다.
- 기업은 두 지수 중 하나 이상에 포함된 최대10개를 고정 선정하고 중복 편입은 한 기업으로 센다. 실적·회사 실적 전망·핵심 사업의 중요한 확정 변화를 원문으로 설명한다. 기사에 지수명이 직접 나올 필요는 없지만 기업 이름만 등장하는 것은 부족하다.
- 기업 후보는 확인된 사건 중요성 → 지수 내 기업 중요성 → 새 사실의 최신성 순으로 비교한다. 동률은 안정적인 식별자로 고정하며 목록·점수화·근거 일관성은 샘플로 검증한다.
- 주가 등락·목표가·매수 추천만의 기사, 루머·일상 홍보·기존 발표 재해설은 제외한다. 지수 편입 사실만으로 지수 등락의 원인을 단정하지 않는다.
- 같은 사건 후속 보도는 다음 아침에 검토한다. 기업 후속은 다음 기업 편성 후보로 전달하며 자동 이월 게시하지 않는다. 같은 사실을 반복 게시하지 않는다.

## 콘텐츠와 자료 부족

본문 또는 충분한 요약에서 주체·사건·시점을 확인하고 수치를 쓰면 값·단위·기간·비교 기준까지 대조한다. 제목만으로 추측하지 않으며 핵심 근거가 없으면 제외한다. 게시문은 명사형 핵심 항목으로 압축하고 사실과 출처의 해석을 구분한다. 근거 없는 인과관계·가격 예측·매매 지시는 넣지 않는다.

| 자료 상태 | 아침 호 처리 |
| --- | --- |
| 두 지수 중 필수 종가 누락 | 전체 보류 |
| 정상 수집 후 선정 뉴스1건 | 지수 글 + 뉴스·원문 링크 글, 최대2개 글로 발행 |
| 정상 수집 후 선정 뉴스0건 | 지수 글에 이번 수집 범위에서 선정 뉴스가 없음을 표시하고 나머지 검증 후 1개 글로 발행 |
| 뉴스 제공처 수집 실패 | 전체 보류 |

아침 뉴스 글과 기업 글은 각각 출처명과 원문 링크를 같은 글에 포함한다. 독립된 출처 모음 글을 추가하지 않는다. 모든 글은 시각·단위·조건·출처를 보존한 완성본으로 280 가중 글자 한도를 검사한다. 낮은 중요도의 부가 설명을 줄이거나 뉴스를 제외해 길이를 맞추며 핵심 근거·출처를 숨기지 않는다. 아침이 지수 누락으로 보류돼도 해당 자료와 무관하게 독립 검증된 기업 뉴스는 기존 한도 안에서 발행할 수 있다. 제공처·게시 시스템 장애나 성공 불명 상태를 우회하지 않는다.

## 관리자·운영 범위

관리자 사이트는 로그인 → 대시보드 → 근거·미리보기 검증 화면으로 구성한다. 후보 상태·출처·검증 결과·게시물 ID·보류 사유를 조회한다. 개발·테스트에는 승인/보류, 안정화 후에는 자동 검증을 통과한 콘텐츠의 예약 게시와 결과 조회를 제공한다. 문안 직접 편집·직접 게시·복구 화면·다중 권한은 첫 버전에 넣지 않고 수동 복구는 CLI로 수행한다.

2026-10-25 사용자는 로컬 PC 의존성을 없애기 위해 DB·관리자·수집·게시 예약의 전면 클라우드 전환을 요청하고 추천 작업 진행을 승인했다. 배포 목표는 Neon PostgreSQL·비공개 Streamlit·Cloud Run Jobs·Cloud Scheduler이며 로컬 한정 구성은 개발용으로 남긴다. 현재 가상 자료·원격 DB 시험과 실제 인증/승인·운영 배포의 완료를 구분한다. Python 고정 워크플로를 유지하며 LLM은 예약·예산·승인·X 전송 권한을 변경하지 않는다. [전환 계획·현재 상태](../tasks/plans/클라우드_전환.md)

월 총비용 상한은30,000원이다. 실제 비용과 데이터 공개 이용 범위는 별도 검증하며 유료 서비스 신청이나 실제 X 게시 승인을 뜻하지 않는다. 시각·일일 한도·정보 기준·재시도·보관·완료 기준은 [운영 정책](운영_정책.md) 한 곳에서 관리한다.
