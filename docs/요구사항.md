## 만들 기능

시장·뉴스 수집 → AI 분석·한국어 콘텐츠 생성 → 원자료 대조·검증 → 개발·테스트 관리자 확인 또는 안정화 후 자동 발행 → X 게시 → 결과 조회를 연결한다. 초기 개발은 주당15시간·총30시간을 계획 기준으로 삼는다. [개발 일정](../tasks/plans/개발_일정.md)

| 편성 | 내용 | 최대량 |
| --- | --- | --- |
| 아침 브리핑 | 최근 완료 미국 거래일의 두 지수 종가·등락률 요약 1개 글 + Marketaux에서 조회·선별한 두 지수 관련 중요 뉴스 | 거래일당1호, 뉴스 최대2건·스레드 최대3개 글 |
| 추가 중요 뉴스 | 아침 정보 기준 이후 정기 감시에서 새로 확인한 S&P 500·Nasdaq-100 관련 중요 변화 | KST 날짜당 최대2건·한 사건1개 글 |

영어·한국어 기사 입력을 허용하고 한국어로 게시한다. 뉴스 후보는 **Marketaux 한 흐름**에서 수집해 두 지수 관련성·중요도·근거를 선별한다. 거시·정책·시장·업종 사건과 지수에 실질적 영향을 줄 수 있는 주요 구성기업 사건을 같은 기준으로 평가한다. 단순히 구성기업 이름이 등장했다는 이유만으로 채택하지 않는다. 아침 최대 2건과 이후 추가 최대 2건은 서로 다른 새 사건이며, 각 글에 설명·출처·원문 링크를 담고 반복 AI 총평은 생략한다. Marketaux의 공개 게시·외부 AI 처리 권한과 무료 수집 완전성은 검증 전이므로 이 선택이 운영 가능 판정을 뜻하지 않는다.

## 뉴스 선정 기준

- 아침은 확인된 새 발표·결정·시장 사건을 해설·전망보다 우선한다. 같은 등급은 시장 전체 중요성 → 새 사실의 최신성 순으로 비교한다. CPI·PCE·고용·GDP, 주요 정책 확정 변경, 거래·결제 운영 변화 등을 높은 중요도 범주로 시작한다.
- 업종 공통의 규제·수요/공급·비용/공급망·사업 구조 변화는 아침 후보다. 여러 기업 이름이 등장하거나 업종명이 붙었다는 이유만으로 개별 기업 사건을 업종 전체 뉴스로 보지 않는다.
- 관련성은 지수 자체의 규칙·움직임, 미국 거시·정책·시장/업종 전반의 영향, 주요 구성기업의 지수 차원에서 의미 있는 확정 사건으로 판단한다. 두 지수와의 연결 이유를 기록한다. 고정 5개 회사만 조회하는 [이전 안](research/관찰_기업.md)은 현재 필터가 아니다.
- 후보는 확인된 사건의 지수 관련 중요성 → 영향 범위·확정성 → 새 사실의 최신성 순으로 비교한다. 동률은 안정적인 식별자로 고정하며 관련성·근거 일관성은 샘플로 검증한다.
- 주가 등락·목표가·매수 추천만의 기사, 루머·일상 홍보·기존 발표 재해설은 제외한다. 지수 편입 사실만으로 지수 등락의 원인을 단정하지 않는다.
- 같은 사건의 단순 후속 보도는 재게시하지 않는다. 정정·새로운 중요한 사실은 다음 선정 회차에서 재검토하며 자동 이월 게시하지 않는다.

## 콘텐츠와 자료 부족

본문 또는 충분한 요약에서 주체·사건·시점을 확인하고 수치를 쓰면 값·단위·기간·비교 기준까지 대조한다. 제목만으로 추측하지 않으며 핵심 근거가 없으면 제외한다. 게시문은 명사형 핵심 항목으로 압축하고 사실과 출처의 해석을 구분한다. 근거 없는 인과관계·가격 예측·매매 지시는 넣지 않는다.

| 자료 상태 | 아침 호 처리 |
| --- | --- |
| 두 지수 중 필수 종가 누락 | 전체 보류 |
| 정상 수집 후 선정 뉴스1~2건 | 지수 글 + 선정 뉴스별 원문 링크 글, 최대3개 글로 발행 |
| 정상 수집 후 선정 뉴스0건 | 지수 글에 이번 수집 범위에서 선정 뉴스가 없음을 표시하고 나머지 검증 후 1개 글로 발행 |
| 뉴스 제공처 수집 실패 | 전체 보류 |

아침·추가 뉴스 글은 각각 출처명과 원문 링크를 같은 글에 포함한다. 독립된 출처 모음 글을 추가하지 않는다. 모든 글은 시각·단위·조건·출처를 보존한 완성본으로 280 가중 글자 한도를 검사한다. 낮은 중요도의 부가 설명을 줄이거나 뉴스를 제외해 길이를 맞추며 핵심 근거·출처를 숨기지 않는다. 아침이 지수 누락으로 보류돼도 해당 자료와 무관하게 독립 검증된 추가 뉴스는 기존 한도 안에서 발행할 수 있다. 제공처·게시 시스템 장애나 성공 불명 상태를 우회하지 않는다.

## 관리자·운영 범위

관리자 사이트는 로그인 → 대시보드 → 근거·미리보기 검증 화면으로 구성한다. 후보 상태·출처·검증 결과·게시물 ID·보류 사유를 조회한다. 개발·테스트에는 승인/보류, 안정화 후에는 자동 검증을 통과한 콘텐츠의 예약 게시와 결과 조회를 제공한다. 문안 직접 편집·직접 게시·복구 화면·다중 권한은 첫 버전에 넣지 않고 수동 복구는 CLI로 수행한다.

2026-10-25 사용자는 로컬 PC 의존성을 없애기 위해 DB·관리자·수집·게시 예약의 전면 클라우드 전환을 요청하고 추천 작업 진행을 승인했다. 배포 목표는 Neon PostgreSQL·비공개 Streamlit·Cloud Run Jobs·Cloud Scheduler이며 로컬 한정 구성은 개발용으로 남긴다. 현재 가상 자료·원격 DB 시험과 실제 인증/승인·운영 배포의 완료를 구분한다. Python 고정 워크플로를 유지하며 LLM은 예약·예산·승인·X 전송 권한을 변경하지 않는다. [전환 계획·현재 상태](../tasks/plans/클라우드_전환.md)

월 총비용 상한은 **50,000원**이다. 실제 비용과 데이터 공개 이용 범위는 별도 검증하며 유료 서비스 신청이나 실제 X 게시 승인을 뜻하지 않는다. 시각·일일 한도·정보 기준·재시도·보관·완료 기준은 [운영 정책](운영_정책.md) 한 곳에서 관리한다.
