# 요구사항 · 풀스택 포트폴리오 2주 MVP

- 현재 기준: 2026-10-28, Asia/Seoul
- 목적: 곧 4년차 풀스택 개발자의 이직 포트폴리오로 **검토·승인 업무 흐름, 데이터 정합성, 외부 API 장애와 AWS 배포**를 설명할 수 있는 서비스를 만든다.
- 대상 독자: S&P 500·Nasdaq-100에 관심 있는 개인 투자자. 관리자: 운영자 1명·X 계정 1개
- 확정 과정: [풀스택 MVP·18시 편성](../tasks/discussions/2026-10-28_풀스택_MVP와_18시_뉴스_편성.md). [이전 Streamlit·수시 게시안](archive/Streamlit_관리자와_수시_뉴스_편성.md)은 현재 제품 목표가 아니다.

## 만들 기능

React·TypeScript 관리자 → FastAPI → PostgreSQL과 별도 Python worker를 연결한다. worker는 지수/뉴스 수집 → Luna 분석·한국어 생성 → Python 검증 → 모드/정확한 버전 확인 → 정시 X 게시 → 결과·비용·장애 기록을 수행한다. Docker·AWS에 배포하며 중요한 오류는 Telegram Bot으로 통지한다.

| 편성 | 내용·발행 시각 KST | 최대량 |
| --- | --- | --- |
| 아침 브리핑 | 최근 완료 미국 거래일의 두 지수 종가·등락률 1글 + 중요한 두 지수 관련 뉴스·출처·원문 링크. **08:00 목표**, 정보 기준 07:30 | 1호 최대 3글, 뉴스 최대 2건 |
| **18시 추가 뉴스** | 낮 감시에서 확보한 서로 다른 새 중요 사건을 모아 **18:00에 발행**. 발견 즉시 게시하지 않음 | KST 날짜당 최대 2건, 사건당 1글 |

하루 최대 5글은 의무량이 아니다. 같은 사건 재게시·반복 AI 총평·전용 출처 모음 글을 제외한다. 아침 미선정 기사를 이유 없이 저녁에 자동 이월하지 않는다. 두 지수와 관련된 거시·정책·시장·업종·중요 구성기업 사건을 같은 기준으로 평가하고 고정 다섯 기업 감시는 하지 않는다.

## 뉴스·콘텐츠의 필수 조건

- 개발 뉴스 경로는 **Marketaux 한 곳**이다. 지수는 yfinance `^GSPC`·`^NDX`, 생성 모델은 `gpt-6-luna`를 유지한다.
- 후보는 확정된 새 사실·두 지수 관련성/영향·근거·최신성·중복으로 선정한다. 회사/지수 이름 일치만으로 합격시키지 않는다. 전망·목표가·루머·일상 홍보·가격 등락 나열은 제외한다.
- 주체·변화·시점과 숫자의 단위·기간·비교 기준·조건을 원자료에 연결한다. 제목만으로 추측하거나 근거 없는 인과·가격 예측·매매 지시를 만들지 않는다.
- 모든 글은 출처·원문 링크와 실제 X 가중 길이를 확인한다. 원문·요약의 공개 이용, 외부 AI 전송·보관 조건을 충족한 입력만 실제 처리한다.
- Marketaux의 검색 범위·근거·Free 완전 수집·공개/AI 권한과 지수 공개 이용은 여전히 검증 대상이다. 제공처 선택을 운영 적합성 합격으로 표시하지 않는다.

| 자료 상태 | 처리 |
| --- | --- |
| 아침 필수 두 지수 누락 또는 뉴스 수집 partial/failed | 아침 호 보류·사유 기록, 중요한 최종 실패는 Telegram |
| 정상 수집 후 아침 적격 뉴스 0/1/2건 | 지수 1글 또는 뉴스 포함 최대 3글. 0건은 범위를 한정해 표시 |
| 정상 수집 후 저녁 적격 뉴스 0/1/2건 | 18시 0~2개 글, 0건이면 게시·푸시 알림 생략 |
| 저녁 필수 수집 구간 불완전·근거 충돌·마감/한도 위반 | 저녁 편성 보류·원인 기록·조치가 필요한 오류 통지 |

## 관리자·운영 범위

| 화면 | 필수 기능 |
| --- | --- |
| 대시보드 | 날짜/편성/상태별 후보 목록, 마지막 수집·게시 결과, 비용·쿼터·알림 실패 요약 |
| 후보 상세 | 출처·허용 근거·완성 게시글·검증 결과, 정확한 버전 승인/보류, 발행 결과·ID·보류 사유 |

Google 로그인·단일 운영자 허용 목록을 FastAPI에서 확인한다. 프론트 버튼과 독립적으로 API 권한·세션 만료·CSRF·버전 경쟁을 검사한다. React는 DB·공급자·Telegram 비밀을 갖지 않는다. 문안 편집·직접 게시·재생성 UI·다중 사용자/권한·복구 화면은 제외하고 CLI로 제한 복구한다.

## Telegram 운영 알림

자동 검증/승인 처리 예외와 잘못된 버전의 발행 시도, 제공처 quota/credit 소진·월 예산 경고/초과 예상, 최종 수집 실패·X 부분 성공/결과 불명 등 **조치가 필요한 상태**를 개인 chat 하나에 발신한다. 같은 장애는 중복 억제하고 알림 자체의 실패도 DB/관리자에 남긴다.

알림은 원인 코드·run/job ID·중단 상태·관리자 링크만 담고 키·기사 본문·민감한 HTTP 응답을 보내지 않는다. Telegram에서 승인·예산 변경·게시 명령은 받지 않는다. VM/worker 전체 중단의 외부 생존 감시는 후속이며 자체 알림이 이를 감지한다고 보장하지 않는다.

## 2주 완료 범위와 제외

5~6주차 **15시간씩 총 30시간**의 목표는 2화면·8API·PostgreSQL·아침/18시 worker·게시 상태·Telegram·단일 AWS 배포와 핵심 실패 시험을 갖춘 **reviewed MVP**다. 기존 수집·AI·가상 자료를 재사용한다. 구현·배포는 아직 완료하지 않았다.

개발은 dry_run→reviewed, auto는 기존 최소 5미국 거래일·장애 시험 뒤 활성화한다. auto 판정 코드·오류 알림은 MVP에서 시험하지만 2주 종료를 무인 운영 합격으로 보지 않는다. 실제 X 게시와 Telegram 시험 발송은 해당 사용자의 명시적 승인 범위에서 수행한다.

월 총비용 상한은 **50,000원**을 유지한다. AWS 고정비와 예상 사용료를 선반영하고 초과 예상 유료 요청은 차단한다. 1GB VM 적합성과 도메인·백업까지 포함한 예산은 배포 전 확인한다. RDS/ECS·Redis/Celery/SQS·Terraform·S3/CloudFront·고급 차트·실시간 알림 화면·완전 자동 CD는 MVP에서 제외한다.
