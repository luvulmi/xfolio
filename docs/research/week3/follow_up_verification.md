## 실제 실행한 로컬 실험

| 스크립트 | 입력·실행 방식 | 결과·해석 |
| --- | --- | --- |
| [OpenAI 계약 검증](experiments/openai_contract_probe.py) | 직접 만든 가상 자료·httpx.MockTransport, 실제 키·네트워크 없음 | 스키마·요청 설정·파싱 통과, 잘못된 입력3개 거부. 실제 모델 정확성·지연·과금 실측은 아님 |
| [SQLite 기능 검증](experiments/sqlite_probe.py) | 폐기 가능한 임시 DB·WAL·독립 연결2개, 실제 운영 DB 없음 | 한 발행 키 1성공/1중복 거부, 승인 조건부 갱신0/1/0, 고의 예외 롤백, 백업·복원 무결성 통과 |

SQLite 실험은 독립 연결을 가진 두 스레드이며 서로 다른 OS 프로세스나 강제 종료·부하 시험을 대신하지 않는다. 백업 결과에는 가짜 게시물 ID와 승인 버전을 넣어 복원 여부를 확인했다. 실제 X 전송과 DB 기록이 원자적으로 처리된다는 검증은 아니다.

재현 명령:

```powershell
.venv/Scripts/python.exe docs/research/week3/experiments/openai_contract_probe.py
.venv/Scripts/python.exe docs/research/week3/experiments/sqlite_probe.py
```

필요한 라이브러리·검증 환경과 상세 출력은 [AI](openai_usage.md), [저장](storage_admin.md), [예약](scheduling_deployment.md)에 남겼다. Windows 임시 디렉터리 권한이 제한된 실행 환경에서는 SQLite 실험 실행에 도구 승인이 필요할 수 있다. 실험은 임시 폴더만 사용하고 종료 시 정리한다.

## 현재 결론

로컬 기술 구성과 출처 통합 형식의 가능성은 추가로 확인했다. 그러나 실제 운영으로 넘어가는 가장 큰 의존성은 여전히 **정확한 두 지수와 한 뉴스 제공처의 공개 사용 권한·자료 확보**다. 계정·키가 없다는 사용자 답변에 따라 현재 가능한 공개 조사와 로컬 실험을 마쳤으며 실제 서비스 품질·권한·요금을 확인 완료로 표시하지 않는다.

다음 준비 순서는 데이터 이용 조건 확인 → 해당 제공처 키/허용 샘플 확보 → OpenAI 소량 시험과 X 콘솔 확인 → 로그인·예약을 포함한 실제 앱 검증이다. 키나 토큰은 문서·채팅·Git에 기록하지 않는다. 이번에 새 구독이나 편성 변경을 확정하지 않았다.
