## 1. Telegram · 본인 알림

[봇 소개](https://core.telegram.org/bots)는 BotFather 생성·봇 토큰·사용자 선행 메시지 조건을 안내한다. 본인이 봇에 `/start` 등 메시지를 보낸 뒤 정해진 시간에 자신에게 보내는 것은 지원되는 이용 형태다. 이 규모의 본인 알림을 위한 별도 방송 제휴/유료 broadcast 요건은 확인되지 않았다. [FAQ](https://core.telegram.org/bots/faq#how-do-i-avoid-hitting-limits)는 한 chat에서 초당 1개 초과를 피하도록 안내한다. 여러 조각이면 간격을 두고 429를 처리한다.

[개발자 약관](https://telegram.org/tos/bot-developers) §5의 원치 않는 메시지/스팸 금지, §9의 법령·제3자 권리 준수, §4의 개인정보 최소화·보존/삭제·보안 의무를 따른다. 개인정보 처리방침은 표준 정책의 적용 적합성을 확인하고, 맞지 않으면 별도 정책을 BotFather에 설정한다. 본인용이라고 이 의무가 면제된다고 보지 않는다.

구현 시 수신자 본인의 숫자 user/chat ID와 private chat 유형을 서버 allowlist로 검사하고, 다른 사용자의 `/start`나 그룹 추가가 수신 권한을 주지 않게 한다. 키·계좌정보·뉴스 전문을 메시지에 넣지 않고, 인증 토큰과 chat ID가 로그/발표에 노출되지 않게 한다. 공개 시연에는 합성 데이터/비식별 화면을 쓴다.

[Telegram 개인정보 정책](https://telegram.org/privacy#3-3-1-cloud-chats)은 cloud chat 메시지의 서버 보관을 설명한다. 1:1 비공개 대화가 로컬 파일만 사용하는 구조와 같지는 않다. 서버 저장을 금지한 자료를 자동으로 허용된 것으로 취급하지 않는다. 그룹/채널/지인 전달·공개 포트폴리오에 실자료 노출은 이번 개인 이용 판단 범위 밖이다.

## 2. KIS · 개인 이용과 제3자 제공

[공식 고객 약관](https://file.koreainvestment.com/Storage/customer/guide/regards/openAPI_service_customer.html)을 직접 HTTPS로 읽어 확인했다. 확인본은 2022-08-08 제정·2022-10-01 시행 표기다. 서비스 신청 때 제시되는 최신 약관/별도 조건을 다시 대조해야 한다.

- 제3조는 시세 등 조회에도 약관이 적용됨을 정한다. 자동 주문을 하지 않는다고 적용 제외가 아니다.
- 제5조②는 앱키·시크릿키의 제3자 대여/위임/양도/누설을 금지한다.
- 제5조③은 시세를 자체 개발 프로그램 등 개인 업무에 사용하도록 하고 제3자 제공을 금지한다.
- 제7조는 서비스 신청·약관 동의·본인/계좌 인증을, 제9·12조는 과도한 부하 제한과 유량 제어를 정한다.

**해석:** 본인 정보 확인용 개인 프로그램에는 허용 근거가 있다. 본인만 받는 Telegram 알림을 곧바로 불특정 다수 재배포라고 단정할 근거도 찾지 못했다. 다만 제5조③이 외부 전달 사업자·개인 AWS VM·Telegram 저장까지 명시하는 것은 아니므로 이를 서면 허가 취득이나 무조건 허용으로 기록하지 않는다. 키는 자신의 서버에 두고 Telegram에는 가격·변동률만 전달하는 구성이 확인 범위를 좁힌다. 가격 계산에는 외부 LLM이 필요하지 않다.

[KIS 제휴 안내](https://apiportal.koreainvestment.com/provider)는 개인 본인 이용자와 제3자 서비스 제공 법인을 구분하고 제휴 시세정보 계약을 안내한다. 이 법인 제휴 요건을 본인 알림에 그대로 강제하거나, 반대로 개인 계정으로 다수 구독자를 운영해도 된다고 해석하지 않는다.

원문과 확보 정보는 [KIS 약관 증거](../../tasks/verification/assets/market/개인_Telegram_이용_정책_2026-11-02/README.md)에 보존했다. 11/2 조사 당시 외부 전달 방식 적용 판단을 남겼으며, 아래11/3 사용자 결정으로 본인 이용 범위를 채택했다. 공급자 별도 명시 허가 취득 여부에 대한 조사 사실은 유지한다.

## 3. Exa · API 기능과 기사 이용권

[공식 Contents 문서](https://exa.ai/docs/contents/quickstart)는 LLM context에 검색 결과를 사용하는 방법과 본문/하이라이트/요약 기능을 안내한다. 따라서 약관의 일반 자동 접근 제한만 보고 공식 API 호출·LLM 활용 자체가 전면 금지라고 결론 내리면 안 된다.

반면 [약관](https://exa.ai/terms) §4.2(a)는 복제·전송·파생물 등에 제한과 명시적 허용 예외를 두며, §4.1은 문서상 목적과 제3자 지식재산 준수를 요구하고 §6.1은 제3자 자료의 저작권 적합성을 보증하지 않는다. **공식 기능 지원은 원매체 기사 전문의 무제한 AI 입력·보관·재전달 라이선스와 다르다.**

본 프로젝트의 `검색 → 기사 본문 → 외부 OpenAI API → 한국어 요약 → 본인 Telegram → DB 보존` 조합에 대해 공개 문서만으로 포괄 허가를 확인하지 못했다. Exa에 API 계약 적용을 확인하고 원매체별로 실제 처리할 기사/사이트 정책도 확인해야 한다. 특정 원매체·기사 목록은 아직 확정되지 않았으므로 원매체별 허용 인수를 완료하지 않았다. 제목·링크만 보내거나 보존 기간을 짧게 해도 자동 면제되는 것은 아니다.

따라서 **기사 전문·이미지 복제/번역 전송, 유료벽 우회, 권리 미확인 본문의 영속 저장은 진행하지 않는다.** 최소한의 사실을 자체 문장으로 정리하고 원문 링크를 붙이는 것은 위험을 줄이는 설계이지 계약상 포괄 허가가 아니다. BLS 등 허용 범위가 명확한 자체 자료는 별도로 판단한다.

## 5. OpenAI · 입력 권한과 데이터 처리

[OpenAI Services Agreement](https://openai.com/policies/services-agreement/) §2.2는 API 앱 통합, §4.1은 당사자 사이의 출력 권리, §4.3은 입력에 필요한 권한 확보 책임을 규정한다. §3.3의 제3자 권리 침해 제한도 적용된다.

[공식 API 데이터 제어 문서](https://developers.openai.com/api/docs/guides/your-data)는 기본 학습 미사용을 안내한다. 이는 무보존/ZDR을 자동 의미하지 않으며 abuse monitoring·Responses 상태 저장 등은 계정/endpoint 설정에 따라 별도로 검토한다. 앱의 원문7일 보존 정책이 공급자 또는 Telegram 저장까지 7일로 만드는 것은 아니다. 전달 허용이 없는 기사를 학습 미사용이라는 이유로 입력하지 않는다.

## 6. 개인 이용 법령과 이메일 대안

[저작권법 제30조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?chrClsCd=010202&lsJoLnkSeq=1033063043)는 비영리 개인 이용 등의 복제를 규정한다. 2026-11-02 조회한 본문은 2026-10-29 시행본이다. 이것만으로 외부 AI 업체로의 전문 전송·서비스 사업자의 처리·모든 계약 제한이 해소된다고 판단하지 않는다.

[대법원 2004도5350](https://law.go.kr/LSW/precInfoP.do?precSeq=216041)은 사실 자체와 창작적 표현을 구분하고 기사별 판단을 요구한다. 모든 금융 뉴스가 단순 사실이라 보호받지 않는다는 결론은 잘못이다. 미국 원매체/해외 처리에 이 조문만 일률 적용하지 않는다.

**이메일도 원자료 이용권 확인이 필요하다.** Telegram 메시지 대신 본인 메일로 바꿔도 제3자 메일 서버 저장·원문 AI 입력·요약/보관 허용 문제는 남는다. 가독성·길이 때문에 채널을 고를 수는 있지만 저작권 해결책으로 이메일을 채택할 근거는 없다.

Guardian Open Platform은 [현행 조건 §6(g)](https://www.theguardian.com/open-platform/terms-and-conditions)에 AI 관련 제한이 있어 무상 AI 요약 대안으로 추천하지 않는다. 일반 뉴스 제공처 확정은 후속 인수이며, 어떤 언론사 RSS나 검색 API든 전부 사용 불가라는 결론은 아니다.

일반 뉴스용 문의 범위는 “비상업 본인1명, 하루 최대3건 중 일부, 원제·매체·발행시각·원문 링크만 원문 그대로, 기사 본문/이미지/AI 처리 없음, 본인 AWS 프로그램→본인1:1 Telegram, 메타데이터 최대90일”이다. 필요하면 출처/링크 보존과 제공처의 삭제 조건에 맞춰 기간을 단축한다. 이 문의는 발송하지 않았다.

### KIS 문의 문안

본인 명의 계좌와 Open API 키로 국내 ETF 최대10종목을 조회하는 비상업 개인 프로그램입니다. 본인 관리 AWS Lightsail에서 종목 마스터 검색·기본정보/시세 조회·등락률 계산을 하고 Tailscale로 본인 기기만 접근하는 관리자 화면에서 관심 종목을 관리하려 합니다. 가격/발송 이력은 Neon PostgreSQL에 저장하고, 제 계정과 봇의 1:1 Telegram 대화로 하루2~3회만 전달하려 합니다. 키/계좌정보는 브라우저·메신저에 전달하지 않고 타인·그룹·채널·공개 화면에는 시세를 제공하지 않습니다. 이 이용이 제5조③의 개인 업무 범위에 해당하는지, AWS·Neon·Telegram 처리/보관에 추가 승인이나 제한이 있는지, 가격/발송 이력1년 보관이 가능한지 확인 부탁드립니다.

### Exa 문의 문안

다음은 일반 언론사 기사로 범위를 확대할 때 사용할 기존 문의안이다. 11/2에 확정한 초기 공식 발표 범위의 운영 허가를 받은 문안이 아니다.

For a non-commercial, single-user application, may I use Search/Contents results as context for the OpenAI API, generate short Korean factual summaries of up to three news stories per weekday, and send only those summaries with source links to my own private Telegram chat? There is no public channel, forwarding service, or other subscriber. Please clarify the applicable permissions under Sections 1.1, 4.1 and 4.2(a), whether publisher-specific permissions are required, and any retention limits for excerpts (up to 7 days), summaries/metadata (90 days) and downstream processors. We will not bypass paywalls or republish article text or images.

이 문안은 검토용이며 문의를 발송하거나 답변을 받지 않았다. 법적 확실성이 필요한 범위는 약관 해석 확인/전문가 검토를 통해 결정한다. 이번 조사만으로 실제 자동 전송을 켜지 않는다.
