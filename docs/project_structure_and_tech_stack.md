# 프로젝트 구조와 기술 스택

- 2026-10-14 반영 상태: [국내 상장 S&P500·NASDAQ100 ETF 자동 게시 설계](isa_etf_publishing_design.md)의 확정 범위와 미정 제공처를 구분한다. 원본은 [2주차 결정 기록](../tasks/brain_storm/session_2026-10-12_week2_requirements.md)이다.

## 이번에 정한 사항

- 저장소 루트의 `docs/`는 요구사항·조사·설계 같은 지속적인 프로젝트 문서를 보관합니다.
- `tasks/`는 주제별 작업 계획과 `progress/`의 날짜별 진행 기록을 보관합니다. 업무 목록을 GitHub Issues로 옮기면 두 곳을 동시에 관리하지 않습니다.
- 실제 Python 패키지는 `src/xfolio/`에 두고, `pyproject.toml`과 `uv.lock`은 저장소 루트에서 관리합니다. 이로써 저장소와 패키지에 같은 `xfolio` 이름을 쓰면서도 중첩된 프로젝트 루트를 만들지 않습니다.
- `tests/`는 구현된 기능의 테스트를, `dashboard/`는 파이프라인과 공통 기록을 읽는 운영 화면 코드를 둡니다.
- `.github/workflows/`는 실행 시각과 배포 방식을 정한 뒤 추가합니다.

| 역할 | 선택 | 적용 시점 |
| --- | --- | --- |
| 언어·패키지 관리 | Python 3.12, `uv` | 현재 |
| 외부 HTTP 요청 | `httpx` | 데이터 소스와 X 연동 시 |
| 데이터·설정 검증 | `pydantic`, `pydantic-settings` | 입출력 계약 확정 시 |
| AI 분석 | 공식 `openai` Python SDK, Responses API | 분석·콘텐츠 생성 시 |
| 테스트·정적 검사 | `pytest`, `ruff` | 기능 구현과 함께 |
| 대시보드 | `streamlit` 선택 의존성 | 파이프라인 기록과 함께 연결, 8주차 마무리 |
| 정기 실행 | GitHub Actions 우선 검토 | 실행 시각·허용 지연 결정 후 |

## 구현 순서

1. 확정한 독자·국내 상장 ETF 관찰 범위·게시 형식에 맞춰 상품 2~4개와 제공처의 자료·공지 확보 및 공개 게시 조건을 확인합니다.
2. 거래일·Asia/Seoul 기준 시각, 출처·발행·수집 시각, 확정 여부가 포함된 파이프라인 입출력과 공통 기록을 정의합니다.
3. `Market Pipeline`의 개장 후·종가 수집 작업과 `News Pipeline`의 뉴스·공식 공지 확인을 구현합니다. 수집 작업 횟수와 실제 API 요청 횟수는 구분합니다.
4. AI 분석·후보 생성, 원본 대조·중복 검증, CLI 미리보기·시험 실행, `Upload Pipeline`과 예약 실행·결과 확인을 연결합니다.
5. 대시보드가 같은 기록에서 후보·상태·이력을 조회하게 연결하고, 누락·오래된 시세·게시 실패를 시험합니다.

## 아직 결정하지 않은 사항

- 관찰 ETF의 구체적인 상품, 지수·ETF·뉴스·공식 공지 제공처와 공개 게시 조건
- `OpenAI` 모델, 프롬프트, 비용 상한
- X API 계정·권한·비용, 인증 방식, 08:30·09:10·18:30·19:00 편성안의 실제 게시 시각
- 시세 허용 지연, 확정 판정, 휴장일·중복·재시도 세부 운영값
- 게시 이력의 영속 저장 방식과 대시보드의 데이터 소스
- GitHub Actions 예약 실행의 지연 허용 범위 및 대체 배포 방식

현재 `src/xfolio/`의 파이프라인 파일은 역할을 표시하는 골격입니다. 외부 API 요청이나 X 게시를 수행하지 않습니다.
