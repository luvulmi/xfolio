## 이번에 정한 사항

2026-10-23 후속 확정: Market Pipeline은 [yfinance](research/week3/yfinance_index_collection.md)로 S&P 500(`^GSPC`)·Nasdaq-100(`^NDX`) 일별 종가를 조회하고 등락률을 계산한다. 기존 검색 우선안을 대체하며 일반 가격 조회용 키 발급은 필요하지 않다. 의존성 설치·실제 연동은 아직 수행하지 않았다. [게시 모드 설계](market_search_and_publishing_modes.md)의 reviewed 관리자 승인은 개발·테스트 전용이고 안정화 후 auto는 검증 통과 콘텐츠를 자동 게시한다.

- 저장소 루트의 `docs/`는 요구사항·조사·설계 같은 지속적인 프로젝트 문서를 보관합니다.
- `tasks/`는 주제별 작업 계획과 `progress/`의 날짜별 진행 기록을 보관합니다. 업무 목록을 GitHub Issues로 옮기면 두 곳을 동시에 관리하지 않습니다.
- 실제 Python 패키지는 `src/xfolio/`에 두고, `pyproject.toml`과 `uv.lock`은 저장소 루트에서 관리합니다. 이로써 저장소와 패키지에 같은 `xfolio` 이름을 쓰면서도 중첩된 프로젝트 루트를 만들지 않습니다.
- `tests/`는 구현된 기능의 테스트를, `dashboard/`는 `로그인 → 대시보드(메인) → 검증 화면`의 관리자 사이트 코드를 둡니다. 대시보드는 공통 기록의 후보·상태·결과를, 검증 화면은 근거·미리보기와 승인/보류를 다룹니다.
- `.github/workflows/`는 실행 시각과 배포 방식을 정한 뒤 추가합니다.

## 구현 순서

1. 3~4주차에 S&P500·나스닥100 종가와 뉴스 제공처 1곳의 자료 확보·공개 게시 조건, 월 총비용 3만 원 내 실현 가능성을 확인합니다.
2. 미국 거래일·한국 운영일·정보 기준 시각·출처·발행·수집 시각, 원본 수정 이력이 포함된 입출력과 공통 기록을 정의합니다.
3. 5~6주차 주당 15시간·총 30시간 기준으로 `Market Pipeline`의 두 지수 마감 수집과 `News Pipeline`의 아침 및 추가 뉴스 수집을 구현합니다. 추가 뉴스는 09:00~17:30에 30분 간격 확인하며 한국 날짜와 같은 미국 날짜가 거래일인 날만 운영합니다.
4. AI 분석·후보 생성, 원본 대조·중복 검증, 관리자 사이트의 로그인·대시보드 후보 목록·검증 화면의 근거/미리보기 확인과 승인/보류, `Upload Pipeline`의 승인 후보 예약 게시·결과 확인을 연결합니다.
5. 기능별 테스트는 개발과 함께 작성하고 7주차에는 예약 시험·장애 검증을 진행합니다. 8주차에는 관리자 사이트의 결과 조회와 README·시연을 마무리합니다. 확정한 30시간 작업 배분은 [설계서](market_briefing_agent_design.md)를 따릅니다.

## 아직 결정하지 않은 사항

- 뉴스 제공처, yfinance 실제 응답의 필드 매핑·아침 도착·공개 게시 조건
- `OpenAI` 모델·프롬프트·의미 검증 방법과 월 총비용 3만 원 내 배분
- X API 계정·권한·비용·인증과 게시 이력 대조 방법
- 종가 확정 판정·공식 거래소 달력·중복 방지 구현·수동 복구와 정정 절차
- SQLite의 스키마·잠금·백업 경로와 관리자 로그인 구현 방식
- Windows 작업 등록 방법·절전/재부팅 처리·로컬 실행 지연 검증

아침 07:30 정보 기준·08:00 발행 목표·09:00 마감, 추가 뉴스 18:00 마감, 일시적 오류 최대 2회 재시도와 뉴스 최근 7일 복구 범위는 확정된 정책입니다. 관리자 사이트에서는 검증을 통과한 후보를 운영자가 승인하거나 보류합니다. 승인 전·마감 후 미승인 후보는 게시하지 않습니다. 부분 게시 실패는 자동 이어쓰기를 멈추고 운영자가 CLI에서 이력을 확인한 뒤 미게시 부분만 수동 재개합니다. 이전 ETF 중심 편성은 현재 구현 기준으로 사용하지 않습니다.

현재 `src/xfolio/`의 파이프라인 파일은 역할을 표시하는 골격입니다. 외부 API 요청이나 X 게시를 수행하지 않습니다.
