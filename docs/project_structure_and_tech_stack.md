# 프로젝트 구조와 기술 스택

- 2026-10-15 반영 상태: [시장 브리핑 AI 에이전트 설계](market_briefing_agent_design.md)의 요구사항·운영 정책은 합의됐다. 제공처·실행·저장 방식은 조사 후 선정한다. 결정 근거는 [재설계 세션](../tasks/brain_storm/session_2026-10-15_market_briefing_redesign.md)이다.

## 이번에 정한 사항

- 저장소 루트의 `docs/`는 요구사항·조사·설계 같은 지속적인 프로젝트 문서를 보관합니다.
- `tasks/`는 주제별 작업 계획과 `progress/`의 날짜별 진행 기록을 보관합니다. 업무 목록을 GitHub Issues로 옮기면 두 곳을 동시에 관리하지 않습니다.
- 실제 Python 패키지는 `src/xfolio/`에 두고, `pyproject.toml`과 `uv.lock`은 저장소 루트에서 관리합니다. 이로써 저장소와 패키지에 같은 `xfolio` 이름을 쓰면서도 중첩된 프로젝트 루트를 만들지 않습니다.
- `tests/`는 구현된 기능의 테스트를, `dashboard/`는 파이프라인과 공통 기록을 읽는 운영 화면 코드를 둡니다.
- `.github/workflows/`는 실행 시각과 배포 방식을 정한 뒤 추가합니다.

| 역할 | 선택 | 적용 시점 |
| --- | --- | --- |
| 언어·패키지 관리 | Python 3.12, `uv` | 현재 |
| 외부 HTTP 요청 | `httpx` | 데이터 소스와 X 연동 시 |
| 데이터·설정 검증 | `pydantic`, `pydantic-settings` | 입출력 계약 확정 시 |

| 테스트·정적 검사 | `pytest`, `ruff` | 기능 구현과 함께 |
| 대시보드 | `streamlit` 선택 의존성 | 5~6주차 공통 기록 준비, 8주차 조회 화면 마무리 |
| 정기 실행 | GitHub Actions 우선 검토, 미확정 | 08:00 목표·추가 뉴스 30분 주기·발행 마감 충족 여부 검증 후 |

## 구현 순서

1. 3~4주차에 S&P500·나스닥100 종가와 뉴스 제공처 1곳의 자료 확보·공개 게시 조건, 월 총비용 3만 원 내 실현 가능성을 확인합니다. 경제지표 전용 수집·비교는 8주차 이후 확장입니다.
2. 미국 거래일·한국 운영일·정보 기준 시각·출처·발행·수집 시각, 원본 수정 이력이 포함된 입출력과 공통 기록을 정의합니다.
3. 5~6주차 주당 15시간·총 30시간 기준으로 `Market Pipeline`의 두 지수 마감 수집과 `News Pipeline`의 아침 및 추가 뉴스 수집을 구현합니다. 추가 뉴스는 09:00~17:30에 30분 간격 확인하며 한국 날짜와 같은 미국 날짜가 거래일인 날만 운영합니다.
4. AI 분석·후보 생성, 원본 대조·중복 검증, CLI 미리보기·시험 실행, `Upload Pipeline`과 예약 실행·결과 확인을 연결합니다.
5. 기능별 테스트는 개발과 함께 작성하고 7주차에는 예약 시험·장애 검증을 진행합니다. 8주차에는 대시보드가 같은 기록에서 후보·상태·이력을 조회하게 연결하고 README·시연을 마무리합니다. 확정한 30시간 작업 배분은 [설계서](market_briefing_agent_design.md)를 따릅니다. 부분 게시 자동 복구와 복수 뉴스 제공처·자동 대체는 8주차 이후로 둡니다.

## 아직 결정하지 않은 사항

- 첫 버전의 지수·뉴스 제공처와 공개 게시 조건·원본 필드. 경제지표 시계열·계절조정 기준은 8주차 이후 확장 설계
- `OpenAI` 모델·프롬프트·의미 검증 방법과 월 총비용 3만 원 내 배분
- X API 계정·권한·비용·인증과 게시 이력 대조 방법
- 종가 확정 판정·공식 거래소 달력·중복 방지 구현·수동 복구와 정정 절차
- 게시 이력의 영속 저장 방식과 대시보드의 데이터 소스
- GitHub Actions 예약 실행의 지연 허용 범위 및 대체 배포 방식

아침 07:30 정보 기준·08:00 발행 목표·09:00 마감, 추가 뉴스 18:00 마감, 일시적 오류 최대 2회 재시도와 뉴스 최근 7일 복구 범위는 확정된 정책입니다. 대시보드는 운영자 조회용이며 부분 게시 실패는 자동 이어쓰기를 멈추고 운영자가 CLI에서 이력을 확인한 뒤 미게시 부분만 수동 재개합니다. 이전 ETF 중심 편성은 현재 구현 기준으로 사용하지 않습니다.

현재 `src/xfolio/`의 파이프라인 파일은 역할을 표시하는 골격입니다. 외부 API 요청이나 X 게시를 수행하지 않습니다.
