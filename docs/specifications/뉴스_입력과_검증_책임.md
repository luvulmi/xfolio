# 뉴스·공식 자료 입력과 검증 책임

> 입력·편성의 단일 기준은 [현재 요구사항](../요구사항.md)이다. 현재 목표는 AM 최대 4글이며 기존 코드·OpenAPI·PM 이력/시험과 구분한다.
- 기준: 2026-10-30. 목표 계약이며 현행 BLS CPI 전용 코드와 구분한다.
- [수집 설계](공식_발표와_공시_수집_설계.md) · [API](API_명세서.md) · [ERD](데이터_모델_ERD.md) · [WBS](../planning/작업_분해_WBS.md)

## Exa 입력 확장 · 구현 전

N02/N08/N09에서 질의·기간·결과 상한·원매체·기사/보도자료·발행 시각 정밀도·수정/확보 버전·본문 절단·비용을 계약으로 확정한다. 검색 응답 성공은 시장 전체 포괄이나 본문 충분성 합격을 뜻하지 않는다. 날짜만 있는 값·자정 정규화·실시간 갱신은 별도로 검토한다. 기존 official 프로필은 Exa 승인에 사용하지 않고 미등록 프로필 차단을 유지한다.

## D01. 입력부터 승인까지

핵심 Exa/BLS, 후속 Fed/BEA/SEC 어댑터가 후보를 발견하고 원문 사용 범위를 확인한 뒤 지원 유형의 사실을 추출한다. 연결 초기에는 허용 실자료 fixture·사전 검토 사실을 쓰되, 제품 인수에는 실제 지원 어댑터와 원문→사실→초안 연결을 검증한다. Marketaux title/snippet은 새 제품의 입력 경로가 아니다.

| 입력 | 표시·처리 |
| --- | --- |
| 허용 과거 fixture | data_origin=permitted_fixture, synthetic=false, 원래 시각/출처 유지. 격리 clock/DB/mock 송신으로 재현 |
| 합성 fixture | data_origin=synthetic_fixture, synthetic=true. 차단/선정 규칙 시험용이며 제품 승인·게시 불가 |
| 실제 어댑터 | data_origin=live_capture, synthetic=false. 원문 확보·수집 완주·이용 검토를 실제 기록 |
| 수동 대조 사실 카드 | extraction_mode=manual_review. 자동추출 결과와 분리하며 출처/시각/hash/검토주체 필요 |
| 권리 불명/거절 | 해당 용도의 AI/저장/공개 진행 차단. 허용 범위의 최소 메타데이터만 유지 |

data_origin과 transport_mode(mock/live), generation_mode(mock/live)를 분리한다. 실제자료+모의전송을 실제 게시 성공으로 표시하지 않는다. 시각을 오늘로 덮어쓰거나 synthetic을 false로 바꾸는 우회는 금지한다.

## D02. 지원 사실

| 유형 | 필수 의미 조건 |
| --- | --- |
| earnings | 발표회사·(SEC이면 CIK)·회계기간·통화/단위·GAAP/non-GAAP·실적/전망 구분 |
| merger_acquisition | 당사자·거래·제안/계약/승인/완료 상태·금액 및 조건·효력시점 |
| policy | 기관·결정 회차·결정 내용·금리 범위/단위·발표/효력 시점·조건 |
| economic_indicator | 기관·지표·대상기간·값/단위·전월비/전년비·계절조정·잠정/수정 여부 |

단일 수치와 명시된 범위(예:회사 매출 전망 하한/상한)는 타입으로 구분해 그대로 보존한다. 임의 단위환산·자체 합산·문맥 없는 숫자복사·서로 다른기간 비교는 초기 자동 추출에서 제외한다. 복잡한 표/PDF는 지원하지 않는다고 표시한다. ETF 가격 등락률 계산은 별도 Market Pipeline 규칙이다.

## D03. 공통 입력 계약 · 목표

| 영역 | 필드와 의미 |
| --- | --- |
| 출처 | 핵심 source_id=exa/bls, 후속 fed/bea/sec, source_record_id, source_url, source_revision, content_hash |
| SEC | cik, accession_number, form, item, document_name/attachment URL. 비SEC에서는 null |
| 시각 | published_at, accepted_at(nullable), 최초 retrieved_at/available_at, 재확인 last_checked_at, 원래 시간대/정밀도, event_time, target_period |
| 수집 | collection_run_id, scope, adapter_version, watchlist_version, 조회창·필수범위·완료범위·커서·complete/partial/failed |
| 이용검토 | rights_status, 용도별collection/storage/ai_transfer/summary_publication, review_id, reviewed_by/at, expires_at, policy_reference |
| 근거 | evidence_text(허용범위), evidence_refs, 문서/문단/표셀 위치, 근거를 포함한정규화텍스트의SHA256 |
| 주장 | claim_id, event_type, subject, action, value 또는 range, unit, comparison_basis, conditions, target_period, evidence_refs |
| 사건 | event_key, fact_version, supersedes/정정 관계, change_reason |
| 검토 | related/importance와 근거, 의미 검토주체·시각·입력버전; 모델이reviewed=true를 만들지 못함 |
| 재현 | schema_version=official_news_input_v1, data_origin, synthetic, extraction_mode, generation_mode |

source_id는 제공처 식별자이며 Exa가 발견한 원매체와 구분한다. 현행 evidence_bundles.source_id 저장키와 혼동하지 않고 [ERD](데이터_모델_ERD.md)의 기관+원자료ID 매핑을 따른다. 예전 reviewed_news_input_v1과 새 계약을 이름만 바꿔 혼용하지 않는다.

해시를 계산한 근거에서 evidence_span/위치를 대조한다. 숫자가 존재한다는 것만으로 주체·기간·부정·조건이 맞는 것은 아니다. published_at과 accepted_at 모두 신뢰할 수 없는 날짜형 발표는 초기 지원에서 보류한다. 최초 조회 완료 retrieved_at과 최초 사용 가능 확보 available_at은 같은 버전 재확인으로 덮어쓰지 않는다. available_at은 retrieved_at보다 이르지 않으며 재확인은 last_checked_at에 기록한다.

## D04. 책임 분담

| 단계 | 책임 |
| --- | --- |
| 발견·수집 | worker 어댑터: 허용된 기관/기업/유형·범위·페이지·커서·원문 버전·실패 기록 |
| 사실 후보 | 지원 parser 또는 AI: 허용 근거에서 주장과 조건/위치 추출. 검토 완료나 게시 허가를 부여할 수 없음 |
| 기계 검사 | Python: schema·출처/해시·시각·수치/단위/기간·범위쌍·중복·사용검토·길이 |
| 한국어 초안 | AI: 검사한 사실 후보의 claim_id에 연결. 원문 URL은 서버에서 조합하며 인과관계·가격 예측·매매 지시 추가 금지 |
| 의미 검토 | 운영자: 기사·공식 발표의 실제 내용·회계기간·거래 상태·조건·정정·관련성과 새 사실 대조 |
| 승인 | FastAPI/DB: 정확한 버전·검사·사람 확인·기한·동시 승인·한도 예약·감사 |
| 송신 | worker: 같은 승인/근거 버전·마감·원문 유효성·중복·예산·작업 점유 재확인, 글별 결과 저장 |

목표 검증 프로필은 `official_news_reviewed_v1`, 세 ETF AM은 `am_official_reviewed_v1`이다. 현재 bls_cpi_v1/bls_cpi_pm_v1은 별도다. 모르는 프로필은 거절한다. `validated`는 기계 검사 완료이며 의미 정확성이나 auto 전환을 뜻하지 않는다.

## D05. 승인 확인

review_checks는 evidence_support, conditions_preserved, relevance_and_novelty 세 항목을 정확히 요구한다. 세 ETF와 뉴스 0건일 때의 정상 수집 완료도 확인한다. 주체/시각/hash는 서버가 현재 버전에 묶어 감사 기록에 저장한다. 보류 사유를 기록하고 새 버전은 다시 검사·승인한다. 첫 전송 시도 후 버전 교체 금지와 CLI 수정 단계는 운영 정책을 따른다.

## D06. 시간·0건·실패

AM은 같은 완료 거래일의 세 ETF와 07:30까지 확보한 뉴스 0~3건으로 편성한다. 필수 scope가 complete여야 정상 뉴스 0건을 인정한다. 필수 ETF 누락·수집 실패·중요 근거 충돌은 전체 보류하며 PM 신규 편성은 만들지 않는다. 원문 정정/접근 실패로 근거를 재확인할 수 없으면 전송을 보류한다.

## 현재 구현과 차이

현재 MarketSnapshot은 두 지수, NewsArticle은 Marketaux, BLS 파서는 CPI의 제한된 문형을 지원하며 SEC 실험은 사전 대조 사실 카드다. Fed/BLS/BEA/SEC 어댑터·ETF 전환·공통 입력·새 프로필과 그에 맞는 사람 확인 감사·UI는 목표 구현이다. 기존 승인 store의 CPI PM 특례를 Fed·BLS·BEA·SEC의 검증 완료로 간주하지 않는다. 실제 진척은 WBS와 실행 로그로 판정한다.
