- 기준: 2026-10-30. **목표 설계**, 실제 배포/연동 완료 그림이 아니다.
- [수집 계약](공식_발표와_공시_수집_설계.md) · [API](API_명세서.md) · [ERD](데이터_모델_ERD.md) · [운영 정책](../운영_정책.md)

## 시스템 구성

```mermaid
flowchart LR
  Y["yfinance: S&P500 / Nasdaq100 / DJIA"] --> M["Market Pipeline"]
  F["Fed / BLS / BEA"] --> N["기관별 발표 어댑터"]
  S["SEC: CIK 목록 10 → 20"] --> E["공통 rate limiter / 공시 어댑터"]
  N --> C["출처별 완주 / 원문 버전 / 사실 후보"]
  E --> C
  C --> V["사용 범위 / 시각 / 근거 / 수치 검사"]
  V --> L["Luna 한국어 초안"]
  M --> D[("PostgreSQL: 실행 / 근거 / 편성 / 감사")]
  L --> D
  U["운영자 React"] --> A["FastAPI: 인증 / 조회 / 정확 버전 승인"]
  A <--> D
  D --> W["단일 Python worker: 예약 / 재검증 / 점유"]
  W --> X["X adapter: mock 또는 명시된 live"]
  W --> T["Telegram: 중요한 장애 / 예산"]
  X --> D
```

목표 배포는 Lightsail의 web/api/worker와 외부 PostgreSQL이다. 브라우저는 공급자·DB·봇 비밀에 접근하지 않는다. 수집/AI/게시를 API 요청 내부에서 실행하지 않는다. worker 단일 프로세스 설정과 별개로 DB 점유·사건키·버전 검증이 중복을 막는다. 현재 worker와 이4기관 통합은 미구현이다.

## 수집→초안→검토

```mermaid
sequenceDiagram
  participant W as Worker
  participant P as 공식 출처
  participant D as PostgreSQL
  participant L as AI
  participant A as API
  participant U as 운영자
  W->>D: scope와 watchlist_version 고정, run 시작
  W->>P: 필수 목록 / 페이지 / 문서 조회
  alt 필수 범위 실패 또는 공백
    W->>D: partial/failed, 커서 유지, 편성 보류
  else 범위 완주
    W->>D: complete, 원문 버전/시각, 커서 전진
    alt 중요한 사건의 필수 근거 확인 불가
      W->>D: 편성 보류, 사유 저장
    else 정상 처리 가능
      alt 새 적격 사실 없음
        W->>D: 뉴스0건 기록 (AM은 세 지수 글 검토 대기, PM은 job 없음)
      else 허용 근거와 사실 후보 존재
      W->>L: 검사한 사실과 허용 근거로 한국어 초안
      L-->>W: claim_id와 문장
      W->>D: 코드 검사 결과 / 검토 대기 편성 버전
      end
      opt 검토 대기 편성이 있음 (AM 뉴스0건 포함)
        U->>A: 원문·조건·초안 대조, 현재 버전 승인
        A->>D: 권한/CSRF/버전/검사/한도 확인, 감사와 예약
      end
    end
  end
```

## 승인→전송과 실패

```mermaid
sequenceDiagram
  participant W as Worker
  participant D as PostgreSQL
  participant P as 공식 출처
  participant X as X adapter
  W->>D: due 편성 점유 / 승인버전·기한·예산 확인
  W->>P: 동결 근거 유효성 재확인
  alt 중요한 정정 또는 확인 실패
    W->>D: 보류, 신규 전송 금지
  else 같은 근거 유효
    W->>D: 글별 전송 시도와 예약액 먼저 기록
    W->>X: 승인된 정확 문안 전송
    alt 성공 ID 확인
      X-->>W: post_id
      W->>D: 성공·비용·사건 기록
    else timeout / 결과 불명
      W->>D: unknown, 자동 재전송 금지, 잔여 전송 중단
    end
  end
```

모의 전송 성공과 실제 X 성공은 다른 인수다. 실제 게시에는 명시적 요청이 필요하다. 부분 성공·unknown은 기록을 보존하고 결과 대조 후 복구하며 새 편성 버전으로 중복 전송하지 않는다. 정정은 새 원문/사실 버전을 만들고 첫 전송 전 승인을 무효화한다. 이미 게시한 사실 오류는 운영 정책의 별도 정정 절차를 따른다.
