# 공식 발표와 공시 수집 설계

- 기준: 2026-10-30. **목표 계약·미구현**, [요구사항](../요구사항.md)·[입력 책임](뉴스_입력과_검증_책임.md)·[ERD](데이터_모델_ERD.md)와 함께 적용한다.
- 기관4곳·세 지수·기업10개 시작20개 확장은 확정. 아래 세부 발표 유형·호출 설정은 초기 구현 추천값이다.

## 수집 단위와 최소 지원

| 출처 | 발견 경로 | 최소 추출 대상 | 경계 |
| --- | --- | --- | --- |
| Fed | 공식 통화정책 RSS/발표 일정→FOMC 성명 HTML | 목표금리 범위·결정 행위·발표/효력 시점 | 숫자 범위는 상·하한과 단위를 같이 보존. 연설/의사록 전체는 후속 |
| BLS | 발표 일정→CPI HTML, 필요 시 통계 API 대조 | CPI 월간/연간; 고용은 후속 | 기존 CPI 두 주장 파서만 구현됨. 고용은 후속 신규 유형. 최신 통계 API가 과거 발표 버전을 보장하지 않음 |
| BEA | 공식 RSS/일정→Personal Income and Outlays 발표문·표, 필요 시 API 대조 | PCE 물가·대상기간; GDP는 후속 | 전월비/전년비·실질/명목 혼동 금지. 후속 GDP는 추정 차수·연율도 검사. API 수치만으로 새 발표 시각을 만들지 않음 |
| SEC | CIK별 submissions JSON→필요한 과거목록→accession별 문서/첨부 | 실적 8-K Item 2.02 및 근거 첨부, M&A Item 1.01/2.01과 관련 첨부 | Item 1.01은 M&A 외 중요 확정 계약, 2.01은 자산 취득/처분도 포함하므로 번호만으로 M&A 판정 금지. 9.01은 첨부 위치 단서 |

SEC `data.sec.gov/submissions/CIK##########.json`에서 CIK는10자리로 정규화한다. Archives의 accession 경로는 해당 문서목록에서 얻고 첨부 제목만 보고 EX-99.1을 실적 본문이라고 가정하지 않는다. 과거목록 포인터가 조회 창에 필요하면 끝까지 조회한다. 첫 페이지/최근 배열만 확인하고 범위 완주라고 표시하지 않는다. companyfacts는 필요한 수치 대조 후보이며 M&A/공시 본문 대체가 아니다.

문서에 로그인/유료벽/차단이 있으면 우회하지 않는다. PDF·이미지·복잡한 표는 초기 자동 추출 대상에서 제외하고 수동 검토 대기로 남긴다. 다른 문서의 수치를 끌어와 빈칸을 추정하지 않는다. 자동 처리 지원 밖 중요 사건의 누락은 인수 결과에 드러내야 한다.

## 감시 기업 계약

서버 설정은 `version`, `effective_at`, `companies[{cik,name,tickers,issuer_type,selection_reason,reference_url,verified_at,enabled}]`로 관리한다. run과 draft의 `watchlist_version`은 이 version을 참조하며 설정 조회 API는 안전한 표시 필드만 투영한다. 실제 10개 명단은 확정 전이다. US domestic issuer 10개로 시작하는 안을 권장하며 외국 발행인의 6-K/20-F를 제외할 경우 화면에도 범위를 명시한다. ticker→CIK 매핑은 공식 자료로 대조하고 AI가 추정하지 않는다.

하나의 CIK·여러 주식종류는 한 기업이며, 처리 중인 run/편성은 시작 시 watchlist_version을 고정한다. 명단 변경은 다음 수집부터 적용하고 이전 커서·사건·승인 근거는 보존한다. 신규기업은 감시 시작일과 초기 조회창을 기록해 과거 공시를 새 뉴스로 만들지 않는다. 20개 확장에는 호출량·완주시간·누락·중복 회귀가 선행한다.

## 시간과 버전

`published_at`은 기관 발표 시각, `accepted_at`은 SEC 접수 시각, `event_time`은 실제 사건/효력 시각, `target_period`는 지표·회계기간이다. `retrieved_at`은 해당 근거 버전의 최초 조회 완료(고정), 동일 버전의 재확인은 `last_checked_at`으로 별도 기록하며, **available_at은 해당 버전의 최초 확보 완료 시각**이다. 원천 시각/시간대/정밀도를 보존하고 UTC 정규화하며 날짜만 있는 자료는 임의00:00을 넣지 않는다.

AM은 available_at≤07:30 KST인 버전, PM은 신뢰 가능한 원천 공개시각≤17:30 및 available_at≤17:45인 버전만 쓴다. 두 편성 모두 신뢰 가능한 published_at 또는 accepted_at이 필요하며 날짜만 확인되는 자료는 초기 지원에서 보류한다. 기준 후 신규 본문을 이전 버전처럼 소급하지 않는다. SEC 접수와 사건일 사이 지연은 가능하며 공시 접수를 실시간 사건 탐지로 광고하지 않는다.

URL/ID가 같아도 허용 텍스트의 `content_hash`가 달라지면 `source_revision`을 생성한다. 수정 시각 미제공은 null로 남긴다. SEC accession도 수정·삭제 가능성을 고려해 송신 전 같은 근거의 유효성을 대조한다. 공시8-K/A 및 GDP 수정 추정은 새 자료 버전이며 사실 변경 여부를 판정해 이전 승인 무효화 또는 다음 편성 후보로 연결한다.

## 커서·요청량·실패

- 커서의 고정 scope는 `source_id + feed/dataset + CIK(해당 시) + watchlist_version + adapter_version`으로 식별한다. 회차마다 달라지는 `window_start/window_end`는 collection_run의 조회 범위이며 scope 키에 넣지 않는다. 개별 문서는 source_record_id로 구분한다.
- 출처/기업별 커서는 complete일 때만 전진한다. 정상 신규0건은 complete+new_version_count=0이며 API의 no_updates는 파생 boolean이다. partial/failed는0건과 다르며 실패 회차를 건너뛴 커서 갱신을 금지한다.
- AM07:00~07:30, PM09:00~17:00 매시간+17:30 최종 확인을 기존 초기 편성 시간표로 유지한다. 네 기관·기업10/20개별 요청량과 최종17:45 마감 내 완주는 구현 인수에서 측정한다.
- 최초/복구 조회는 최근7일 상한과 마지막 성공 커서를 기록한다. 더 긴 공백은 gap으로 표시하고 수동 복구 범위를 정하기 전 완주로 표시하지 않는다. 날짜/수정 겹침 창은 설정값으로 기록하며 실제 누락 시험으로 조정한다.
- SEC는 모든 요청 작업을 합친 공통 rate limiter와 설명 가능한 User-Agent(앱/연락처)를 쓴다. 공식 최대10요청/초보다 낮은 **초기1요청/초·순차**를 권장한다. 이는 전체 이용 조건 준수 보장이나 고정 허용량이 아니다.
- 403/429·Retry-After·timeout은 제한된 backoff와 기존 재시도 상한을 적용한다. 여러 worker나 기업별 limiter로 총한도를 우회하지 않는다. 캐시/조건부요청은 공급자가 지원할 때만 사용한다.
- 필수 scope 하나라도 partial/failed면 편성 전체 보류. unsupported/rights 차단은 해당 자료의 eligibility로 분리하되 중요한 사건의 필수 근거를 확인 못하면 편성 보류. UI에서 기관·기업·조회 범위·제외 사유를 공개한다.

## 사건·권리·추출

유형 enum은 `earnings`, `merger_acquisition`, `policy`, `economic_indicator`다. 실적 키는CIK+회계기간, 인수합병은당사자+거래식별(미확정이면 수동 확인), 정책은기관+결정 회차/정책, 지표는기관+지표+대상기간이다. accession은 자료ID이며 사건ID와 같지 않다. 한 거래의 계약/승인/완료는 단계가 달라 새 사실 버전으로 처리한다.

Fed/BLS/BEA 자체 텍스트는 기관 정책의 적용 범위를 기록하고 제3자 콘텐츠를 구분한다. SEC 기업 제출문은 자료별 AI/보관/공개 요약 범위를 검토한다. `rights_status=permitted|pending_review|restricted|expired`와 용도별 검토 근거를 유지한다. 권리가 미확인인 텍스트를 AI에 먼저 보내 확인하지 않는다.

지원 유형의 parser/AI가 사실 후보·근거 위치·조건을 만들고 Python이 필수값과 수치·기간·형식·중복을 검사한다. 운영자가 의미를 확인한 뒤 한국어 문안과 근거를 최종 승인한다. 직접 대조해 작성한 사실 카드도 출처·버전·작성 주체가 필요하며 자동추출 성공률에 합산하지 않는다.

## 개발 인수

기관별 허용 실제 표본과 오프라인 fixture로 정상/신규0건/partial/429/시간미상/정정/지원외형식/권리미확인 사례를 확인한다. SEC는 실적·M&A 각각의 근거와 CIK/티커중복·10→20확장·과거목록·수정/삭제를 시험한다. 세 지수는 같은 완료 거래일·3개완비·길이초과·다우누락을 확인한다. 이는 개발 계약이며 시험 완료 기록이 아니다.

공식 링크와 접근/권리 근거는 [뉴스 조사](../research/뉴스_수집.md)·[데이터 이용 조건](../research/데이터_이용_조건.md)에 모은다.
