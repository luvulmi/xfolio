# 관리자 화면 · 개인용 뉴스레터

- 기준: 2026-11-01, Asia/Seoul. [요구사항](../요구사항.md)·[운영 정책](../운영_정책.md)의 목표 IA다. 신규 기능 구현 완료를 뜻하지 않는다.
- 기존 Google 로그인·검토 화면은 재사용하되 매회 승인 화면에서 자동 발송 관측·설정 화면으로 전환한다. [이전 IA](../archive/2026-11-01_X_공개_게시_이전안/specifications/관리자_화면_구조.md)

## 메뉴와 이동

`Google 로그인 → 대시보드 → 뉴스레터/발송 상세 확인`, 설정할 때 `관심 종목 → 알림 설정`으로 이동한다.

| 화면 | 표시·동작 | 서버 수용 조건 |
| --- | --- | --- |
| 대시보드 | 다음 08/14/16시 편성, 활성 종목 수, 한국 거래일·휴장, 시세 신선도, 뉴스 수집 상태, 최근 발송/장애, 비용, 일시 중지 | 미조회·정상0건·부분 실패 구별. 시세 조회시각/가격 기준시각 별도 |
| 뉴스레터 목록/상세 | 날짜·슬롯·상태 필터, 가격/뉴스 미리보기와 출처, 제외 사유, 종목/설정 버전 | 승인 버튼 없이 검사 통과/제외/보류 표시. 정정해도 전송한 버전 보존 |
| 발송 이력 목록/상세 | mock/live, 예약/시도/완료 시각, 메시지 조각별 성공·실패·불명, 안전한 오류, 본문 | 성공 message_id 근거, 부분 성공/unknown 강조. 자동 재송신 버튼 없음 |
| 관심 종목 | 검색·공식 종목정보 확인·추가, 기본 3종, 활성 3/10, 활성/비활성, 순서 변경 | 국내 상장 해외 ETF 지원 여부 확인. 코드 중복 금지. 동시 추가에도 11번째 활성 거절. 비활성화로 과거 이력 삭제 금지 |
| 알림 설정 | 08:00 고정 표시, 14:00 기본 켜짐, 16:00 기본 꺼짐, 전체 발송 일시 중지/재개 | 인증·CSRF·revision·감사. 시각 임의 변경·수신자/비밀 웹 입력 없음. 재개 시 만료 편성 발송 금지 |

초기 경로 제안은 `/`, `/newsletters`, `/newsletters/:id`, `/deliveries`, `/deliveries/:id`, `/watchlist`, `/settings`다. 현행 hash 라우팅을 유지할 수 있으며 API/라우트는 새 OpenAPI 계약으로 별도 인수한다. 위 경로가 구현돼 있다고 보지 않는다.

## 종목 추가 흐름

`종목명/코드 검색 → 명칭·코드·시장·통화·ETF 여부·지원 확인 → 추가 → 활성 수·표시 순서 갱신`

이름 문자열만 입력해 저장하지 않는다. 공식 마스터와 상품 분류로 확인하고 분류를 검증할 수 없는 종목은 추가를 차단한다. 중복·한도·미지원·시세 미연결을 구분해 설명한다. 기존 종목이 10개라면 비활성화 후 다른 종목을 활성화한다. 단순 가격 하락/거래정지를 지원 불가 종목으로 자동 삭제하지 않는다.

## API·권한·구현 차이

FastAPI가 로그인·CSRF·한도·종목 확인·revision·감사·중지 상태를 검사하고 DB에 기록한다. worker는 같은 설정/DB로 편성하고 전송한다. 변경 API는 종목 추가·활성/순서·알림 설정에만 제공하며 임의 주문/즉시 발송 기능은 없다. 공급자/DB/봇 비밀은 서버에 둔다.

기존 API 명세·ERD·HTML 와이어프레임은 X 승인 기준의 legacy 자산이다. 종목/설정/슬롯/Telegram 결과 계약과 migration은 T02/T05/T06에서 작성한다. 기존 X ID를 Telegram message_id로 덮어쓰거나 PM 차단을 무조건 해제하지 않는다. 구버전 이력은 읽기 전용으로 구분한다.
