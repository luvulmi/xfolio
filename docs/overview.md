# XFolio 스터디 및 개발 개요

## 프로젝트 목표

**XFolio(엑스폴리오)**는 X(구 트위터)와 Portfolio를 합친 이름입니다. 각 크루원이 OpenAI API와 Codex를 활용해 **현재의 주요 주식시장 정보를 수집·분석하고, 읽기 쉬운 콘텐츠를 정해진 시간에 X에 자동 게시하는 AI 에이전트**를 만듭니다.

시장 데이터 수집 + 시장 뉴스 수집 → AI 분석 및 콘텐츠 생성 → 예약 실행 및 X 게시

스터디의 핵심은 주식 지식 자체보다 **기획 → 설계 → 데이터 수집 → AI 분석 → 콘텐츠 생성 → 자동화 → 테스트 → 배포**를 직접 경험하는 것입니다. 이 경험을 업무 자동화, 데이터 분석, 콘텐츠 자동화 등 다른 분야에도 응용하는 것을 목표로 합니다.

## 스터디 방식과 최종 결과물

- **개인별 구현:** 6명이 하나의 서비스를 분담하지 않습니다. 각자 하나씩, 총 6개의 XFolio 에이전트를 만듭니다.
- **공통 흐름, 자유로운 구현:** 전체 작업 단계는 함께 따라가되 언어, 기술 스택, 세부 기능과 자동화 방식은 각자가 선택합니다. 개발이 익숙하지 않은 크루원은 기획·설계 단계부터 리더와 다른 크루원의 도움을 받을 수 있습니다.
- **함께 해결:** 매주 정기 온라인 미팅에서 진행 상황, 선택한 기술과 구조, 막힌 점과 시도한 해결 방법을 공유합니다.
- **최종 결과물:** 개인 XFolio 에이전트, GitHub 레포지토리, 실제 동작 시연, 프로젝트 발표 자료.

## 기능 범위와 데이터 흐름

OT에서 **Market Pipeline, News Pipeline, Upload Pipeline**의 세 가지 파이프라인이 필요하다고 정했습니다. 아래 역할과 입출력은 개발을 시작하기 위한 **설계 초안**입니다. 데이터 소스와 파이프라인의 정확한 경계는 각자 설계할 때 확정합니다.

| 구성 | 맡을 일 | 입력 예시 | 출력 예시 |
| --- | --- | --- | --- |
| Market Pipeline | 현재의 주요 주가지수·경제지표 등 시장 데이터 수집 및 정리 | 기준일, 선택한 데이터 소스 | 출처와 기준 시점이 포함된 시장 데이터 |
| News Pipeline | 금융·시장 뉴스 수집 및 정리 | 기준일, 선택한 뉴스 소스·주제 | 출처와 발행 시점이 포함된 뉴스 목록 |
| AI 분석·콘텐츠 생성 | 수집 결과에서 주요 이슈를 골라 읽기 쉬운 요약 생성 | 시장 데이터, 뉴스 목록, 작성 지침 | 게시 후보 글 |
| Upload Pipeline | 생성한 글을 정해진 시간에 X에 게시 | 게시 후보 글, 게시 일정, X 연결 정보 | 게시 결과 또는 실패 기록 |

**News Pipeline의 범위와 복잡도로 프로젝트 난이도를 조정할 수 있습니다.** 수집 대상과 뉴스 선별 방식은 개인별로 정하고, 선택한 기준을 기록합니다. 구현 과정에서 OpenAI API, 외부 데이터 API, X 연동, 프롬프트 설계, 스케줄링, 배포·운영을 다룹니다.

### 이 저장소의 현재 구현 방향 (2026-10-15 요구사항·운영 정책 합의)

상태: 2026-10-22 상세 기획 Q14까지 확정하고, 남은 정책은 사용자 요청에 따라 [세부 운영 추천안](market_briefing_operating_plan.md)으로 일괄 정의했다. 제공처·비용 실현 가능성과 상세 기술 설계는 검증 대기다. 기준 문서는 [시장 브리핑 AI 에이전트 설계](market_briefing_agent_design.md)이며 결정 이력은 [재설계 세션](../tasks/brain_storm/session_2026-10-15_market_briefing_redesign.md)과 [사전 조사 전 상세 기획 세션](../tasks/brain_storm/session_2026-10-21_pre_research_planning.md)에 있다. 아래 이력의 후속 정의 항목은 운영 추천안에서 제시한 정책값과 조사 의존 항목으로 구분해 읽는다.

이 저장소의 첫 구현은 **S&P500·나스닥100 마감과 관련 뉴스를 수집·정리해 X에 게시하는 시장 브리핑 에이전트**다. 독자는 ISA 투자자를 포함해 두 지수에 관심 있는 개인 투자자다. 아침 브리핑 1호와 새로운 주요 뉴스 최대 2회 발행을 우선한다. 게시문은 명사형 핵심 항목 중심으로 쓰고 글자 수 안에서 확인된 수치·기간·변화·근거를 최대한 담는다. 경제 소식은 근거가 있는 뉴스로 전달할 수 있지만 CPI·고용·FOMC 전용 수치 수집·비교는 개발 범위에 넣지 않는다. [2주차 발표](../tasks/progress/2026-10-18.md)에 예상 모습을 정리한다.

상세 기획 Q1에서 영어·한국어 입력과 한국어 게시를 정했다. 2026-10-22 Q8·Q8-1에서는 아침을 두 지수 마감과 미국 거시경제·정책·시장/업종 전반의 변화로, 추가 뉴스를 두 지수 관련 주요 기업의 실적·전망·중요 사업 변화로 나누기로 확정했다. 기업 뉴스는 밤사이 발표된 미게시 소식도 허용한다. 기업의 범위·지수 관련성·중요도 세부 기준과 정보 신선도 상한은 후속 결정한다. 같은 사건의 후속 보도는 다음 아침 검토로 넘기고, 기업 후속 기사는 검토 뒤 기업 뉴스 편성의 후보로 전달한다. 이는 Q2·Q7 당시 범위에서 변경된 최신 편성이며 뉴스 제공처 1곳, 기존 운영일·발행 한도·검증·승인·수동 정정 원칙은 유지한다.

아침 호는 한국 시간 07:30 정보 기준·08:00 발행 목표·09:00 자동 처리 마감이다. 추가 뉴스는 같은 날짜의 미국 거래소 달력이 거래일인 한국 날짜에 09:00~17:30 동안 30분 간격 확인하며 18:00에 자동 처리를 마감한다. 추가 뉴스 최대 2회 한도는 한국 날짜 기준으로 계산한다. 월 총비용 상한은 3만 원이다. 관리자 사이트에서 초안·근거·미리보기를 확인하고 운영자가 승인한 후보만 예약 게시한다. 결과는 사이트에서 조회하고 부분 게시 복구는 CLI로 처리한다. 구체적인 발행·검증·실패·정정 기준은 설계서를 따른다.

Q9(2026-10-22)에서 기업 관찰 범위는 두 지수 중 하나 이상에 포함된 기업 중 최대 10개를 고정 선정하는 것으로 구체화했다. 실제 목록은 조사 후 결정하며 기업별 발행 횟수를 할당하지 않는다. Q10에서 확인된 실적·회사 전망·핵심 사업의 중요한 확정 변화 중 매출·이익·핵심 사업과의 연결을 원문으로 설명할 수 있는 사건을 선정하기로 정했다. 주가 등락·목표가만의 기사, 루머·일상 홍보·재해설은 제외한다. Q11에서 시간대별 할당 없이 하루 최대 2회를 사용하기로 정해 오전에 한도를 모두 쓸 수 있다. 한도 소진 후 기업 소식은 다음 아침 검토 후 기업 뉴스 후보로 넘긴다. 후보 간 우선순위와 정보 신선도 상한은 후속 정의한다.

Q12에서는 현재 확보한 기업 후보를 사건의 확인된 중요성 → 기업의 지수 내 중요성 → 새 사실의 최신성 순으로 비교하기로 정했다. 앞서 미정으로 둔 후보 우선순위는 이 결정으로 확정했으며, 실제 비교·점수화의 일관성은 샘플과 운영자 검토로 검증한다. 정보 신선도 상한은 별도 후속 정의한다.

Q13에서 아침 업종 뉴스는 업종 공통의 정책·규제·수요/공급·비용/공급망·사업 구조 변화가 근거로 확인되는 기사에 집중하기로 정했다. 단순 업종별 등락률 나열·근거 없는 테마/가격 전망은 제외하고, 단일 기업 사건은 기업 뉴스로 분류한다.

Q14에서 07:30 이후 수정된 기사는 확인 가능한 기준 전 버전의 사실만 아침 호에 사용하기로 확정했다. 이전 버전이 없거나 핵심 오류 정정이 확인되면 사용하지 않는다. 남은 시간·신선도·중복·승인·대기열·수집 실패·수치·글 길이·복구·운영·보관·예산·시험 기준은 운영 추천안 R01~R14에 정리했다. 이는 조사할 조건을 구체화한 문서이며 구현이나 실제 제공처 검증 성과는 아니다.

국내 TIGER·KODEX 4개 ETF의 개별 장중·종가 게시는 현재 범위에 넣지 않는다. 이전의 국내 ETF·KOSPI·KOSDAQ 중심 편성은 [이전 설계](market_briefing_agent_design.md)와 [2주차 결정 이력](../tasks/brain_storm/session_2026-10-12_week2_requirements.md)에 보관한다. 무료 제공처를 우선 조사하며, 수집 가능성과 공개 X 게시 허용 여부를 구분한다. 두 지수의 무료 조회 경로는 확인했으나 정기 공개 게시가 허용된 무료 제공처는 아직 확보하지 못했다. 근거는 [미국 지수 데이터 조사](research/us_index_data_research.md)에 기록한다.

시장·뉴스 수집 → AI 분석·생성 → 관리자 사이트 검토·승인 → 예약 X 게시 → 결과 확인의 흐름을 완성한다. 11/2~11/15는 주당 15시간·총 30시간 기준으로 두 발행 흐름과 최소 관리자 사이트를 연결하고, 7주차 시험·8주차 결과 조회와 시연 마무리로 구분한다. 뉴스 제공처는 1곳으로 시작하고 부분 게시 실패는 자동 이어쓰기를 멈춘 뒤 CLI로 확인·복구한다. 상세 작업 배분은 [설계서](market_briefing_agent_design.md)를 따른다. 포괄적인 ETF 추천, 댓글·DM 응답, 계좌 연결, 개인화, 자동 매매와 정기 교육·비교 콘텐츠는 구현 범위에 포함하지 않는다. 아래 OT 목록은 스터디 공통의 **원래 미결정 항목**이며, 이 저장소에서 이미 확정한 독자·대상·게시 형식을 다시 미결정으로 돌리지 않는다.

다음 항목의 구체적인 값과 방식은 OT에서 확정되지 않았습니다. 각자 결정한 내용을 자신의 레포지토리에 기록합니다.

- **대상 시장과 기준 시점:** 어떤 시장을 다룰지, 시장 정보와 뉴스의 기준 시점·시간대를 어떻게 정할지
- **데이터 소스:** 지수·경제지표·뉴스 제공처, 수집 범위, 이용 조건, 출처 표기 방법
- **뉴스 처리 범위:** 수집량, 중복 제거, 관련성 판단, 기사 선정 기준
- **콘텐츠 형식:** 대상 독자, 글의 길이와 문체, 숫자·출처 표기, 게시물 분할 여부
- **자동화 방식:** 실행 시각과 시간대, X 게시 방법, 인증 정보 관리, 배포 환경
- **실패 처리:** 데이터 누락, API 오류, 중복 게시, 게시 실패 시 기록 및 재시도 기준
- **검증 방법:** 분석 내용의 근거 확인, 게시 전 미리보기, 전체 흐름과 예약 실행 시험

수집한 정보와 생성한 글을 대조해, 근거 없는 수치나 뉴스 내용이 게시되지 않도록 확인할 방법도 설계합니다.

## 10-03 오리엔테이션 기록

OT에서는 XFolio에서 만들 에이전트의 큰 흐름과 **Market Pipeline, News Pipeline, Upload Pipeline**의 필요성을 소개했습니다. News Pipeline의 복잡도로 프로젝트 난이도를 조절할 수 있으며, 구현에 필요한 third-party 기능과 함께 공유할 부분·개인별 커스텀 부분을 안내했습니다.

스터디 진행 순서는 **자신만의 Codex 작업 환경 세팅 → 기획·설계 및 리서치 → 개발 → 테스트 및 배포**입니다. 매주 정기 온라인 미팅 전에 각자의 발표 내용을 공유 문서에 작성해 크루원들과 공유합니다.
