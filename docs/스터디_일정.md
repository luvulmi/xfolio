## 4주차 · 10/26 ~ 11/1

**해야 할 일:** 구현 방식과 기술 스택을 확정하고, 이후 2주간 개발할 내용과 예상 일정을 구체화합니다.

**발표일: 2026-11-01(일).** 발표 내용은 2026-10-30 사용자가 전달한 아래 기준을 따른다.

1. **확정한 기획안:** 서비스의 큰 그림과 구체적인 개발 내용, 미결정이었던 주제를 어떻게 결정했는지 설명합니다.
2. **개발 일정과 계획:** 주차별로 할 작업·시간·산출물·완료 기준을 제시합니다. 실제 보면서 작업할 수 있도록 수집 대상, 관리자 메뉴, 추가 API와 검증 항목까지 구체화합니다.
3. **개발 진행 상황:** 현재 구현·검증 결과, 차주 계획, 겪은 문제와 해결 방법을 공유합니다. 모의 시험과 실제 로그인·조회·게시·배포를 구분합니다.

**⭐ 2026-11-01(일)까지 준비:** GitHub 계정과 XFolio repository, X 계정, X 개발자 콘솔 가입·API Key 발급·게시용 사용자 인증/쓰기 권한, OpenAI 등 필요한 서비스의 가입·키·사용 권한을 점검합니다. Neon·Google OAuth는 기존 자산을 재사용하고, 공식 수집 경로·허용 원문 표본·SEC User-Agent와 10기업 CIK, 후속 AWS·Telegram 준비 상태도 확인합니다. 준비 마감은 발표일인 11/1이며, 상태와 완료 조건은 [발표 준비 목록](../tasks/presentations/4주차_개발_계획.md#-11월-1일까지-준비할-것)에 정리합니다. 비밀 값은 문서·Git에 남기지 않습니다.

기존 API 8개·DB 8개 테이블을 재사용하므로 새 AWS DB 생성이나 API 10개 신규 개발을 계획으로 옮기지 않습니다. 1단계는 발행 조회 API 2개를 더해 총 10개를 목표로 합니다. 5~6주차 각 15시간은 확정, 7~8주차 각 15시간은 가정입니다.

## 8주차 · 11/23 ~ 11/29

**해야 할 일:** 11/23~24는 모의 전송·통합 인수 시작·추가 여유에 8시간, 11/25~29는 회귀·발표·남은 결함에 7시간을 가정한다. 11/24 기능 동결을 추천한다.

**시간과 범위:** 아침 단일 편성 핵심 56h+여유 4h=60h다. 기존 AM 최대 3글·DB 제약을 4글로 변경하는 대조 1h를 포함한다. 전체 후속까지 기준 87h이며 7~8주차 가용 시간과 11/24 기능 동결은 가정이다. [WBS](planning/작업_분해_WBS.md)
**발표할 내용:** 한 주 동안 진행한 작업과 현재 상태를 설명하고 최종 결과를 발표합니다.
