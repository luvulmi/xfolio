## 뉴스 파이프라인의 현재 설계

Marketaux 뉴스 API → 시각·S&P 500/Nasdaq-100 관련성 필터 → 같은 사건 묶기 → 근거 충분성·중요도 검토 → 아침 최대 2건 또는 이후 추가 뉴스 하루 최대 2건 → Luna 초안 → Python 재검증 순서로 구현한다. 아침 지수는 별도 `yfinance` Market Pipeline이 제공한다. `symbols`·`entity_types`·검색어 중 실제로 충분한 질의 조합은 아직 미확정이다. [10/25 제한 표본](../tasks/verification/두_지수_뉴스_질의와_감시_비용.md)에서 지수 심볼 검색은 0건, 지수명 검색은 무관 기사와 거시 기사 누락 위험을 보였다. 60분 감시는 초기 시험 추천값이다. 조회 완료 범위를 정의하고 페이지 누락·한도 소진 시 해당 회차 게시를 보류한다. 짧은 발췌가 핵심 사실을 뒷받침하는지, 공개 X 요약·외부 AI 처리가 허용되는지는 **아직 검증해야 한다**. 공통 출처·근거·사건 모델과 로컬 SQLite의 완료 커서를 구현했다. `news-check --run --save-run`은 필수 질의 완료 때만 진행 기록을 전진시키고 공백·동시 갱신을 차단한다. 두 지수 관련 질의 확정·정기 감시·두 번째 아침 기사 선정·실기사 AI·클라우드 DB의 뉴스 커서 이식은 후속이다.

이전 BLS CPI 파서는 실제 자료를 파싱했고 SEC 세 과거 공시를 대조했다. 이 작업은 [BLS 시험](../tasks/verification/BLS_파서와_제공처_채택.md)과 [SEC 시험](../tasks/verification/SEC_기업_공시_발견과_요약_시험.md)에 보존한다. **이번 범위에서 BLS·SEC를 뉴스 필수 경로로 운영하지 않으며**, Marketaux 단독 공개 운영의 과거 불합격 근거도 그대로 유지한다. 사용자 선택은 구현 방향을 정한 것이고 품질·권한·무료 한도 합격 판정은 아니다.

## 자동화 에이전트의 확정 방식

첫 버전은 **Python 코드가 순서와 정책을 정하는 고정 워크플로**다. LLM이 다음 행동을 자유롭게 선택하는 실행 루프를 추가하지 않는다. 확정 모델 `gpt-6-luna`를 기존 OpenAI Python SDK·Responses API로 호출해 관련성 판단·한국어 요약의 구조화 출력을 받고, Agents SDK·LangGraph는 추가하지 않는다. 이는 프로젝트의 구현 선택이며 해당 프레임워크가 불필요하다는 일반적인 결론은 아니다.

```text
Cloud Scheduler → Cloud Run Jobs의 Python 명령 (운영 등록 전)
  → 지수·뉴스 수집 → 규칙 필터 → LLM 관련성·요약
  → Python 사실·시각·중복·길이·예산 검증
  → dry_run / reviewed / auto 정책 확인
  → X 전송 → 성공·실패·게시물 ID 기록
```

LLM은 근거와 문안을 제안하며 예약·게시 모드·예산·일일 한도·승인 상태를 스스로 바꾸지 못한다. 모델에 예약 설정·DB 승인 변경·X 전송 도구를 제공하지 않고 Python이 고정 설정과 상태를 검사한다. `dry_run`은 미리보기, `reviewed`는 정확한 버전에 대한 운영자 승인 후 전송, `auto`는 안정화 시험과 이용 조건을 충족한 뒤 활성화한다. 현재 가상 미리보기는 `can_publish=False`이며 실제 승인·auto gate가 구현됐다는 뜻이 아니다.

공식 OpenAI 문서는 Python/Pydantic 기반 구조화 출력과 SDK 파싱을 지원하지만 구조화 출력에도 내용 오류가 남을 수 있다고 설명한다. 형식 통과를 사실 합격으로 사용하지 않는다. `preview`/Streamlit의 고정 가상 문안과 `ai-preview --run`의 실제 모델 생성 가상 문안을 구분한다. 후자는 출처·근거·수치 등을 기계 검사하지만 자동 의미 검증기가 아니다. 실기사의 외부 AI 전달·근거 보관은 [이용 조건](research/데이터_이용_조건.md) 확인 후 활성화한다. [OpenAI Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)

## 실행과 관리자 화면의 경계

예약 CLI와 Streamlit은 별도 프로세스로 공통 PostgreSQL을 사용하는 구성이 목표다. 현재 원격 저장은 가상 초안에 한하며 뉴스 수집 커서·근거 등의 SQLite 구현은 추가 이전이 필요하다. 브라우저나 Streamlit 세션이 예약을 담당하지 않는다. 아침07:00 준비·07:30 정보 기준·08:00 게시 목표/09:00 마감, 추가 뉴스09:00~17:30 매60분 시험 추천(마지막17:30), 게시 대기5분 추천은 [예약 실행](research/예약_실행.md)을 따르며 KST·거래일·마감 검사를 클라우드에서도 적용한다.

로컬 개발은 `dashboard/app.py`를 `127.0.0.1:8501`에서 실행한다. 클라우드는 `dashboard/cloud_app.py`와 비공개 앱 설정·Google OIDC·운영자 허용 목록을 사용한다. 설정·로그인·운영자·만료 확인 전에는 DB에 접근하지 않는다. [배포 절차](../deploy/cloud/README.md) · [가상 미리보기 계약](../tasks/verification/뉴스_수집과_아침_미리보기.md)
