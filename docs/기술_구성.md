기본 구조는 `KRX ETF(KIS)·일반 뉴스 링크/공식 발표(BLS·BEA·Board) → worker 검사/정리 → PostgreSQL → Telegram`이다. `React → FastAPI → PostgreSQL`은 종목·알림 설정과 이력 조회를 담당한다. 화면을 닫아도 worker는 독립 실행한다. DB 점유·유일 키 없이 replica=1만으로 중복을 보장하지 않는다.

### 제품 worker·스케줄러 실행 설계

worker는 API와 분리된 상주 Python 프로세스1개이며 APScheduler 3.x를 내부 라이브러리로 사용한다. `Asia/Seoul` 시간대에서 월~금07:50 `prepare_morning`(종목/설정 버전·뉴스 발행 기준07:50 고정→수집→검사/공식 발표 요약→07:58 편성 저장 목표),08:00 `send_morning`(활성/수신자/DB 편성/마감 재검사→원자 점유→송신/결과)을 등록하는 설계다. 준비·발송 작업의 중복 실행 제한과 재시작 시 놓친 예약 처리를 명시적으로 설정하며 APScheduler의 기본 동작에 맡기지 않는다. DB의 날짜/슬롯 유일 키·원자 점유는 별도로 유지한다.

준비 작업이08시를 넘겨 진행 중이어도 발송 작업이 미완성 자료를 읽지 않게 준비 상태를 검사한다. 안전한 송신 재시도는08:10 마감 내에서만 실행하고 결과 불명은 자동 재시도하지 않는다. 마감 후 누락 편성을 몰아서 보내지 않는다.14/16시 선택 작업은 기본 비활성이다. 실제 의존성 추가·함수 구현·DB 계약·운영 배포는 후속이며 [APScheduler 공식 안내](https://apscheduler.readthedocs.io/en/3.x/userguide.html)의 cron/동시 실행·누락 처리 기능을 인수해야 한다. 제공처 목록/응답의 준비 시각도07:50로 별도 검증해야 하며 기존08시 표본 관측은 이를 대신하지 않는다.

### 뉴스 입력과 개발용 관측

Finnhub는 서버 HTTPX로 `GET /api/v1/news?category=general&minId=0`를 조회하고 `X-Finnhub-Token` 헤더로 인증한다. 키를 URL·브라우저·로그에 넣지 않는다. [개발용 시험](../scripts/experiments/finnhub_news_probe.py)은 제품 어댑터/worker 구현 완료를 뜻하지 않는다. 현재 CNBC/Reuters만 지원하며 제목 기준 미국 시장/경제·확인 목록 미국 기업의 사업 사건을 통과시키고 의견·암호화폐·간접 국제뉴스를 제외한다. ID/정규 URL/정규 제목 중복과 중간선거 사건군 편성 제한을 구분한다. 바꿔 쓴 제목 전체의 의미 중복·미국 뉴스 전체 회수율은 검증하지 않았다.

공급자가 직접 제공한 주소는 출처 일치·HTTPS·허용 호스트·개별 기사 경로를 확인하면 채택하고 HEAD2xx를 필수로 요구하지 않는다. 홈페이지/섹션 주소는 제외한다. Google News는 정상 HTTPS 리다이렉트로 같은 원매체의 개별 기사 주소에 도달한 경우만 인정하며 중간 페이지는 제외한다. HEAD 최대4회/링크·timeout15초·시험 전체최대12회로 제한하고 이후 직접 주소도 계속 검토한다. 본문/이미지·비공식 Google 해독·차단 우회는 사용하지 않는다. 주소 식별은 원문 열람 성공/이용권 검증과 구분하며 `article_availability_verified:false`로 기록한다. 11/3 22:00 KST100건에서 관련9건·직접 주소3건을 선정했다. [실측·한계](../tasks/verification/news/Finnhub_시장뉴스_표본과_개인_전달.md).

정시 관측은 개발용 `finnhub_slot_probe.py`에서 평일08:00 KST 실제 요청 시작08:00:00~08:00:59만 인정한다. 슬롯 전 최대90초 대기하고 지각은 무통신 누락으로 기록한다. 영속 claim/출력 파일로 중복 관측과 덮어쓰기를 막으며 요청/수신/발행 시각·24/96시간 기사 수를 구분한다. 11/4 관측은 Codex 로컬 자동화로1회 예약했으며 제품 APScheduler worker/실제 Telegram 송신 구현이 아니다.

**개인 이용 기준:** Finnhub는 본인1명·비상업·비전문 개인용으로 채택하고 별도 이메일/허가 회신을 자동 발송·보관의 선행 조건으로 두지 않는다. 공급자 개별 허가를 취득했다는 뜻은 아니다. 타인 수신·공개·사업용 확대 시 이용 조건을 다시 검토한다. 일반 기사 본문/이미지·AI 입력/번역/요약은 제외하고 메타데이터는 최대90일 목표·더 엄격한 조건 우선으로 보관한다. 이용 종료 시 DB/캐시/백업 삭제와 Telegram 과거 메시지의 본인 수동 삭제 절차를 둔다. 원매체 링크·08:00 확보·중복/수신자 제한·worker/outbox·실제 본인 수신 등 기술 인수는 그대로 남는다. [조건 기준](research/데이터_이용_조건.md).

KIS는 현재가/일별 원주가 REST를 우선 검토한다. 장중 5분 신선도 기준을 입증할 실제 시각 필드가 없으면 체결 조회 등 보완 경로를 인수해야 하며 실시간 스트리밍을 완료했다고 표현하지 않는다. 주문 API는 사용하지 않는다. 인증 키·토큰은 서버 로컬 비밀로만 관리한다.

관리자 접근은 [비공개 배포](research/비공개_배포.md)를 따른다. 사설 접근과 공급자 자료 이용권은 별개다. Neon은 기존 선택을 유지하며 전체 데이터가 AWS 안에만 남는 구조가 아니다.

기존 yfinance SPY/QQQ/DIA·미국 거래일·X adapter/승인 정책·PM 차단은 이전 범위다. 새 국내 슬롯은 별도 프로필/계약·migration·회귀로 도입한다. 기존 DB 운영 반영 여부와 새 제품 완료를 구분한다. 새 의존성/환경변수는 실제 구현 시 pyproject.toml·README에 반영한다.
