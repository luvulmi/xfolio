# 기술 구성 · 개인용 Telegram 뉴스레터

- 기준: 2026-11-01, Asia/Seoul. 제품 목표와 실제 구현 상태를 구분한다.

| 경계 | 기술·목표 | 실제 상태 |
| --- | --- | --- |
| 관리자 | React·TypeScript·Vite·TanStack Query | 기존 검토/승인 UI 기반. 종목 관리·알림 설정·발송 이력 신규 |
| API·인증 | FastAPI·Uvicorn·Pydantic·Google OIDC·서버 세션/CSRF | 로컬 인증/기존 API 자산. 새 종목/설정 계약 전 |
| 국내 가격 | KIS REST 조건부 채택, HTTPX·Decimal | 공개 마스터 3종목 식별 확인. 계좌 있음/Open API 신청 전. 종가·장중 실응답/이용 조건 대기 |
| 뉴스·공식 근거 | Exa·기존 BLS CPI | 수집/검사/AM 연결 기존 자산. 새 검색 기준·개인 이용/보관 허용·실자료 인수 필요 |
| AI | 기존 OpenAI SDK·Responses API·Luna | 요약 자산 재사용, 가격 계산은 Python. 새 뉴스 품질 인수 필요 |
| 공통 DB | PostgreSQL(Neon)·SQLAlchemy Core·psycopg·Alembic | 기존 AM 승인·0002 자산. 관심 종목/설정/슬롯/outbox의 새 migration 미작성 |
| 예약 | 별도 Python worker·APScheduler 3.x | 구현/의존성 추가 전. 한국 거래일·08/14/선택16시 처리 목표 |
| 전달 | Telegram Bot API·영속 outbox | 기존 테스트 수신 이력. 뉴스레터 자동 전송/운영 outbox 미구현 |
| 배포·검증 | Docker Compose·AWS Lightsail Linux·Caddy, pytest/Ruff·Vitest·Playwright·CI | 기존 검사/CI 자산, 새 배포/백업 복원 인수 전 |

기본 구조는 `KRX ETF(KIS)·Exa/BLS → worker 검사/정리 → PostgreSQL → Telegram`이다. `React → FastAPI → PostgreSQL`은 종목·알림 설정과 이력 조회를 담당한다. 화면을 닫아도 worker는 독립 실행한다. DB 점유·유일 키 없이 replica=1만으로 중복을 보장하지 않는다.

KIS는 현재가/일별 원주가 REST를 우선 검토한다. 장중 5분 신선도 기준을 입증할 실제 시각 필드가 없으면 체결 조회 등 보완 경로를 인수해야 하며 실시간 스트리밍을 완료했다고 표현하지 않는다. 주문 API는 사용하지 않는다. 인증 키·토큰은 서버 로컬 비밀로만 관리한다.

기존 yfinance SPY/QQQ/DIA·미국 거래일·X adapter/승인 정책·PM 차단은 이전 범위다. 새 국내 슬롯은 별도 프로필/계약·migration·회귀로 도입한다. 기존 DB 운영 반영 여부와 새 제품 완료를 구분한다. 새 의존성/환경변수는 실제 구현 시 pyproject.toml·README에 반영한다.
