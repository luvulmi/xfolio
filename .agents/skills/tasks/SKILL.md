# 작업 문서와 실행

요청을 작업 문서로 구체화하고 실제 수행과 검증까지 연결한다. 문서를 만든 것으로 구현을 완료했다고 보고하지 않는다.

## 시작과 문서 선택

1. 저장소의 `AGENTS.md`, [작업 목록](../../../tasks/README.md), 요청과 관련된 기존 작업·기준 문서와 코드를 읽는다. 같은 주제의 문서가 있으면 이어 쓰고, 기존 사용자 편집·완료 근거를 보존한다. GitHub Issues로 관리하는 업무는 체크리스트를 별도로 복제하지 않고 해당 이슈와 실행 근거를 연결한다.
2. 요청의 주된 목적에 맞는 폴더를 고른다. 일반 작업은 `plans/`에서 시작하고 시험 자체가 목적이면 `verification/`에서 시작한다. 한 요청에 모든 종류의 문서를 만들 필요는 없다.

| 문서의 역할 | 위치와 파일명 | 기록할 내용 |
| --- | --- | --- |
| 구현·수정·조사 작업 계획 | `tasks/plans/주제.md` | 목표·범위·완료 조건·진행 체크리스트 |
| 구현 계약·시험·관측 | `tasks/verification/주제.md` | 입력·출력·시험 방법·판정 기준·실제 근거 |
| 실제 수행 결과 | `tasks/logs/YYYY-MM-DD_주제.md` | 변경·실행한 검증·결과·남은 일 |
| 주차별 발표·대본 | `tasks/presentations/N주차_주제.md` | 실제 성과 중심의 발표 내용. weekly 스킬 적용 |
| 질문·선택·결정 과정 | `tasks/discussions/YYYY-MM-DD_주제.md` | 추천안·사용자 답·확정/미결정. brain 스킬 적용 |

문서 파일명은 한글과 `_`, 폴더명은 영어 `snake_case`를 쓴다. `OpenAI`·`X`·`tasks` 같은 고유명사와 `README.md`·`SKILL.md`는 유지한다. 날짜는 Asia/Seoul 기준이다. 동일 주제의 계획은 날짜별로 복제하지 않고 갱신하며 파일명 충돌 시 주제를 구체화한다. 사용자가 지정한 경로·형식은 우선한다.

3. 실제 변경에 앞서 선택한 작업 문서를 작성하거나 갱신한다. 기존 문서의 형식이 있으면 활용하고, 새 문서는 아래 항목 중 작업에 필요한 것만 담는다.

```markdown
# 작업 주제

- 작성일·갱신일: YYYY-MM-DD, Asia/Seoul
- 상태: 예정 / 진행 중 / 대기 / 완료
- 관련: 기준 문서·기존 작업·결과 링크

## 목표와 범위

요청한 결과와 이번에 다룰 범위, 완료를 판정할 조건.

## 작업

- [ ] 확인·구현할 일
- [ ] 관련 검증

## 결과와 남은 일

실제 수행 결과·근거 링크·미완료 사유.
```

4. [작업 목록](../../../tasks/README.md)의 알맞은 항목에 연결하고, 필요한 경우 하위 목차도 갱신한다. 사실 확인으로 해결할 수 있는 내용은 먼저 확인한다. 중요한 정보가 부족하면 해당 부분만 질문하고 답과 무관한 작업은 계속한다. 일상적인 구현 선택은 합리적인 가정을 문서에 남기고 진행한다.

## 수행과 검증

- 구현·수정 요청은 문서 작성 후 곧바로 실제 작업을 이어 간다. 이미 허용된 저장소 작업에 계획 승인을 다시 요구하지 않는다. 사용자가 계획·초안만 요청했다면 문서까지만 작성한다.
- 확정 요구사항과 운영·기술 기준은 `docs/`, 기술·서비스 조사 근거는 `docs/research/`에 둔다. 작업 문서에는 실행 범위·상태·근거 링크를 남기고 같은 내용을 여러 문서에 복사하지 않는다. 실험 코드는 `scripts/experiments/`, 그림·관측 원본은 해당 작업 폴더의 `assets/`에 둔다.
- 진행에 맞춰 체크리스트와 상태를 갱신한다. 확인하지 않은 테스트·실제 API 연동·예약 관측·외부 게시를 완료 처리하지 않는다. 대기 상태에는 필요한 조건과 계속할 수 있는 작업을 구분한다.
- 변경에 맞는 검증을 실제 실행한다. 코드·기능 변경은 AGENTS.md의 관련 검사, 문서 변경은 상대 링크·파일 위치·UTF-8·`git diff --check`를 확인한다. 검사 실패를 숨기거나 승인 요청을 완료로 기록하지 않는다.
- 실제 수행 결과는 해당 날짜·주제의 `tasks/logs/` 문서에 기록하고 계획·검증 문서에서 연결한다. 같은 작업의 기존 기록이 있으면 갱신한다. 계획만 작성했다면 구현 결과 기록을 만들지 않는다.
- 완료 조건과 필요한 검증을 충족했을 때 완료로 표시한다. 커밋·푸시·서비스 신청·유료 실행·실제 외부 게시의 권한은 사용자 요청과 AGENTS.md를 따르며 스킬 호출만으로 확장하지 않는다.
- 마지막 응답은 작업 문서 링크, 실제 변경·검증 결과, 남은 제약을 간단히 보고하고 다음 작업1~3개를 우선순위대로 추천한다.
