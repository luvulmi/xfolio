# Brain

사용자가 `brain`으로 논의할 주제를 제시하면 확인할 수 있는 사실을 먼저 살핀다. 질문마다 추천안과 이유, 선택지의 장단점·불확실성을 제시하고 답을 기다린다. 사용자가 추천안 일괄 정의를 요청한 범위에서는 질문을 반복하지 않고 그 위임 범위를 기록한다.

## 세션 기록

- 새 세션은 시작일(Asia/Seoul)과 한글 주제를 합쳐 `tasks/discussions/YYYY-MM-DD_주제.md`로 만든다. 충돌하면 주제를 구체화하거나 `_02`를 붙인다. 같은 논의는 기존 파일을 이어 쓰고 기존 세션 ID는 보존한다.
- 첫 실질 대화부터 파일을 만들고 세션 ID, 주제, 시작·최근 갱신 시각, 상태(진행 중·보류·종료)를 기록한다. `제안과 대안`, `사용자가 확정한 사항`, `미결정 질문`, `다음에 확인할 일`을 구분한다. 확정 사항에는 선택 이유를 적고 추천안을 사용자 결정으로 기록하지 않는다.
- 중단·정리 요청에는 현재 결론과 미해결 사항을 남긴다. 질문이 남아 있어도 보류 상태로 마칠 수 있다.
- 세션을 [논의 목록](../../../tasks/discussions/README.md)에 연결하고 [작업 목록](../../../tasks/README.md)에서 접근할 수 있게 한다.

논의만으로 코드·설정 변경이나 외부 실행이 승인되지는 않는다. 사용자가 이미 반영·구현을 요청한 범위는 추가 확인 없이 진행한다.

## 확정 사항의 문서 반영

반영을 요청받으면 해당 세션과 관련 기준 문서를 읽는다.

1. 확정 사항과 사용자가 위임한 범위만 반영하고 제안·미결정 항목은 구분한다. 기존 결정과 충돌하면 변경 이유·시점을 남긴다.
2. 기능·범위는 [요구사항](../../../docs/요구사항.md), 기술 선택은 [기술 구성](../../../docs/기술_구성.md), 시각·한도·게시 정책은 [운영 정책](../../../docs/운영_정책.md)에 둔다. 조사 근거는 `docs/research/`, 이전안은 `docs/archive/`에 둔다.
3. 작업 계획은 `tasks/plans/`, 구현 계약·시험 근거는 `tasks/verification/`, 실제 수행 결과는 `tasks/logs/YYYY-MM-DD_주제.md`에 기록한다. 발표 요청에는 weekly를 사용해 `tasks/presentations/`에 계획과 완료 사실을 구분한다.
4. 대상 문서에 날짜·상태·세션 링크를, 세션에는 반영 결과·문서 링크를 남긴다. 문서명은 한글과 `_`, 폴더명은 영어 `snake_case`를 쓰고 고유명사·도구 인식 파일명은 유지한다.
5. 목차·상대 링크와 `git diff --check`를 검증한다. 이동하면 관련 스킬·예약 경로도 갱신한다. 커밋·푸시는 사용자가 명시적으로 요청한 경우에만 한다.
