# Brain

사용자가 `brain`으로 논의할 주제를 제시하면 전역 `grill-me` 스킬의 질문 절차를 따른다. 질문마다 추천안과 이유를 제시하고 답을 기다린다. 선택지의 장단점과 불확실성을 밝히고, 확인할 수 있는 사실은 먼저 확인한다.

## 세션 기록

- 새 주제의 세션 ID는 시작일(Asia/Seoul)과 주제를 합친 `YYYY-MM-DD_<topic>` 형식으로 만든다. `<topic>`은 짧은 영어 `snake_case`로 정한다(예: `2026-10-12_week2_requirements`). 파일명은 `tasks/brain_storm/session_<id>.md`로 한다. 같은 ID가 이미 있으면 다른 주제어를 선택하거나 `_02`처럼 숫자를 붙인다. 같은 논의가 이어지는 동안 ID와 파일명을 유지하고, 사용자가 기존 세션을 지정하면 해당 파일을 이어 쓴다.
- 첫 실질 대화에서 파일을 만들고 진행하면서 갱신한다. 세션 ID, 주제, 시작·최근 갱신 시각(Asia/Seoul), 상태(진행 중·보류·종료)를 적는다. `제안과 대안`, `사용자가 확정한 사항`, `미결정 질문`, `다음에 확인할 일`을 구분한다. 확정 사항에는 선택 이유를 적고 추천안을 사용자 결정으로 기록하지 않는다.
- 사용자가 중단하거나 정리를 요청하면 현재까지의 결론과 미해결 사항을 남긴다. 질문이 남아 있어도 보류 상태로 마칠 수 있다.
- 세션을 [목록](../../../tasks/brain_storm/README.md)에 연결한다. `tasks/README.md`에서도 세션 목록으로 이동할 수 있게 한다.

브레인스토밍은 실행 승인이 아니다. 저장소의 코드·설정·외부 서비스를 바꾸는 작업은 사용자가 별도로 요청한 범위에서 진행한다.

## 확정 사항의 문서 반영

사용자가 반영을 요청하면 지정한 세션과 관련 `docs/`, `tasks/` 문서를 읽고 다음을 따른다.

1. `사용자가 확정한 사항`만 반영한다. 잠정안은 잠정 상태를 유지하고, 제안이나 미결정 사항을 확정 요구사항으로 옮기지 않는다. 필요한 범위가 모호하면 해당 부분만 확인하고 명확한 부분은 진행한다.
2. 기능·범위·입출력은 관련 요구사항 문서에, 기술 선택과 이유는 설계 문서에, 실제 완료 작업만 `tasks/progress/`에 기록한다. 발표 초안을 요청받은 경우 예정된 작업과 완료된 작업을 구별한다. 기존 문서와 충돌하면 결정 변경의 이유와 시점을 남긴다.
3. 반영 문서에 날짜, 상태, 원본 세션 링크를 연결하고 세션의 `반영 결과`에도 대상 문서와 반영 상태를 적는다. `tasks/README.md`의 관련 링크를 갱신한다.
4. 링크와 `git diff --check`를 검증한다. 커밋·푸시는 사용자가 명시적으로 요청한 경우에만 한다.
