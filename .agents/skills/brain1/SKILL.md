# Brain1

사용자가 `brain1`으로 논의할 주제를 제시하면 의견을 주고받으며 생각을 구체화한다. 시작할 때 [grill-me](../grill-me/SKILL.md)를 읽고, 그 스킬이 연결하는 `grilling`의 질문 절차를 따른다. 질문마다 자신의 추천과 이유를 제시하고 사용자 답변을 기다린다. 질문만 이어 가지 말고 대안, 반론, 장단점에 대한 자신의 의견도 분명히 말한다. 저장소에서 확인할 수 있는 사실은 먼저 확인한다.

## 세션 기록

- 새 주제로 시작할 때 `python -c "import uuid; print(uuid.uuid4().hex)"`로 32자리 소문자 16진수 ID를 생성한다. `tasks/brain_storm/session_<id>.md`를 만들고, 같은 논의가 이어지는 동안 그 파일과 ID를 재사용한다. 사용자가 기존 세션 ID로 재개를 요청하면 해당 파일을 읽고 이어 간다. 새 세션을 명시하거나 별개의 주제로 전환하면 새 ID를 만든다. 같은 이름의 파일이 이미 있으면 ID를 다시 생성한다.
- 첫 실질적인 대화에서 파일을 만들고, 논의가 진전될 때마다 갱신한다. 파일에는 세션 ID, 주제, 시작·최근 갱신 시각(Asia/Seoul), 상태(진행 중·보류·종료)를 적는다. 대화 전문 대신 `제안과 대안`, `사용자가 확정한 사항`, `미결정 질문`, `다음에 확인할 일`을 구분해 남긴다. 각 확정 사항에는 선택 이유를 적고, 자신의 추천을 사용자 결정으로 기록하지 않는다.
- 사용자가 중단하거나 정리를 요청하면 현재까지의 결론과 미해결 사항을 기록하고 파일 경로를 알려준다. 모든 질문에 답하지 않아도 보류 상태로 마무리할 수 있다.
- 세션 파일을 [목록](../../../tasks/brain_storm/README.md)에 링크한다. 작업 문서 목록인 `tasks/README.md`에서도 `brain_storm/README.md`로 이동할 수 있게 한다.

브레인스토밍은 실행 승인으로 해석하지 않는다. `grilling`의 실행 보류 지침은 논의 대상 작업에 적용하며, 사용자가 요청한 세션 기록은 대화 중 작성한다. 사용자가 별도로 요청하기 전에는 논의 대상의 코드·설정·외부 서비스를 변경하지 않는다. 확정 사항을 프로젝트 문서에 반영하는 작업은 [brain2](../brain2/SKILL.md)가 맡는다. 기존 저장소 지침에 따라 기록 파일과 링크를 검증하고, 커밋·푸시는 명시적 요청이 있을 때만 수행한다.
