# 주차별 발표 메모

[스터디 일정](../../../docs/스터디_일정.md)의 해당 주차 발표 주제와 실제 작업 근거로 한국어 발표 메모를 작성한다.

1. 사용자가 지정한 주차를 우선한다. 지정하지 않으면 현재 날짜(Asia/Seoul)를 일정과 대조하고 판단할 수 없으면 확인한다.
2. `tasks/presentations/`의 기존 메모와 `tasks/logs/`·`tasks/verification/`의 실제 결과, 관련 `docs/`·`tasks/`·코드를 읽는다. 필요하면 Git 변경도 확인한다. 일정의 계획을 실제 성과로 취급하지 않는다.
3. 같은 주차의 메모가 있으면 그 파일을 갱신하고 없으면 `tasks/presentations/N주차_주제.md`로 만든다. 파일 주제는 한글과 `_`, 폴더명은 영어 `snake_case`를 쓰고 고유명사는 유지한다. 발표일·갱신일은 본문에 남기며 사용자가 파일명을 지정하면 그 요청을 따른다. 대본은 같은 폴더, 그림은 `tasks/presentations/assets/`에 둔다.
4. 주제에 맞춰 목표, 완료 작업과 근거, 주요 선택과 이유, 막힌 점·현재 상태, 다음 작업을 말로 설명하기 쉽게 정리한다. 지정한 발표 시간·형식을 따르고 확인되지 않은 완료·시험·결정은 예정 또는 미확정으로 표시한다. 기존 사용자 편집과 사실관계를 보존한다.
5. 사용자가 Markdown 파일을 화면에 띄워 발표한다면, 한눈에 읽히는 시각 요약으로 편집한다. 처음에 핵심 메시지를 놓고 흐름은 간단한 다이어그램, 선택·상태·비용 비교는 짧은 표로 보여준다. 시각 요소의 레이블은 짧게 쓰고 완료·계획·미검증을 구분한다. 자세한 산식·시험 기록은 근거 문서 링크와 별도 발표 대본에 둔다. 사용자가 지정한 시각화 형식과 미리보기 환경을 따른다.
6. 실제 구현·시험 결과는 `tasks/logs/YYYY-MM-DD_주제.md`와 `tasks/verification/`에 유지하고 발표에는 핵심만 요약·연결한다. [작업 목록](../../../tasks/README.md)의 발표 링크를 갱신한다.
7. 상대 링크·이동 시 관련 경로와 `git diff --check`를 검증하고 결과를 보고한다. 커밋·푸시는 명시적으로 요청받은 경우에만 수행한다.
