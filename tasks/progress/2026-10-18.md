## ❸ 뉴스 정보를 정제·가공하는 과정

```mermaid
flowchart TD
    C["콘텐츠 작성"]
    N["뉴스 수집"] --> S["출처·시각 확인"] --> D["사건 단위 중복 제거"] --> R["관련성·새로움·근거 평가"] --> C
    C --> V["관리자 사이트<br/>근거 대조·미리보기"]
```

**1. 뉴스 수집**

- **제공처:** 공개 게시·요약 조건을 확인한 곳 1곳
- **아침 호 범위:** 직전 호의 정보 기준 시각 이후 ~ 이번 호의 한국 시간 **07:30**
- **최초 실행·장애 복구:** 최대 최근 7일 확인
- **기록:** 기사 링크·출처·발행 시각·수집 시각 구분

**2. 중복 제거**

- **판정 단위:** 동일 링크뿐 아니라 서로 다른 기사의 **같은 사건·이미 전한 동일 사실**도 한 건으로 묶기
- **게시 이력:** 아침 호와 추가 뉴스 사이의 반복 여부 확인
- **새 사실:** 기존 사건의 업데이트 후보로 분리
- **구현 전 결정:** 사건 식별 키와 자동 판정·시험 방법

**3. 중요도·신선도 평가 및 선정**

- **선정 기준:** 미국 시장·두 지수와의 관련성, 정보의 새로움, 원문 근거 확인 가능성
- **제외 기준:** 단순 인기순·기업별 고정 배분, 제목만 있고 본문이나 충분한 요약을 확인할 수 없는 기사
- **미정:** 중요도·신선도 점수와 임계값

**4. 콘텐츠화·검증**

- **작성:** 사건별 확인된 사실·핵심 수치·시점을 명사형 중심의 짧은 항목으로 압축하고 원문 링크 연결. 지수 변화와 관련 뉴스도 같은 방식으로 정리
- **정보 밀도:** 게시물 글자 수 안에서 인사말·반복 설명을 줄이고 수치·기간·대상·변화·근거를 우선 배치. 출처·기준 시각·원문 링크와 사실/해석 구분은 유지
- **관리자 사이트:** 대시보드의 아침 호·추가 뉴스 후보 목록에서 항목을 선택하면 검증 화면에 초안, 원문 링크, 출처·기준/발행 시각, 문장별 근거와 검증 결과를 표시
- **대조:** 자동으로 수치·날짜·링크와 원본을 확인하고 운영자가 표시된 근거와 글을 최종 확인
- **오류 처리:** 근거 누락·모순 시 1회 자동 재생성·재검증 → 재실패 시 게시 보류 및 사유 표시. 사이트에서 임의 문구 수정·무제한 재생성은 제공하지 않음

**5. 게시 전 확인**

- **화면 흐름:** `로그인 → 대시보드(메인) → 검증 화면`. 로그인 후 대시보드에서 검토 대기 건수·최근 게시 결과와 후보 목록을 보고, 후보를 선택해 검증 화면으로 이동
- **미리보기:** 검증 화면에서 X 게시 순서·글자 수·원문 링크와 검증/보류 이유를 확인하고 시험 실행 결과 조회
- **운영자 결정:** 검증 통과 후보에만 `승인`·`보류` 버튼 제공. 승인한 후보만 예약 게시 대상으로 넘기고, 승인 전이거나 보류한 후보는 게시하지 않음
- **결과 확인:** 승인·보류 뒤 대시보드로 돌아와 대기·게시 성공/실패, 게시 시각·X 게시물 ID를 확인. 실패 복구는 기존 CLI 수동 절차 사용
- **최소 화면:** 로그인, 대시보드(후보 목록·상태·결과), 검증 화면(근거·미리보기·승인/보류)만 구현. 다중 계정·권한 체계와 콘텐츠 편집기는 범위에서 제외
- **실제 X 게시 시험:** 별도 승인 후 진행. 08:00 발행 목표는 07:30 생성 후보의 운영자 승인과 검증이 마감 전에 완료된 경우에만 적용

- **아침 운영일:** 새 미국 거래일 마감이 있을 때 최근 마감 거래일 기준 1호
- **추가 뉴스 운영일·한도:** 한국 날짜와 같은 날짜가 미국 거래일인 날, 한국 날짜 기준 최대 2회
- **횟수 구분:** 아침 호의 최대 3건은 한 스레드에 담는 선정 뉴스 수, 추가 뉴스 최대 2회는 별도 발행 횟수
- **실제 게시 조건:** 추가 뉴스의 관련성·근거·중복 검증 통과. 새 소식이 없으면 생략
- **실현 가능성 확인:** 제공처 갱신 시점과 예약 실행 환경을 통한 목표 시각 검증 필요
- **아침 호 형식:** `시장 마감 → 뉴스별 요약·원문 링크(최대 3건) → AI 핵심 정리` 순서의 연결된 X 스레드
- **게시문 문체:** 명사형 항목 중심. 확인된 정보를 글자 수 범위에서 최대한 담되 근거 없는 인과관계·예측으로 분량을 채우지 않음

**완성된 게시글 예시 — 수치·사건·링크 모두 가상**

아래는 아침 호에 뉴스 2건을 선정한 경우의 **스레드 4개 게시물**과, 그날 낮에 새로 확인한 소식의 **별도 게시물 1개**를 보여주는 형식 예시다. `example.com` 링크는 실제 원문이 아니다.

- **글 분할:** 실제 글자 수 검증 후 X 게시물 개수·분할 위치 결정. 브리핑 1호·추가 뉴스 1회의 발행 횟수와 개별 게시물 수 구분
- **게시 결과:** 관리자 사이트 승인·중복 검사 후 성공·실패·게시물 ID 기록. 스레드 중간 실패 시 자동 이어쓰기 중단 → 운영자의 CLI 이력 확인 → 명확한 미게시 부분만 수동 재개
- **성공 여부 불명·정정:** 확인 전 재게시 금지. 게시 후 오류 기록 및 운영자가 검토한 정정문 수동 연결 게시
