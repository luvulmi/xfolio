## 목표와 완료 기준

정규 운영비는 [월 비용](../../docs/research/월_비용.md)의 최신 아침 단일 편성 산식을 따른다. 계정 잔액·개발 한도·예상 운영비는 서로 다른 값이다.

**최신 확정 계획:** 사용자는 OpenAI에 이미 $5를 충전했다. 확인 잔액 $4.97을 쓰고 추가 충전은 $0으로 둔다. XFolio의 실제 키 소속 프로젝트를 대조한 뒤 월 $2 hard limit을 적용한다. X는 청구 주기 $2 한도를 적용하고 첫 유료 시험 직전 $5를 충전하며 자동 충전은 켜지 않는다. X 콘솔의 가장 작은 제시 버튼은 $5였고 해당 금액을 선택할 수 있음을 확인했으나 결제 단계로 진행하지 않았다. 사용자 정의 금액의 최솟값이나 결제 시 세금·환전 수수료는 확인하지 않았다. 보너스 크레딧은 예산에서 차감하지 않는다.

계획 환율 1,815원 기준 OpenAI·X 개발 한도 합계 $4는 7,260원이며 전체 월 50,000원 예산 안에서 관리한다. X 최초 $5 충전은 9,075원에 해당하는 선불 잔액 확보로, 같은 달 사용액 $2와 중복 합산하지 않는다. 세금·환전 수수료와 다른 서비스 비용은 별도다. 정규 운영 X 견적은 [월 비용](../../docs/research/월_비용.md)을 따르며 개발 한도 $2로 운영 가능하다는 뜻이 아니며 운영 전 재산정한다.

- [ ] 실제 OpenAI 키 소속 프로젝트를 확인하고 월 $2 hard limit 적용 후 저장 상태를 검증한다.
- [ ] 첫 X 유료 시험 전에 청구 주기 $2 한도를 저장·검증하고 $5 충전을 진행한다. 최종 결제 금액·조건은 당시 확인한다.

현재 콘솔 설정은 위 조회 표와 같다. 금액 계획만 확정했으며 한도 설정·충전·자동 충전 변경은 수행하지 않았다.

공식 [OpenAI Spend limits](https://developers.openai.com/api/docs/guides/spend-limits)는 알림과 hard limit을 구분한다. 현재 계정 설정에서 hard limit 적용 여부까지 확인해야 하며 반영 지연에 따른 소폭 초과 가능성이 있다.

## ② AWS ringXFolio 계정 준비

사용자는 이전 계정을 기억하지 못해 **새로 만든 ringXFolio를 사용하기로 결정**했다. 기존 계정 복구는 현재 준비 순서에서 제외하며, 이전 계정의 청구·리소스는 미확인 상태로 남긴다. ringXFolio는 **Free 대상 제외·신규 $200 크레딧 미지급·Paid 동의 대기** 상태다. 무료 크레딧을 예산에서 차감하지 않으며 실제 배포 시 유료 플랜 동의·VM 크기·부대비용을 결정한다.

- [x] ringXFolio 계정은 신규 가입 중 계정이라고 사용자가 확인했다. 기존 계정 점검과 구분한다.
- [x] 사용 계정을 ringXFolio로 결정하고 콘솔 로그인 상태를 확인했다.
- [x] 보안 자격 증명 접근 시 계정 설정 완료 안내가 나오며, 가입 계속하기에서 Paid 동의 대기 상태를 확인했다.
- [ ] 배포 준비 때 사용자가 유료 플랜 동의와 남은 가입 절차를 완료하고 서비스 활성화를 확인한다.
- [ ] 활성화 후 ringXFolio의 청구서·미결제 내역을 다시 조회한다.
- [ ] 과금 서비스와 리전을 기준으로 실행 중/중지된 컴퓨팅, 디스크·스냅샷·공인 IP·DB·스토리지·구독을 점검한다. 청구 $0을 리소스 0개로 간주하지 않는다.
- [ ] 루트 MFA·관리자 접근과 예산 알림 설정을 준비한다.
- [ ] 배포 시점에 Lightsail 적정 용량·최신 요금·세금/환율·X/AI 합계와 월 50,000원 상한을 대조하고 플랜을 결정한다.

10/30 조회: **ringXFolio 계정(끝 0045)**의 2026년 10월 청구서는 **예상 USD 0.00·표시할 사용 내역 없음**이었다. Billing 홈 비용 요약은 로드 오류, 예산은 생성되지 않음으로 표시됐다. 사용자의 계정 선택 후 콘솔 로그인은 다시 확인했지만, 보안 설정 접근은 가입 완료 안내로 전환됐다. 가입 화면은 Paid 동의 체크박스가 선택되지 않았고 Confirm이 비활성화된 상태였다. **콘솔 로그인과 가입·서비스 활성화 완료를 구분한다.** 유료 플랜 동의·설정 변경·리소스 생성/종료는 하지 않았다.

가입 단계의 비밀번호·결제/개인 정보 입력과 약관 동의가 필요한 화면에서는 사용자 직접 처리를 안내한다. 실제 VM 생성·배포는 [AWS 배포 계획](클라우드_전환.md)에 남긴다. 예산 알림이 모든 AWS 비용을 자동 차단한다고 보지 않는다.

## ③ Telegram bot 생성

- [x] 공식 BotFather에서 XFolio 알림용 bot을 생성했다. 사용자 완료 보고 기준이다.
- [x] bot username은 `ringXFolioNotifyBot`으로 확정했다. 표시 이름은 별도 확인 전이다.
- [x] 사용자가 토큰을 `.env`에 저장했고 실제 `getMe`로 `@ringXFolioNotifyBot` 인증을 확인했다. 토큰 값은 문서·채팅·Git에 남기지 않았다.
- [x] 개인 대화의 최근 설정 메시지를 확인하고 수신 ID를 `.env`에 저장했다. 새 프로세스에서 토큰·수신 ID 로딩과 형식 검사를 통과했다.

username은 `ringXFolioNotifyBot`으로 확정했다. 사용자가 개인 대화에서 `/start xfolio_setup`을 보내고 `.env`에 `TELEGRAM_BOT_TOKEN`을 직접 입력한다. 설정 도구는 공식 Bot API의 `getMe`·`getWebhookInfo`·`getUpdates`로 봇 일치와 최근 개인 대화의 설정 메시지를 확인하고 수신 ID를 `.env`의 `TELEGRAM_CHAT_ID`에 저장한다. 토큰·수신 ID·응답 원문은 출력하지 않는다. 복수 수신 후보나 기존 다른 ID는 자동 선택/덮어쓰기를 거부한다. 실제 메시지 발송·자동 알림 worker 구현은 이번 환경 준비와 구분한다.

10/30 환경 설정 단계 결과: `BOT_VERIFIED`·`CHAT_ID_SAVED`·`TELEGRAM_ENV_READY` 확인. 잘못 입력된 수신 ID 항목의 봇 username을 확인된 개인 대화의 숫자 ID로 수정했다. `.env`는 Git 제외·미추적 상태이며 메시지 발송은 하지 않았다. 이미 실행 중인 서버에는 재시작 후 환경이 반영되며 자동 알림 연결은 후속이다.

- [x] 사용자 명시 요청으로 본인 개인 대화에 테스트 알림 1건을 발송했다. Telegram API 정상 응답과 사용자 수신 확인을 모두 완료했다. 자동 알림 worker 구현은 후속이다.

위는 기존 조사 기준의 경로 정리이며 이번에 각 기관의 원문 조회·이용 허가 판정을 새로 완료한 것은 아니다. [이용 조건](../../docs/research/데이터_이용_조건.md)과 [개발 일정](../../docs/planning/작업_분해_WBS.md)에 연결한다. 연락처·허용 표본 준비는 미완료로 남기며, 10기업 CIK 대조는 후속 SEC 착수 작업이다.

### 11/1 준비 완료 판단

발표에 필요한 기획·일정·진행 상황·준비 상태 문서는 점검했다. 다만 **전체 준비 목록을 모두 완료했다고 보지는 않는다.** 실제 리허설과 Exa 공개 이용 조건 확인이 남아 있다. GitHub 저장소 존재·읽기 접근은 확인했으며 사용자가 작업별 커밋·push를 요청했다. 발표에는 최신 점검본을 사용하고 공유 전 원격 커밋과 파일을 대조한다. AWS 활성화·실제 X 유료 시험·자동 알림 구현은 후속이다.
