# 개발 일정 · 풀스택 2주 MVP 30시간

- 기준: 2026-10-28, Asia/Seoul · [확정 범위](../../docs/요구사항.md)
- 기간: **5주차 11/2~11/8 15h + 6주차 11/9~11/15 15h**. 기존 선행 코드를 재사용한 작업 예산이며 소요 시간 보장이나 운영 합격 기록이 아니다.
- 실행 순서: [개발 우선순위](개발_우선순위.md), 상세 완료 조건: [MVP 계약](../verification/2주_MVP_구현_계약.md)

## 30시간에 넣는 범위

React/TypeScript 2화면·FastAPI 8개 endpoint·PostgreSQL 8개 저장 단위·단일 Python worker·아침 최대 3글/18시 최대 2글·중요 장애 Telegram·Docker Compose AWS 배포를 연결한다. Streamlit을 새 제품 UI로 확장하지 않는다.

지수·Marketaux 수집기·공통 Pydantic·Luna 가상 분석·가상 미리보기·Neon 시험이 기존 자산이다. React·API·승인·X·worker·Telegram·AWS 제품 배포는 새 작업이다. 뉴스 수집/권한 조사나 프론트 장식을 계속 넓히지 않고 고정된 사례와 허용 입력으로 개발한다.

## 4주차 · 11/1까지 준비

- X 계정·사용자 인증/쓰기 권한, Marketaux/지수 공개·AI 사용 범위, OpenAI 예산 확인
- AWS 계정·결제·Lightsail 지역·1GB 시험안과 HTTPS 도메인/DNS, Telegram bot/chat 준비
- Google OIDC callback 이전, 운영 DB 역할, API/DB/상태·시험 입력 계약 고정
- 미확보 항목은 가상/모의와 실제 완료 조건을 구분한다. 30시간 안에서 공급자 전면 재조사나 여러 AWS 대안 병행 구축을 하지 않는다.

## 5주차 · 검토 가능한 아침 흐름 15시간

| 순서 | 배정 | 작업 | 산출물·검증 |
| --- | ---: | --- | --- |
| 1 | 2h | React/Vite·FastAPI 골격·OpenAPI 계약 | frontend/API 경계와 빌드·기본 healthcheck |
| 2 | 3h | PostgreSQL migration·최소 저장 인터페이스 | 8개 저장 단위 골격, 기존 가상 표 보존, 유일 키·버전·트랜잭션 시험 |
| 3 | 3h | Google 인증·API 조회/결정·summary | 단일 운영자·세션/CSRF, 401/403/409·정확 버전 승인 |
| 4 | 3h | React 목록/상세·승인/보류 | 2화면, 서버 상태 갱신·로딩/빈 결과/오류·충돌 표시 |
| 5 | 3h | 아침 0/1/2뉴스·Luna·검증·저장 | 한 날짜 아침 dry_run→관리자 승인, 지수 누락/partial·길이 초과 보류 |
| 여유 | 1h | 병목 대응 | 미완료·다음 작업 기록 |
| 합계 | **15h** | | **로그인한 React에서 아침 후보 버전 승인** |

8API·저장소 골격을 먼저 만들고 실제 게시·알림 상태 전이는 6주차에 완성한다. 가상 모델의 게시 불가를 해제하지 않으며 제품 초안을 별도로 둔다. 실기사 조건이 안 되면 허용 fixture로 검증한다.

## 6주차 · 18시 발행·알림·AWS 연결 15시간

| 순서 | 배정 | 작업 | 산출물·검증 |
| --- | ---: | --- | --- |
| 1 | 3h | 단일 worker·낮 감시·저녁 동결/편성 | 18시 전 미전송·0~2건·아침 중복/partial·18:10 마감 |
| 2 | 3h | X adapter·DB 점유·글별 결과·비용 차단 | 모의/실제 분리, 타임아웃·부분 성공·unknown의 중복 발행 차단 |
| 3 | 2h | Telegram outbox·중요 이벤트·중복 억제 | 오류/한도·복구 알림, 429 대기·3회 실패와 화면 표시 |
| 4 | 3h | Linux 이미지·AWS Compose·HTTPS·CI | web/api/worker 배포, callback·재시작·메모리·비용, 수동 태그 복귀 |
| 5 | 3h | 통합/E2E·복원·실행 문서·시연 | PostgreSQL 경쟁 상태, React 승인→발행 결과, 장애·알림·기한·예산, 백업 복원 |
| 여유 | 1h | 병목 대응 | 제품 실행/모의/보류 영역과 남은 결함 기록 |
| 합계 | **15h** | | **reviewed MVP·모의/제한 실제 연동·배포 근거** |

각 기능의 테스트를 함께 작성하고 마지막 3h는 통합·장애 검증과 결과 정리에 사용한다. 실제 X/Telegram 시험과 AWS 자원 생성은 필요한 계정·예산·승인 범위가 갖춰진 경우에만 수행한다. 준비가 안 됐으면 배포 완료/실제 발송 성공으로 표시하지 않는다.
