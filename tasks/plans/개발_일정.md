# 개발 일정과 30시간 배분

- 상태: 기존 합의한 계획, 구현 완료 기록이 아님

[주차별 일정](../../docs/스터디_일정.md)의 5~6주차 개발 시간은 주당 15시간·총 30시간을 계획 기준으로 삼는다. 조사·사전 연동 확인은 3~4주차에, 장기 시험과 관리자 사이트 마무리는 7~8주차에 배치한다. 30시간은 완료 보장이 아니며 제공처 확보와 실제 작업 속도에 따라 다시 점검한다. 각 주차의 아래 항목은 완료 기록이 아닌 계획이다.

| 주차 | 작업 배치 | 주차 말 확인할 결과 |
| --- | --- | --- |
| 3주차 · 10/19~10/25 | 두 지수·뉴스의 조회·공개 게시 조건, X 권한·월 비용 조사 | 사용 후보와 확인 근거, 해결되지 않은 의존성 |
| 4주차 · 10/26~11/1 | 실제 데이터 샘플·접근 권한 확인, 저장·실행 방식 선정, 콘텐츠 예시·작업량 확정 | 개발에 사용할 입력 샘플과 실행·검증 계획 |
| 5주차 · 11/2~11/8 | 두 지수·뉴스 수집 → AI 생성·검증 → 관리자 사이트의 아침 호 미리보기·승인 → 게시 흐름과 기록 연결 | 한 날짜의 아침 호를 처음부터 끝까지 시험 실행 |
| 6주차 · 11/9~11/15 | 추가 뉴스·예약 실행·일일 한도·중복 방지와 관리자 사이트의 상태 조회 연결 | 두 발행 흐름의 예약 시험 및 기본 실패 처리 |
| 7주차 · 11/16~11/22 | 5개 미국 거래일 예약 시험, 품질·누락·중복·부분 게시 검증과 수정 | 시험 결과와 남은 결함 목록 |
| 8주차 · 11/23~11/29 | 관리자 사이트의 결과 조회·운영 절차·README·시연 마무리 | 전체 완료 기준 점검과 시연 자료 |

**6주차 연결 완료와 8주차 프로젝트 완료를 구분한다.** 기능별 외부 API 없는 테스트는 개발과 함께 작성하고, 첫 게시 전부터 수치·출처 검증, 발행 이력, 중복·한도 검사, 성공 여부 불명 시 재시도 중단을 갖춘다. 7주차를 미완성 핵심 기능의 신규 개발 기간으로 계산하지 않는다. 관리자 사이트는 5~6주차에 검토·승인 흐름을 연결하고 8주차에 결과 조회와 운영 절차를 마무리한다.

개발 시작 전 공개 게시 권한·자료·X 접근을 확보하지 못하면 샘플과 시험 실행으로 가능한 내부 작업은 진행하되 실제 연동·게시 완료로 표시하지 않는다. 비용이나 범위를 바꿔야 한다면 제약과 대안을 명시해 재조정한다.

### 확정한 개발 30시간 배분 — 완료 보장이 아닌 계획 상한

| 주차 | 작업과 시간 | 합계 |
| --- | --- | --- |
| 5주차 | 지수·뉴스 1곳 연동 4시간 / 공통 데이터·발행 기록·중복 검사 3시간 / AI 생성·근거 검증 3시간 / 관리자 사이트 미리보기·승인과 X 시험 연결 4시간 / 여유 1시간 | 15시간 |
| 6주차 | 추가 뉴스·일일 한도 3시간 / 예약·거래일·마감 처리 3시간 / 관리자 사이트 상태 조회·CLI 수동 복구 3시간 / 기능 테스트·통합 검증·실행 안내 5시간 / 여유 1시간 | 15시간 |

테스트는 각 기능 구현과 함께 수행하며 6주차에는 두 흐름의 통합 검증을 모은다. 5주차 말 아침 호를 끝까지 시험하지 못하면 6주차 진입 전에 병목과 남은 시간을 확인해 재계획한다. 검증을 생략해 분량을 맞추거나 7주차를 자동으로 개발 기간에 합산하지 않는다. 3~4주차 사전 조사와 7~8주차 시험·마무리 시간은 위 30시간에 포함되지 않는다.

### 첫 결과물 범위

- 첫 결과물: 두 지수·뉴스 제공처 1곳, 아침 호·추가 뉴스, 근거 검증·보류, 관리자 사이트 미리보기·승인, 예약·중복·한도 검사, 게시 상태 저장, CLI 수동 복구.
- 첫 실제 게시 전: 원본 수치·출처·시각·근거 검사, 게시 상태와 ID 보존, 중복 차단, 성공 여부 불명 시 재시도 중단을 시험한다. AI 검증 1회 재생성과 운영자 승인을 적용한다.
