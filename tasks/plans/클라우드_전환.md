## 목표·이번 범위

PC를 꺼도 공통 DB·관리자·작업이 독립적으로 실행되는 구성을 목표로 한다. 이번 시험은 기존 가상 미리보기의 PostgreSQL 저장·조회·중복 방지, 관리자 접근 차단, Cloud Run 단발성 시험 실행의 준비다. 실기사·OpenAI·Marketaux·X 호출과 실제 승인·예약 게시 구현은 이 시험에 포함하지 않는다.

## 구현 계약

- 공통 데이터는 기존 `MorningPreview`의 `synthetic=True`, `mode=dry_run`, `can_publish=False`를 저장 직전에 재검증한다. 출처·기준/수집 시각은 가상 fixture의 값을 보존하고 시험 관측 시각은 UTC로 따로 출력한다.
- PostgreSQL은 `preview_id` 기본 키·`prepared_at TIMESTAMPTZ`·JSON 문자열 payload를 사용한다. 동일 버전은 중복 추가하지 않고 덮어쓰지 않는다. 모든 SQL 값은 파라미터 바인딩한다.
- 연결은 짧은 작업별로 열고 닫는다. TLS 검증(`verify-full`)·연결 timeout을 적용한다. 연결 실패 시 로컬 SQLite로 자동 대체하지 않으며 비밀번호·접속 URL·DB 오류 원문을 UI/CLI에 출력하지 않는다.
- schema 초기화와 데이터 쓰기를 구분한다. SQLite 이전은 원본을 read-only로 열고 모든 가상 payload를 재검증한 뒤 PostgreSQL의 단일 트랜잭션에서 삽입한다. 원본은 수정·삭제하지 않는다. 앱 운영용 DB 역할의 권한은 배포 단계에서 별도 제한한다.
- 클라우드 관리자 진입점은 Google OIDC 로그인·검증된 이메일·허용 운영자 목록·토큰 만료 시각을 확인한 뒤 DB에 접근한다. 설정 없음·미로그인·비허용 계정은 차단한다. Community Cloud 비공개 앱 설정은 추가 접근 제한으로 적용한다.
- 클라우드 시험 실행은 `--run`을 명시했을 때만 DB를 사용한다. schema 초기화·SQLite 복사도 각각 명시 옵션이 필요하다. 기본 실행은 무통신 계획이다. DB 실패는 종료 코드1, 설정·입력 실패는2로 구분한다.
- 컨테이너는 Python3.12·고정 uv·`uv.lock`을 사용한다. Docker build context는 필요한 소스·메타데이터만 허용해 `.env`·Git·data·로컬 설정이 들어가지 않게 한다.

## 예약·비용·운영 후속

첫 배포는 단발성 가상 smoke job이고 상시 예약을 자동 등록하지 않는다. 실제 수집·게시·백업 작업이 구현된 뒤 기존 아침/기업 시각·미국 거래일·KST 마감·버전 승인·원자적 상태 점유·불명 응답 재전송 금지를 클라우드에서도 적용한다. 도착 지연이면 마감 검사를 거쳐 보류하며 과거 게시를 자동 재생하지 않는다.

리전 초안은 Cloud Run `us-central1`과 가능한 가까운 Neon 리전이다. 서비스 가입 후 실제 제공 리전과 네트워크를 확인한다. DB1GB·100CU-hours·GCP CPU/메모리·Scheduler3개뿐 아니라 이미지 저장·전송·비밀 접근·백업의 사용량을 기록한다. 알림과 실제 지출 상한은 구분하며 무료 운영을 실측 전에 확정하지 않는다.
