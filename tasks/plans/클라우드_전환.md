## 선택

AWS Lightsail Linux VM 한 대에서 Docker Compose의 `web`(React 정적 파일·Caddy HTTPS), `api`(FastAPI), `worker`(단일 Python 예약 프로세스)를 실행한다. PostgreSQL은 기존 Neon을 유지한다. RDS·ALB·ECS·S3/CloudFront·Terraform·다중 서버·무중단 자동 CD는 2주에서 제외한다.

1GB·IPv4 $7/월은 초기 시험값이다. 이 크기로 API/worker와 수집 라이브러리를 감당하는지 측정해야 하며 적합 판정이 아니다. 부족하면 자동 증설하지 않고 월 예산·후속 범위를 다시 결정한다. 빌드는 CI/개발 환경에서 하고 VM은 완성 이미지/정적 파일을 실행한다.

## 등록 전 준비

- [ ] AWS 계정·결제·선택 지역·청구/고정비·방화벽과 관리자 접근 준비
- [ ] HTTPS용 도메인/DNS·Google callback 주소·허용 운영자 설정 준비
- [ ] Neon migration 역할·api/worker 최소 권한·TLS·백업/복원 범위 준비
- [ ] X·Exa·OpenAI·Telegram 자격을 Git 제외 런타임 환경에 주입. 프론트·이미지·로그에는 비밀 미포함
- [ ] 월 고정비·도메인/백업·관측 사용량과 예산 경보 확인. 앱의 요청 차단이 AWS 청구 중단은 아님

## 배포·검증

- [ ] 재현 가능한 버전 고정 build·일반 사용자 이미지·healthcheck·필요 포트만 구성
- [ ] `web`의 같은 origin `/api` 전달, Google 로그인·세션/CSRF·미인증/비허용 차단 확인
- [ ] worker replica=1·단일 APScheduler·DB 편성 키/점유로 중복 방지
- [ ] 08:00 목표·09:00 마감, 재시작 후 만료/잔여 PM 예약의 전송 차단과 이력 보존을 확인한다.
- [ ] 피크 메모리·CPU·조회 시간·연결 수·DB 사용량과 제한 설정 기록
- [ ] Telegram 중요 오류·quota·전송 실패·중복 억제 확인. 실제 발송은 승인된 개인 chat만 사용
- [ ] 허용 데이터 백업/복원 1회·이미지 태그 수동 복귀·CLI 중단/재개·unknown 대조 절차 시험

단일 VM/worker 전체 중단의 외부 감시와 자동 failover는 없다. 테스트한 장애와 감지하지 못하는 장애를 구분한다. GitHub Actions는 우선 검사·이미지/프론트 build용 CI이며 제품 시간 예약은 worker가 맡는다.

## 이전 검증 이력

10/25 Streamlit 비공개 앱·Google 로그인·Neon 가상 저장/중복 방지는 실제 확인했다. Cloud Run은 결제 미연결로 보류했고 운영 Job·Scheduler는 만들지 않았다. 기존 `dashboard/`·`deploy/cloud/`는 이 시험 자산으로 보존한다. 새 FastAPI/React·AWS·실제 승인·뉴스 커서 이전의 완료를 뜻하지 않는다.
