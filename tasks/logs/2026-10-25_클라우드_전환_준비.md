# 클라우드 전환 준비와 Neon 가상 자료 시험

- 수행일: 2026-10-25, Asia/Seoul
- 상태: PostgreSQL·관리자 진입점·배포 파일 준비, 실제 Neon 가상 자료 시험 성공. 사이트·GCP job·예약은 배포 전
- 관련: [계획·구현 계약](../plans/클라우드_전환.md) · [선택 과정](../discussions/2026-10-25_무료_클라우드_전환.md) · [배포 절차](../../deploy/cloud/README.md)

## 실제 변경

- `cloud` 선택 의존성에 psycopg binary·certifi를, `dashboard`에 Streamlit auth 의존성을 추가하고 `uv.lock`을 동기화했다.
- 가상 초안 PostgreSQL schema 초기화·저장·정확한 버전 조회·최근 목록·중복 방지·가상 SQLite read-only 복사를 구현했다. TLS 검증·연결/쿼리/잠금 timeout과 비밀 비노출 오류를 적용했다. 연결 실패를 로컬 SQLite로 대체하지 않는다.
- 기존 로컬 가상 화면을 공통 renderer로 옮겼다. 클라우드 진입점은 Google issuer·검증된 이메일·운영자 목록·토큰 만료를 검사한 뒤 DB를 연다. 실제 Google 로그인 왕복·운영 승인 기능은 미검증이다.
- 무통신 기본·명시 `--run` 가상 DB 시험 명령, 소스 allowlist 방식 Docker context, Python3.12·고정 uv·잠금 파일 기반 일반 사용자 이미지, Community Cloud 의존성/Secrets 예제·배포 절차를 준비했다.
- 요구사항·기술·운영 문서에서 전환 목표와 로컬 개발/현재 실제 구현을 구분했다. 기존 뉴스 커서·근거의 SQLite 구현은 이번 가상 저장 이전의 완료 범위가 아니다.

## 실제 Neon 시험

사용자가 직접 Neon Free의 xfolio 프로젝트를 만들고 Streamlit에 가입·로그인했다. 브라우저에서 Neon 리전 AWS Asia Pacific Singapore, PostgreSQL18, Free plan을 확인했다. DB 비밀번호·URL은 사용자 `.env`에서 프로세스에만 로딩했고 로그·문서·Git에 쓰지 않았다.

1. 첫 초기화는 pooler의 `unsupported startup parameter`로 실패했다. 비밀 없이 오류 분류·드라이버 종류만 확인했고 timeout을 startup `options` 대신 트랜잭션 내부 `SET LOCAL`로 이동했다.
2. 01:24 KST 초기화·가상 초안 저장·정확한 버전 왕복·중복 방지 성공. `inserted=true`, `can_publish=false`, 종료0.
3. 01:26 KST 별도 가상 SQLite2개 버전 복사: 원본2개·추가1개. 기존 버전은 유지됐다. [복사 결과 JSON](../verification/assets/cloud/neon_migration_20261025.json), 종료0.
4. 같은 원본으로 재실행: 원본2개·추가0개, 왕복·중복 방지 성공. [재실행 JSON](../verification/assets/cloud/neon_repeat_20261025.json), 종료0.
5. 원본 SQLite의 실행 전후 SHA-256 일치. 실제 사용자 운영 DB가 아니라 `.venv/`의 전용 가상 fixture를 사용했다. 공개 기사·OpenAI·Marketaux·X 호출은 수행하지 않았다.

## 로컬 검증

- 신규 클라우드 테스트20개 통과. DB 연결 mock으로 설정·TLS 옵션·원본 보존·입력 거부·비밀 비노출·기본 무통신과 관리자 허용/거부·만료를 확인했다. 관리자 진입점 차단은 Streamlit stub으로 확인했으며 실제 브라우저 OIDC 인증 성공과 구분한다.
- 전체 외부 API 없는 `pytest`: **278개 통과**, 종료0. Windows 임시 폴더는 `.venv/pytest_tmp`로 지정했다.
- `ruff check .`와 `ruff format --check .`: 통과, 종료0. 최종 포맷 검사115개 파일. 신규 테스트의 dict 스타일1건을 수정했다.
- `xfolio status`와 `python -m xfolio.cloud` 기본 실행: 종료0. 기본 cloud 출력에서 DB 요청0·게시 불가를 확인했다.
- `uv build --offline`: source distribution과 wheel 빌드 성공, 종료0. Windows 임시 실행 파일 쓰기 제한으로 첫 시도가 실패해 도구 승인 경로에서 재실행했다. 결과물은 Git 제외 `.venv/cloud_dist/`에 둔다. Docker는 builder와 runtime 단계를 분리해 최종 이미지에는 설치된 가상 환경만 복사한다.
- wheel 안의 cloud·PostgreSQL·renderer·가상 자료·저장소 모듈5개 포함과 `.env`·로컬 SQLite·Git 자료 미포함을 확인했다. 문서13개의 상대 링크155개·UTF-8 BOM 없음, `git diff --check` 종료0을 확인했다. Git의 LF/CRLF 변환 안내는 있었고 공백 오류는 없었다.
- 최초 Streamlit AppTest 시도는 경로 해석 오류2건을 수정한 뒤 이 환경에서 완료되지 않아 중단했다. 인증 경계 단위 검증은 stub으로 분리했고 실제 배포 UI 시험은 남겨 두었다.
- uv의 기본 샌드박스 네트워크·임시 exe 쓰기 제한으로 최초 sync가 실패했다. 공식 PyPI 설치와 후속 offline sync는 도구 승인 경로로 수행해 종료0을 확인했다. 새 의존성 외 서비스 키를 요청하거나 등록하지 않았다.

## 남은 배포 조건

- GitHub 반영 완료: `8861f7095095c938b82d31febfd1e7b830cc8eeb`(`feat: Neon 저장소와 클라우드 관리자 배포 기반 추가`)를 `origin/main`에 일반 push했다. `git ls-remote`로 원격 해시 일치를 확인했다. 배포 선별34개 파일의 상대 링크105개·내부 모듈 import·UTF-8·공백 검사와 실제 비밀 미포함을 확인했다. 선별 구성을 내보낸22개 Python 파일의 Ruff 검사·포맷도 통과했다.
- Streamlit의 진입점 재검사에서 `This file does not exist`가 사라지고 Deploy 버튼이 활성화됐다. 앱 생성은 아직 하지 않았다. Google OIDC·Secrets·비공개 접근 설정이 다음 단계다.
- 커밋 선별 검증: 배포 코드·필수 가상 미리보기·모델·시험·문서34개를 준비했다. CLI·README·기술 문서·목차는 배포 관련 부분만 선택하고 다른 작업 파일은 보존한다. 기존 HEAD와 선별 내용을 별도 폴더로 내보낸 뒤 독립 소스 경로에서 전체 **77개 시험 통과**, 기본 cloud 실행의 DB 요청0·게시 불가를 확인했다. import 정렬을 바로잡고 선별 구성의 Ruff를 확인했다. 작업 폴더 전체의278개 통과 결과와 이번77개를 구분한다.
- Docker CLI는 있으나 `dockerDesktopLinuxEngine` 파이프가 없어 Engine이 실행되지 않는다. `docker desktop start --timeout 45`도 제한 시간 안에 시작하지 못했다. 실제 이미지 빌드·로컬 PostgreSQL container 시험은 미실행이다. Neon 실제 왕복 결과를 이미지 빌드 성공으로 표시하지 않는다.
- 사용자가 10/25 배포에 필요한 변경의 선별 커밋·push를 명시 승인했다. 배포 코드와 필수 가상 모델·미리보기 및 관련 시험·문서만 선택한다. 뉴스 수집·BLS·OpenAI 분석·발표 변경은 작업 폴더에 보존한다. 원격 main은 로컬 HEAD의 조상이며 기존 미전송3개 커밋(지수 수집·문서 구조·tasks 스킬)을 포함해 fast-forward로 반영할 수 있음을 확인했다.
- Streamlit 배포 화면은 `luvulmi/xfolio`, `main`, `dashboard/cloud_app.py`, `xfolio-yuring`으로 입력되어 있다. 원격에 진입점이 없어 `This file does not exist`와 비활성 Deploy를 확인했다. 배포 변경의 중심은 `src/xfolio/{storage,postgres,cloud,dashboard_ui}.py`, `dashboard/{app,cloud_app}.py`, 의존성·컨테이너·Secrets 예제·전환 문서다. 같은 작업 폴더의 다른 미커밋 기능과 필요한 가상 자료·모델 의존성을 구별해 반영해야 한다.
- Streamlit 비공개 앱·Google OAuth client/redirect/허용 운영자·Secrets 설정과 실제 로그인/차단 관측이 필요하다.
- XFolio 전용 Google 프로젝트·결제 계정·API·실행 계정의 최소 권한·secret·리전·비용 통제 확인 뒤 단발성 Cloud Run 시험을 진행한다. 기존 health-test 프로젝트를 수정하지 않았다.
- 운영 커서·실뉴스 근거·승인/게시 상태의 PostgreSQL 이전, 운영 수집/게시/백업 worker와 예약·복원·사용량 관측은 후속이다.
