# Finnhub 선정·필터·개인 전달 검증

- 기록: 2026-11-03, Asia/Seoul. 실제 API 관측은11/2 23:54 KST다.
- 요청: 미국 관련성/중복·Google News 경유 링크·개인 전달/보관 조건 확인 후 기획서·기술 구성 반영.
- 상태: 기술 표본·공개 조건 조사·문서 반영·회귀 검증 완료. 운영 적합성/구체 권한 적용은 미인수다.

## 변경과 관측

[기획서](../../docs/프로젝트_기획서.md)와 [기술 구성](../../docs/기술_구성.md)에 **Finnhub Free general 개발용 조건부 채택**을 반영했다. 공식 발표는 BLS·BEA·Board에서 직접 수집하고 Exa는 초기 필수 경로에서 제외한다. 개요·요구사항·운영 정책·연구·목차·README·AGENTS의 현재 기준도 맞췄다. 이전 실험/발표 이력을 운영 완료로 바꾸지 않았다.

[개발용 스크립트](../../scripts/experiments/finnhub_news_probe.py)는 제목 관련성·ID/정규 URL/정규 제목 중복·기발송 제외·사건군 편성 제한과 정상 HTTPS HEAD 경유를 검사한다. CNBC/Reuters만 지원하며 의미 중복 전체와 미국 뉴스 전체 회수율을 보장하지 않는다. 본문·이미지·원시 뉴스·원제·기사 URL은 파일 보관하지 않는다. 인증 헤더는 Finnhub endpoint에만 전달한다. 정기 worker/DB/실제 송신 구현은 추가하지 않았다.

제한 환경의 최초 API 연결 실패 후 승인된 네트워크 환경에서1회 성공했다. 100건 응답은23:41 표본과 동일 해시였다. 제목 기준 후보5건·의견/암호화폐11건 제외·명시적 미국 관련성 미충족84건 제외였다. 후보 링크 HEAD9회에서 Google 경유4건은 Google 중간 페이지200, CNBC 직접1건은403으로 원매체 자동 확인 통과0건이다. 비공식 복호화·본문 수집·차단 우회를 하지 않았다. HEAD403은 원문 오류나 유료벽을 확정하는 근거가 아니다. [집계](../verification/assets/news_samples/finnhub_filter_followup/metadata.json) · [검증·한계](../verification/news/Finnhub_시장뉴스_표본과_개인_전달.md).

## 조건 조사 판정

[Finnhub 약관](https://finnhub.io/terms-of-service)에서 개인 비상업 이용, 제3자 공유 시 서면 승인, 이용 종료 시 데이터 삭제, 원매체 권리 준수 책임을 확인했다. 본인 AWS/Neon→본인 Telegram과 메타90일/백업 보존 적용의 명시 근거·공급자 회신은 취득하지 못했다. 미확인을 금지 확정으로 표현하지 않았고 모든 개인 이용에 별도 승인이 필수라고 단정하지 않았다.

[Telegram 일반 Bot API 삭제 제한](https://core.telegram.org/bots/api#deletemessage)은 보통48시간이므로 DB 삭제가 장기 메시지 삭제를 보장하지 않는다. 미발송 문의 문안에 처리사업자·캐시/백업·원매체별 제목/링크 조건·이용 종료 시 본인 수동 메시지 삭제로 충족 가능한지도 추가했다. 조건 적용이 확인되기 전 일반 뉴스 자동 전달/영속 뉴스 보관을 비활성으로 둔다. 실제 공급자 문의·Telegram 송신·유료 가입·커밋/푸시는 하지 않았다.

## 검증

- 새 무통신 시험23건 통과. 제목 관련/무관·의견·다른 사건 보존·추적 인자/매체 접미사 중복·기발송 제외·시각 오류·위험 주소·정상 경유/403/중간 페이지/루프/출처 불일치를 검증했다.
- 전체 회귀: `uv run --no-sync pytest -q --basetemp .venv/pytest_tmp_finnhub` **594 passed, 48 skipped, 1 warning**,112.81초. 격리 PostgreSQL 미설정 등 기존 선택 시험48건은 skip이며 Authlib jose deprecation 경고1건은 기존 항목이다. 제한 환경 실행은 기존 API 시험 구간에서 정체되어 중단했다. 이전 동일 환경의 Windows socketpair 제한 기록을 참고해 승인된 제한 밖 실행으로 전환했다. 첫 `uv run pytest`에서 새 시험의 `scripts` import 경로 오류를 발견해 기존 저장소의 importlib 파일 로딩 방식으로 수정 후 재실행했다.
- 새 코드의 Ruff 규칙/서식을 보완했다. 최종 `uv run --no-sync ruff check .`·`uv run --no-sync ruff format --check .` 통과(287개 파일). 변경 Markdown39개·상대 링크430개·UTF-8/BOM·코드 블록·증거 합계·변경 파일 키 미포함·`.env` Git ignore/무추적·`git diff --check`도 통과했다. 임시 문서 검사 스크립트는 검증 후 삭제했다.

## 남은 인수

이 목록은 이메일 확인을 권고하던 당시의 기록이다. 아래11/3 사용자 후속 결정으로1항의 공급자 회신을 필수 조건에서 제외했다. 기술 인수는 유지한다.

11/3 후속 상태 확인에서 공식 Finnhub 약관을 재확인했다. 모든 개인 이용에 별도 승인 의무가 있다고 단정하지 않고 본인 Telegram·클라우드·90일 보관·종료 삭제에 대한 이메일 적용 확인을 권고했다. 기획서 기술 요약표와 루트 README 도입부에 남아 있던 이전 Exa 표현을 현재 Finnhub 개발용 조건부 채택·Exa 초기 제외로 일치시켰다. 실제 문의 발송/회신은 없으며 운영 허가 취득으로 바꾸지 않았다. 문서3개 UTF-8/BOM·상대 링크83개·`git diff --check`를 통과했다. 최초 PowerShell 인라인 검사식의 따옴표 오류를 파일 기반 검사로 수정했으며 임시 스크립트는 삭제했다.

1. 준비된 문안으로 개인 Telegram·AWS/Neon·보존/삭제의 적용 범위를 확인한다. 현재 문의 미발송·회신 없음.
2. 직접 API 원문 URL에 HEAD 성공을 필수로 요구할지 정하고 Google 경유 원문 확보 가능성을 확인한다. 자동 확인0건을 뉴스 자체가 없다는 뜻으로 쓰지 않는다.
3. 실제 평일08:00 관측 후 운영 채택과 일반 뉴스 자동 발송 활성화를 판단한다. 정시 확보를 밤 표본의 사후 계산으로 대체하지 않는다.

## 11/3 사용자 후속 결정 · 이메일 없이 본인 개인용 진행

사용자가 개인 이용·제3자 미공유 범위이므로 이메일 확인이 불필요하다고 판단했다. 공식 약관의 개인 이용과 제3자 공유 제한을 다시 구분했고 모든 개인 이용에 별도 회신이 필수라는 조항은 없음을 확인했다. 이전에 회신을 자동 발송/영속 보관의 필수 조건으로 둔 것은 과도한 프로젝트 제한이므로 제거했다.

Finnhub는 비상업·비전문 본인1명 개인용으로 채택한다. 원제·출처·시각·링크만 사용하고 본문/이미지/AI 입력은 제외한다. 메타90일 목표·더 엄격한 조건 우선·이용 종료 삭제(오래된 Telegram 메시지는 본인 수동 삭제 포함)를 유지한다. 본인 개인 이용 해석이지 공급자 개별 허가·포괄 원매체 라이선스 취득은 아니다. 타인/공개/사업용 확대 시 재검토한다. KIS의 기존 인증/조건 확인 과제는 바꾸지 않았다.

기획서·기술/운영/요구사항·연구·현재 목차/README/AGENTS에 반영하고 검증 문서의 이전 회신 대기 판정은 이력으로 구분했다. `.env`/예시의 설명 주석도 맞췄으며 환경 변수의 파싱 값은 전후 동일함을 확인했다. 제품 코드·관측 JSON·과거 API 결과/테스트 통과 수치는 바꾸지 않았고 실제 송신/문의도 수행하지 않았다.

검증: 변경 Markdown40개·상대 링크437개·UTF-8/BOM·코드 블록·현재 문서 회신 대기 조건 제거·설정16개 이름/예시 일치·`.env` ignore/무추적·`git diff --check` 통과. 일괄 문구 수정 후 어색한 문장을 검사에서 발견해 수정했고 임시 스크립트는 삭제했다. 제품 코드 변경이 없어 전체 pytest는 반복하지 않았다.
