## 구현

- `news_queries.py`의 좁힌4검색식과 `news_models.py`의 출처/시각/수집 상태, `news.py`의 페이지·중복·쿼터·부분/실패 보류·메타데이터 출력 구현.
- `compose.py`·`demo.py`의 고정 가상 아침2글, complete0건1글, partial/failed·모순 상태·기준 후 근거·지수 오류 보류 구현. 선정문은 수기 fixture이며 실제 AI 생성·의미 정확성 검증이 아니다.
- `storage.py`의 가상 버전 저장·동일 버전 중복 방지·읽기, `preview`/`news-check` CLI와 로컬 Streamlit 화면 연결. `data/`는 Git 제외, `can_publish=False` 강제다.
- `scripts/run_dashboard.ps1`로 기존 가상환경의 Streamlit을127.0.0.1:8501에만 실행한다. Windows 작업 등록·외부 배포·자동 로그인·X 전송은 하지 않는다.
- 독립 코드 검토에서 complete 표시와 부분 query/error가 충돌해 정상0건으로 보일 수 있는 경계를 발견해 수집 진행·미리보기 모두 차단했다.
- INFO 수준 HTTPX가 토큰 쿼리URL을 기록하는 문제를 가상 키로 재현했다. 수집 범위의 민감 로그만 차단하고 정상 로그/레벨·종료 후 필터 복원을 검증했다. 실제 키 노출은 없었다.

## 자동화·배포 결정

사용자는 관리자 사이트의 **현재 Windows PC 접속**을 선택했다. 고정 Python 워크플로·Windows 작업 스케줄러·localhost Streamlit·공통 SQLite로 구체화했다. AI는 관련성·요약을 제안하고 예약·예산·승인·X 전송 권한을 변경하지 못한다. 별도 자율 에이전트 프레임워크는 추가하지 않는다.

아침 준비·기업 수집·게시 대기·화면 로그온 시작의 역할과 시각은 기술/예약 문서에 반영했다. 현재는 수동 실행한 가상 화면이며 실제 앱 인증/권한·승인·AI·게시 큐·제품 예약 등록은 미구현이다. R11의 실제 관리자 인증 요구는 유지했다. PC 전원·절전·로그아웃·인터넷 장애의 영향도 구분했다.
