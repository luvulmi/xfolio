## 실제 PostgreSQL 검증

Docker Desktop은 실행 보고와 달리 Linux 엔진 pipe가 없었고 창 접근 승인은 시간 만료됐다. 엔진 설정이나 기존 DB를 변경하는 대신 [PostgreSQL 공식 Windows 안내](https://www.postgresql.org/download/windows/)가 연결하는 [EDB 바이너리](https://www.enterprisedb.com/download-postgresql-binaries)를 사용했다.

- PostgreSQL 17.11 Windows x64 포터블 바이너리만 `.cache/postgres-portable/`에 추출했다. Windows 서비스는 설치하지 않았다.
- `.cache/postgres-test/` 새 cluster·무작위 시험 비밀번호·loopback `127.0.0.1:55432`만 사용했다. 기존 Neon/preview 접속 문자열은 사용하지 않았다.
- 기존 skip 12건의 Alembic migration·변경 불가 trigger·승인/보류·멱등 재전송·동시 승인·사건 예약·마감·합성 차단을 실제 PostgreSQL에서 통과했다.
- 생성 워크플로 4개 DB 시험도 통과했다. `estimated/reserved/confirmed` 예산 합산과 관리자 API에 맞춘 허용 근거 payload를 보완했다.
- 각 시험은 무작위 schema만 만들고 정리했다. 진단 출력에 포함됐던 일회용 시험 DB 비밀번호는 교체했고 새 값은 출력하지 않았다.

## HTTPS·Google·실제 API 브라우저

- [로컬 HTTPS 도구](../../scripts/dev/README.md): `.cache` 자체서명 인증서·loopback 정적 React/API proxy, 기존 Google 설정의 명시적인 메모리 재사용. OS 신뢰 저장소·Google 콘솔·기존 Streamlit callback은 변경하지 않았다.
- 실제 FastAPI·PostgresStore·Alembic·HTTPS·Edge에 Google provider만 주입한 브라우저 통합 **1/1 통과**. Secure/HttpOnly 쿠키, 로그인 state/flow, 조회, synthetic 승인409, CSRF/Origin403, UI 보류와 DB 사유 재조회, 로그아웃401을 확인했다.
- 상세 보류 사유 표시·403 안내와 회귀 2건을 추가했다. 프론트 단위 시험 **10/10**, build 통과. 기존 모의 API 브라우저 4건의 의미는 그대로 유지한다.
- Windows가 하네스 프로세스를 강제 종료할 때 schema가 남는 결함을 발견해 `globalTeardown`으로 정리했다. 자기 실행의 검증된 schema 이름만 정리하며 잔여 browser schema 0개를 확인했다.
- 실제 Google 설정을 사용한 `https://localhost:8443/`은 인증서 검증을 켠 HTTP 200, `/api/auth/me`는401, `/api/auth/login`은 Google로307을 반환했다. Google 인증 시작 페이지에서 **`redirect_uri_mismatch`**를 확인했다. 사용자 callback 등록과 실제 계정 로그인은 미완료다.
- 새 callback은 `https://localhost:8443/api/auth/callback`이다. 기존 Google 키가 존재한다는 사실만으로 새 callback이 등록됐다고 추정하지 않았다. 실제 사용자 로그인 성공·동의·세션 회복/만료의 Google 통합 확인이 남았다.

## 현재 로컬 확인 환경

앞선 요청 시점의 변경은 위 6개 커밋으로 보존했다. 그 뒤 수행한 후속 구현·검증 변경은 미커밋 상태로 검토한 뒤, 사용자의 추가 커밋·푸시 요청에 따라 HTTPS 도구·생성 연결·브라우저 통합·문서의 4개 작업으로 나누어 커밋 대상으로 포함했다. 원격 반영 결과는 실행 후 최종 응답에서 보고한다.

로그인 준비용 API·HTTPS proxy·PostgreSQL은 loopback에서 실행 중이다. mode는 `dry_run`, Google용 schema는 `xfolio_google_dev`이며 실기사나 게시 job을 넣지 않았다. 인증서는 OS에 설치하지 않았다. callback 등록과 사용자 로그인 전에는 실제 로그인 합격을 주장하지 않는다. 도구 종료 방법은 [개발 안내](../../scripts/dev/README.md)에 있다.
