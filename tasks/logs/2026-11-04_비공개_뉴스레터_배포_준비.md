## 실제 변경

독립 worktree `t08-newsletter-deploy`, 브랜치 `codex/t08-newsletter`에서 작업했다. 공통 기준은 `c1b1b1f`와 전달받은 T04/11월4일 정책 스냅샷이다. 원본 작업 트리·공통 의존성/목차/WBS·기획서·기존 `deploy/cloud/`는 수정하지 않았다.

신규 `deploy/newsletter/`에 frontend build+Caddy의 web 이미지, Python API/worker 공용 runtime 이미지, Compose를 만들었다. host 게시 포트는127.0.0.1:8088 한 건이고 API/DB/worker 포트를 게시하지 않는다. worker는 선택 profile·기본 모의 예약·live accepted=false다. API/worker/maintenance 비밀 파일을 분리하고 예시만 만들었으며 실제 비밀은 읽거나 복사하지 않았다. Docker build context allowlist와 폴더 `.gitignore`로 비밀·cache·DB·Git·frontend 결과를 제외한다.

`maintenance.py`는 DB 무접속 plan, 명시 DB 읽기 verify, `purge --execute`를 제공한다. 가격/뉴스/편성90일·설정 감사/가격 없는 outbox365일 만료를 저장 서비스로 삭제하고 재검사한다. 정확 만료 경계·미완성 schema·legacy payload를 복원 gate에서 차단한다. 외부 DB는TLS verify-full을 요구하고 출력에는 집계/고정 오류만 남긴다. 이 도구는 운영 DB에서 실행하지 않았다.

Tailscale Serve·Google callback/CSRF·DB 역할/권한·migration·모의 시작/정지·암호화 백업·격리 복원 후 삭제·journald30일·최대7일 백업·월예산50,000원 재산정과 운영 인수 절차를 정리했다. 삭제 서비스는 개별 트랜잭션이며 보존 gate는 운영 절차의 확인 결과다. 전체 원자 삭제나 앱 자동 기동 잠금으로 표현하지 않았다.

Docker 엔진28.0.1을 읽기 확인한 뒤 로컬 이미지만 만들었다. 위 이미지에는 T08 독립 worktree의 기준 소스만 들어 있다. T05 신규 UI/0006·T06 worker/0007·APScheduler/새 lockfile을 합친 최종 이미지 검증은 통합 담당의 후속이다. 이미지 build 성공을 신규 worker 실행·최종 API·운영 성공으로 해석하지 않는다. API import에서 기존 Authlib jose deprecation warning은 남아 있다.

초기 sandbox 명령은 worktree cache/임시 쓰기에 실패해 도구가 허용한 범위의 실행으로 전환했다. 첫 시험9성공/1실패는 잘못된 URL의 SQLAlchemy ArgumentError를 고정 오류로 분류하지 못한 회귀였고, 이를 수정하고 최종10건을 통과했다. Compose2.33.1의 미지원 `--no-env-resolution` 옵션은 사용하지 않도록 고쳤다. web build의 npm ci가 기존 lockfile에1 moderate·2 critical 취약점을 보고했다. 기존 frontend 의존성의 검사 결과이며 배포 도구 자체에서 발견한 취약점과 구분한다. 임의 lockfile 변경은 하지 않고 통합 담당에 전달했다.
