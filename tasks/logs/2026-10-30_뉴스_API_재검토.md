- 상태: **Exa 개발 채택·뉴스 중심 60h·게시량 확정**, 공개 이용 조건 확인 대기

## 수행

1. 기존 Marketaux·MarketNewsAPI·Finnhub·FMP·Alpaca·NewsAPI·NewsData.io와 추가 Firecrawl·NewsAPI.ai·Exa·ScrapingBee·Alexandria를 비교했다. 공식 가격·본문/메타데이터·AI/공개/보관 조건을 구분했다.
2. 기존 두 API는 고정 UTC 창에서 뉴스 GET16회·usage2회, Exa는 Auto 검색3회+캐시 Contents1회(응답 비용 합계 $0.023)를 실행했다. 기존 두 API의16GET과 Exa검색은 질의 방식/상위결과 수가 달라 통제된 순위 성능 비교가 아니다. Seeking Alpha 동일 URL도 대조했지만 세 제공처 모두 검토한 내용만으로 수치 근거가 부족했다.
3. Exa가 반환한 Intel IR·CNBC로 조정EPS와 전망을 대조했다. 제목/도입부·본문 절단·자정으로 표시된 발행일·실시간 수정·출처별 예상치 차이를 기록했다. 검색의 전체 포괄률·정시 도착·공개 권한은 미검증이다.
4. 사용자 답변으로 Exa 개발 채택, 공개 조건 확인 후 운영을 확정했다. Exa 문의 초안은 작성했지만 발송하지 않았다. 기사 전문·발췌·키는 저장하지 않고 메타데이터 JSON4개만 보존했다.
5. 요구사항·정책·기술·예산·WBS·일정·11/1 화면/대본을 Exa+BLS 핵심, 하루 뉴스2건+지수1건, 핵심55h+여유5h로 갱신했다. Fed·BEA·SEC와 운영 후속35h를 더한 전체90h를 구분했다. 물리DB/OpenAPI/제품 코드는 변경하지 않았으며 Exa 입력 계약 확장은 N02/N08/N09의 미구현 작업으로 표시했다.
6. `.env.example`에 빈 `EXA_API_KEY` 항목을 추가하고 README에 서버 설정 범위를 설명했다. 실제 `.env` 값은 출력·커밋하지 않았다.

## 검증

- 변경 Markdown 39개, 상대 링크 439개·앵커 11개·JSON 예시 4개, UTF-8/BOM·코드 블록 검사 통과.
- WBS 25개 작업과 핵심 55h·후속 35h·전체 90h, 주차별 15/15/15/8/7h 배정 검산 통과. 10기업 목록과 발표 4개 필수 구성을 확인했다.
- 메타데이터 JSON 4개, Exa 15검색 결과·4요청·$0.023 합계와 5가지 예산 시나리오 검산 통과.
- 변경/신규 파일 44개에서 실제 비밀값 일치 0건. `.env` Git 미추적·제외 확인, 기사 전문/발췌 문자열 필드 저장 없음.
- `git -c core.safecrlf=false diff --check` 통과. 문서·설정 예시만 변경하여 제품 pytest는 재실행하지 않았다. 발표의 실제 화면 전환·5분 낭독은 미완료다.
- 프로젝트 환경에는 pypdf가 없어 PDF 추출 명령 1회가 실패했고 번들 Python으로 약관을 읽었다. PDF 포인터 경고가 있었지만 필요한 §1/4 본문을 추출했다.

## 실행 경계와 남은 일

- 성공 HTTP 조회: 기존 두 제공처18회(뉴스16+usage2), Exa4회. 초기 sandbox의 ConnectError는 HTTP 응답 없는 연결 실패이며 성공 조회로 세지 않는다. API 자동 재시도0.
- 별도 OpenAI 생성0·X 게시0·유료 가입/충전0·문의 발송0. 이번 변경의 커밋·push는 하지 않았다. 종료한 정기 관측도 재개하지 않았다.
- Exa 공개 한국어 요약·외부AI·보관/해지 조건 확인, 계정 무료 잔액·전체 운영 실비 확인이 남았다.
- 11/1 전5분 리허설, 다음 개발은 Exa 계약/어댑터와 세 지수 연결이다.
