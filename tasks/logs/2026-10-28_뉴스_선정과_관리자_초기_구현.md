## 기준 설명과 실제 구현

뉴스 사례는 기존 운영 정책의 통과/실패 경계를 합성 12건으로 옮긴 초기 인수 기준이다. 실제 기사 표본의 통계나 모델 평가 결과에서 중요도를 추론한 것은 아니다. 권한·시각→근거→확정 사실/지수 관련성→중복/후속→질적 중요도/영향 범위→편성 한도를 검사한다. 동급은 새 사실 시각 내림차순·안정 ID 오름차순이다. 모든 거시 기사가 기업 기사보다 우선하는 규칙은 두지 않는다.

관련성·중요성·새 사실의 의미 검토는 근거와 함께 입력되어야 한다. 코드가 그 판단을 원문에서 자동 생성한다고 보지 않는다. 합성 자료와 선정 결과는 발행 불가이며 실제 검색 누락/정확도·공개/AI 이용 조건은 별도다.

- 병렬 작업: 뉴스 정책/fixture/회귀, API/OIDC/DB schema, React 목록/상세 UI. 통합 단계에서 사건 claim·버전별 글 유일 키·근거/hash/동결 검사와 실제 API 응답 형식을 교차 검토했다. 상세 조회는 게시글별 허용 근거를 반환하고 화면은 해당 필드를 표시한다. 미연결 알림은 0건 정상으로 표시하지 않는다.
- Python 의존성은 `pyproject.toml`·`uv.lock`, 프론트 의존성은 `frontend/package.json`·lock에 기록한다. 비밀 환경변수는 값 없이 `.env.example`에만 설명한다.
- 기본 API는 DB·HTTPS origin·Google 설정이 없으면 차단한다. 테스트 로그인·운영 키 조회·기존 preview DB 재사용은 하지 않는다. 실제 외부 게시 어댑터/worker는 이번 초기 구현에 연결하지 않는다.
- [OpenAPI](../../contracts/openapi.json)와 Alembic의 8개 업무 저장 단위를 작성하며 세션·멱등 감사는 기존 `operations_events`에 둔다. Alembic 자체 revision 관리표는 업무 저장 단위와 별도다.

## 검증 기록

- 선정 회귀 33건과 관련 Ruff를 통과했다.
- 기존 전체 시험 첫 실행은 기본 Windows temp 디렉터리 권한 때문에 265통과·17 setup 오류였다. `.venv/pytest_tmp`를 `PYTEST_DEBUG_TEMPROOT`로 지정한 재실행에서 314통과했다. 이후 API 시험이 추가되므로 최종 결과는 아래에 추가한다.
- uv 기본 캐시 쓰기와 sandbox DNS 제한을 확인했다. 작업공간 캐시와 승인된 패키지 설치로 Python 의존성/lock 갱신을 완료했다. 로컬 Docker Desktop을 시작해 격리 PostgreSQL 검증을 준비 중이다.

### 최종 결과

- `uv run pytest -q`: **337 passed, 12 skipped**, 42.79초. skip 12건은 `XFOLIO_TEST_DATABASE_URL`이 없는 실제 PostgreSQL migration·상태/경쟁 시험이다. 메모리 또는 SQLite로 통과를 대체하지 않았다.
- `uv run ruff check .`, `uv run ruff format --check .`: 종료 0, Python 158개 파일 형식 확인. `uv run xfolio status`: 종료 0, 초기 API/React와 운영 연결 전 상태로 문구 갱신.
- Google 검증은 로컬 RSA 서명·모의 token/JWKS로 정상, 잘못된 서명·issuer·audience·nonce·만료 거부를 시험했다. 실제 Google 계정 로그인 시험이 아니다. Authlib `jose`의 폐기 예정 경고 1건이 있으며 현재 `<2`로 제한했다.
- `npm run build`: 통과. Vitest **8/8**, Playwright의 실제 로컬 Edge 브라우저 **4/4** 통과. API는 브라우저 안에서 모의했다. 목록→상세 근거·401·409 재조회·응답 불명 시 동일 키/본문을 확인했다. PNG를 직접 확인해 한글·근거·승인 패널 배치를 점검했다.
- OpenAPI export와 기존 8개 경로 일치 검사 통과. Alembic 오프라인 SQL 생성 통과. 처음에는 명시 URL이 없어 차단됐으며, 무접속 오프라인 URL을 현재 명령에 지정해 재검증했다. PostgreSQL 8개 업무 테이블·활성 사건 유일 키·콘텐츠 변경 방지 trigger를 포함한다.
- FastAPI TestClient의 이벤트 루프 생성이 Windows sandbox의 socketpair 제한에 걸려 해당 검증을 승인된 실행으로 수행했다. 제한된 상태에서 멈춘 시험 프로세스는 종료했다.
- 로컬 Docker 엔진은 백그라운드 시작 뒤에도 응답하지 않아 DB 컨테이너 생성·실제 migration/경쟁 시험을 수행하지 못했다. 대기하던 상태 확인 명령은 중단했다. 실제 서비스 DB에는 접속하지 않았다.
- GitHub Actions 정의에 격리 PostgreSQL 서비스와 Python/Ruff/OpenAPI·프론트 build/Vitest/Chromium Playwright 검사를 추가했다. 원격 CI는 아직 실행하지 않았다.
- 새 의존성·실행·환경변수·실제/모의 경계는 루트와 frontend README, `.env.example`, 기술 구성/작업 목차에 반영했다. 문서 UTF-8/BOM·상대 링크·JSON·`git diff --check`를 확인했다.

## 남은 범위

Google 실제 로그인·권한 확인 실자료 정상 E2E·실제 운영 PostgreSQL/DB 역할·뉴스 의미 추출/생성 연결·CLI 새 버전 수정·예약 worker/X/Telegram·AWS 배포는 별도 후속이다. 초기 코드와 모의 시험을 이들 기능의 운영 완료로 표시하지 않는다. 기획을 구현 코드에 맞춰 완화하지 않고 미구현 조건을 남긴다.
