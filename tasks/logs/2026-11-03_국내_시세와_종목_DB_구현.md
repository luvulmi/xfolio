## Docker 알림과 시험 DB

Docker Desktop을 T02 DB 시험용으로 시작하면서 `dockerInference` 런타임 소켓 정리 실패 알림이 발생했다. 사용자에게 시작 경위와 [공식 동일 증상 보고](https://github.com/docker/desktop-feedback/issues/625)를 설명했다. Docker 설정/데이터를 임의 초기화하거나 진단을 업로드하지 않았다. 사용자가 재기동한 뒤 Docker 엔진28.5.2·기존 `learning-hub-db` 실행 상태를 읽기 확인했다.

저장소에 있던 `.cache/postgres-portable`·격리 시험 cluster를 재사용해 loopback55432의 전용 시험 DB에서 검증했다. 접속 비밀은 메모리 주입/출력 가림 처리했고 `.env`·운영 DB·기존 Docker 컨테이너를 사용하지 않았다. 각 시험의 무작위 schema만 생성/삭제했다. 데이터베이스 서비스가 정상이어야 실행되는 시험을 SQLite/DDL 문자열 검사로 대신하지 않았다.

## 계산·시각·사건 경계

실표본 원종가의 Decimal 표시율 -1.36/-2.56/+0.20%를 새 모델로 재생했다. 날짜만 제공하는 일봉의 실제 가격시각은 null이고 예정 마감/조회시각을 구분한다. 기준 종가와 공급자 직접 차액이 일치하고 T01 필드 패턴이 맞는 경우에만 숫자 비교를 자동 채택하며 사건 enum을 해독한 것으로 기록하지 않는다. 분배금 미포함 가격 변동률이며 분배락/분할/미확인 조건은 별도 근거 또는 보류로 처리한다. 실제 사건일·오후 정시·운영 worker 수신을 새로 확인한 것은 아니다.

seed의 기본3종목 마스터 조회시각은11/1 원래 관측시각으로 보존한다. 재시작/재seed 시각을 새 조회시각으로 만들지 않고 이후 실제 갱신한 마스터 정보를 이전 seed로 덮어쓰지 않는다.
