## 외부 호출 없는 재현

실제 예약과 같은 Windows PowerShell 5.1에서 `$ErrorActionPreference='Stop'`와 `& python fixture.py *> log`를 사용했다. fixture는 socket 연결을 차단한 뒤 `local_calendar()`를 호출하고 후속 완료 표시를 남기는 작은 프로그램이다. 달력 생성은 `pandas_market_calendars/market_calendar.py:145`에서 `break_start`·`break_end` 지원 종료 경고를 stderr에 출력한다.

기존 실행 방식에서는 이 정상 경고가 `NativeCommandError`로 변환돼 PowerShell 종료 코드1, Python의 후속 완료 표시 없음으로 재현됐다. 당일 DB의 거래일 확인 이후 시세 수집 전 중단 위치와 일치한다. 당일 stderr 원본은 남지 않았으므로 역사적 예외 원문을 직접 복원한 것은 아니다. 재현용 원본은 Git 제외 `.cache/local_runtime/offline_failure/`에 보존했다.

## 수정

- `scripts/dev/native_process.ps1`에서 숨김 `Start-Process`로 Python을 실행하고 stdout/stderr를 각각 파일로 저장한다. native stderr를 PowerShell 오류 파이프라인으로 전달하지 않으며 완료를 기다리고 실제 종료 코드를 반환한다. UTF-8·무버퍼로 실행한다.
- `run_local_phase.ps1`은 기존 날짜·시각 제한을 유지하고 위 helper를 사용한다. 시작 실패도 비밀 없는 고정 코드로 저장한다.
- `local_runtime.py`는 phase 시작·종료·예상 밖 실패를 즉시 flush한다. `jobs/collection.py`는 claim부터 설정·달력·시세·뉴스·편성·outbox·완료까지 단계와 시각을 기록한다.
- `jobs/diagnostics.py`는 예외 종류와 최대8개 파일명/함수/줄 번호만 기록한다. 원문 예외·소스 줄·locals·키·메일·chat ID·DB URL은 기록하지 않는다. 로컬 stderr의 경고도 내용 대신 종류·위치만 남긴다.
- 준비 예외는 안전한 진단과 완료 시각을 기존 `operations_events` payload에 남긴다. claim 실패도 단계 로그에 남기며 외부 호출을 시작하지 않는다. migration은 추가하지 않았다.
- worker 결과 `failed`·`unknown`·`retryable_failure`는 종료 코드1이다. 업무 실패가 Windows에서 성공 코드0으로 보이던 문제를 수정했다. `ready`·준비 `partial`·정책상 `skipped`는0이다.
