# 5주차 발표 대본 · 5분 기준

- 발표: **2026-11-08(일)** · 성과·갱신 기준: **2026-11-05, Asia/Seoul**
- 화면: [5주차 아침 뉴스레터 구현](5주차_개인용_뉴스레터_전환.md)
- 기존 4주차 형식에 맞춘 5분 초안이다. 실제 리허설은 미실행이며 11/6 정시 관측 결과는 아직 반영하지 않았다.

## 0:00~0:40 · 01 서비스와 현재 범위

XFolio는 제가 관심 있는 국내 상장 해외 ETF와 미국 주요 뉴스를 한국 거래일 아침 8시에 Telegram으로 받는 개인 뉴스레터입니다. 공개 게시에서 본인이 실제로 사용할 수 있는 범위로 정리했고, 이번 주에는 가격과 뉴스 수집부터 관리자 설정, 전송까지 연결했습니다.

기본 종목은 S&P500, 나스닥100, 미국배당다우존스 ETF 세 개이고 활성 종목은 총 열 개까지입니다. 가격은 최근 완료 한국 거래일의 원화 종가이며 뉴스는 전체 최대 세 건입니다. 한국 휴장 평일과 주말에는 가격과 뉴스 모두 보내지 않고, 오후 알림은 기본 꺼짐입니다.

## 0:40~1:30 · 02 이번 주 연결한 흐름

그림의 왼쪽은 입력입니다. KIS에서 가격을 받고 Finnhub와 공식 기관에서 뉴스를 수집합니다. 가운데 worker가 거래일과 설정을 확인하고 자료를 검사해 아침 뉴스레터로 저장합니다. 발송 대기열에는 보낼 내용과 처리 상태가 남습니다.

7시 50분에 종목과 설정을 고정하고 수집을 시작해 7시 58분 편성 완료를 목표로 합니다. 8시에 중지 여부와 예산, 마감 조건을 다시 확인하고 Telegram으로 보냅니다. 8시 10분을 넘기면 새 송신을 하지 않습니다.

화면은 React, API는 FastAPI, 공통 저장은 PostgreSQL입니다. 예약과 전송은 별도 Python worker가 맡아 관리자 화면과 실행을 분리했습니다. 이번 주에는 이 흐름의 구현과 격리 시험을 마쳤습니다.

## 1:30~2:15 · 03 뉴스 선정과 AI 역할

일반 뉴스는 Finnhub에서 허용된 매체의 제목과 직접 기사 링크만 사용합니다. 일반 기사 본문은 수집하거나 AI에 넣지 않습니다. BLS CPI, BEA GDP와 PCE, Federal Reserve Board FOMC 같은 자체 공식 발표는 직접 수집한 사실을 AI로 요약합니다.

중요도는 AI 판단이 아니라 제목 키워드 규칙입니다. 시스템 위험과 통화정책, 물가와 고용처럼 시장 전반에 관련된 소식을 우선하고 같은 사건과 이미 보낸 기사를 제외합니다. 공식 자료의 요약은 출처와 수치, 기간, 비교기준을 코드로 다시 대조합니다.

이 점수는 실제 주가 영향이나 투자 수익의 예측값이 아닙니다. 적격 뉴스가 없으면 영 건도 정상이고, 수집 실패와는 따로 표시합니다.

## 2:15~2:50 · 04 관리자

관리자는 대시보드, 뉴스레터, 발송 이력, 관심 종목, 알림 설정의 다섯 메뉴입니다. 종목과 순서를 바꾸고 발송을 중지하거나 편성 내용과 결과를 확인합니다. 대시보드의 가격 최신 여부, 뉴스 장애, 준비와 발송 상태, 비용 원장은 실제 DB와 연결했습니다.

매번 사람이 승인하는 방식은 아닙니다. 설정과 자동 검사를 기준으로 실행하고 결과를 확인합니다. 다만 실제 Google 계정 로그인 완료와 AWS에서의 휴대폰 접근은 아직 확인할 단계로 남아 있습니다.

## 2:50~3:50 · 05 검증 결과와 남은 경계

최신 전체 회귀 기록은 Python 천사십 건, UI 스무 건 통과이고 빌드와 브라우저 시험도 통과했습니다. 열 종목 편성과 열한 번째 활성화 거절, 휴장, 중지, 동시 실행과 재시작, 부분 성공과 결과 불명 같은 경계를 시험했습니다. 이 코드 시험의 외부 API는 대역입니다.

실제 통신은 따로 확인했습니다. KIS 세 종목 가격을 수집해 저장했고 뉴스 네 출처도 조회했습니다. 당시 적격 뉴스는 정상 영 건이었습니다. BLS 공식 CPI 자료로 유료 요약 한 번을 실행해 수치와 근거 두 건을 대조했습니다. Telegram에는 시험 표시 메시지를 한 번 보내 API 수락을 확인했습니다.

여기까지가 11월 5일 기준입니다. 가격과 뉴스를 담은 실제 아침 뉴스레터의 정시 수신은 11월 6일 관측 예정입니다. 시험 메시지 성공만으로 정시 운영까지 완료했다고 판단하지 않았습니다.

## 3:50~4:20 · 06 구현에서 배운 점

가장 중요했던 부분은 같은 작업이 반복되어도 중복 요약이나 중복 발송을 하지 않게 만드는 것이었습니다. DB에서 실행을 먼저 점유하고 전송 상태와 비용을 남겼으며, 전송 결과를 모르면 자동으로 다시 보내지 않도록 했습니다.

또 뉴스가 없다는 것과 수집이 실패했다는 것을 구분해야 했습니다. 공통 계약을 먼저 정하고 관리자와 worker 등을 병렬 구현한 뒤, API부터 전송 이력까지 통합 시험으로 확인했습니다.

## 4:20~5:00 · 07 다음 단계와 비용

다음은 실제 한국 거래일 7시 50분 수집부터 8시 Telegram 단말 수신까지 로그와 DB를 대조하는 것입니다. 이후 AWS Lightsail과 Tailscale Serve로 비공개 운영 환경을 만들고, PC와 휴대폰 접근, 백업과 복원, 만료 자료 삭제를 확인합니다. 오후 선택 알림은 실제 시세 시각을 검증한 뒤 인수합니다.

최종 발표와 전체 완료 목표는 11월 29일입니다. 남은 작업의 기존 기준은 에이전트와 사용자 작업을 합쳐 13.75시간이며 새로 실측한 잔여 견적은 아닙니다. 정시 대기는 별도입니다. 월 예산 목표는 5만 원 이내이고 새 구성의 전체 운영비는 배포 단계에서 다시 계산할 예정입니다.

## 선택 시연 · 본문 발표에 포함하면 04·05절 설명을 줄이기

아래는 이미 실행한 검증을 보여주는 순서다. 실제 시연은 로그인과 자료 상태를 먼저 확인한 뒤 진행한다. 11/5 현재 실제 Google 로그인 완료는 미관측이다.

| 순서 | 화면에서 짚을 내용 | 설명 |
| --- | --- | --- |
| 1 | 대시보드 | 가격 기준일·조회시각, 정상 뉴스 0건과 장애 상태의 차이 |
| 2 | 관심 종목 | 기본 3종목과 활성 한도 10개, 순서 설정 기능 |
| 3 | 뉴스레터·발송 이력 | 존재하는 자료만 표시하고 실제/모의·성공/불명을 구분 |
| 4 | 흐름도·검증 표 | 관리자 화면에서 보이지 않는 worker/DB 경계와 정시 관측의 남은 조건 |

실제 자료에 편성이나 발송 이력이 없으면 미실행 상태 그대로 설명한다. 로그인·원자료가 준비되지 않았으면 Markdown의 흐름도와 검증 표로 진행한다. 화면 공유에서는 이메일·개인 채팅 식별자·비밀 설정·DB 자격정보를 가린다.
