# 3주차 발표 대본 | XFolio 기술 스택과 월 비용

- 발표 주차: 2026-10-19~10-25 · 갱신일: 2026-10-25
- 화면 자료: [3주차 기술 조사](3주차_기술_조사.md)
- 예상 시간: 약 3분. *기울임꼴은 발표 동작이며 읽지 않는다.*

## ❶ 어떤 XFolio인가 · 약 40초

*첫 표를 보여준다.*

XFolio는 미국 시장에서 확인된 중요한 변화를 한국어로 정리해 X에 게시하는 에이전트입니다. 아침에는 S&P 500과 Nasdaq-100의 종가와 등락률을 한 글로 묶고, 두 지수 관련 중요 뉴스가 있으면 원문 링크를 단 글을 최대 두 개 더합니다. 이후에는 Marketaux를 정기 감시해 새로 나온 중요 뉴스만 하루 최대 두 건 추가합니다. 적격 뉴스가 없으면 채우지 않습니다. 관리자 화면에서는 후보와 근거·초안을 검토하고 승인·게시 결과를 확인할 계획입니다.

## ❷ 기술 스택과 뉴스 흐름 · 약 1분 20초

*세로 다이어그램을 위에서 아래로 짚는다.*

Cloud Scheduler와 Cloud Run Jobs가 Python 작업을 예약 실행하는 구성이 목표입니다. Market Pipeline은 `yfinance`로 두 지수 종가를 가져옵니다. News Pipeline은 `httpx`와 **Marketaux 한 곳**으로 두 지수와 관련된 뉴스를 아침과 이후 정기 감시에서 조회합니다. 같은 사건을 묶고 관련성·중요도·근거를 확인해 아침 두 건, 추가 하루 두 건까지만 고릅니다. BLS와 SEC를 직접 수집하는 방법도 조사했지만, 첫 제품의 뉴스 흐름은 Marketaux로 단순화했습니다.

OpenAI Python SDK의 Responses API와 `gpt-6-luna`는 관련성 판단과 한국어 초안을 맡습니다. Pydantic으로 응답 형식을 고정하고 Python이 사실·시각·중복·길이·예산을 다시 검사합니다. 모델에 게시 권한은 주지 않습니다. Neon PostgreSQL과 Streamlit 관리자 화면은 가상 초안의 저장·로그인까지 확인했고, 실제 승인·예약·X 게시는 아직 연결 전입니다.

## ❸ 비용과 남은 조건 · 약 1분

*비용 표를 가리킨다.*

월 예산 상한은 **5만 원으로 확정**했습니다. 월 22일 동안 매일 최대 다섯 글을 쓴다고 가정하면 X API 게시·조회가 **18.48달러**, Luna는 가정한 후보량에서 약 **0.18달러**입니다. X 자동 게시가 주요 비용입니다. 기존 예약안의 Cloud Run 작업 3,418회가 각각 1분이면 전체 약 **3만 4천 원**, 모두 2분이면 **3만 9천 원**, 모두 3분이면 **4만 7천 원**입니다. 작업 시간은 작업 하나의 컨테이너가 시작해 종료할 때까지입니다. 실제 측정값은 아닙니다.

가장 큰 조건은 Marketaux입니다. Free는 하루 100요청·요청당 기사 3건인데, 이전의 넓은 아침 검색은 아침만 138페이지가 필요하다는 추산이 나왔습니다. 고정 기업 질의를 없애도 두 지수 관련 기사를 무료 범위에서 충분히 찾을 수 있는지는 아직 모릅니다. 월 29달러 Basic은 구독료만 약 5만 3천 원이어서 이번 예산에는 맞지 않습니다. 기사 근거의 충분성과 한국어 X 공개·외부 AI 처리의 이용 범위도 확인해야 합니다.

다음에는 두 지수 관련 질의와 정기 감시의 실제 요청량·기사 근거를 확인하고, 이용 조건을 검토한 뒤 최대 다섯 글의 미리보기와 실제 사용량을 시험하겠습니다.

## 예상 질문과 답변 · 발표 후 참고

**Q. 왜 Python과 Google Cloud로 자동화하고 OpenAI 에이전트에 전부 맡기지 않나요?**

A. OpenAI를 쓰지 않는 것이 아닙니다. Luna는 중요도 판단과 한국어 초안을 맡고, Python은 수집 순서·중복·예산·승인·X 게시 조건을 확정적으로 검사합니다. OpenAI Agents API에도 [예약 자동화](https://developers.openai.com/api/docs/guides/agents-api/sessions/automations)가 있지만, 첫 버전은 처리 순서가 정해져 있어 고정 워크플로가 단순합니다. Google Cloud 예약·실행은 아직 배포 전인 목표 구성입니다.

**Q. Cloud Scheduler와 Cloud Run Jobs는 각각 무엇을 하나요?**

A. [Cloud Scheduler](https://cloud.google.com/scheduler/docs/overview)는 정해진 시각에 실행을 요청하는 알람이고, [Cloud Run Jobs](https://cloud.google.com/run/docs/create-jobs)는 그때 Python 작업을 실행한 뒤 종료하는 작업자입니다. 계속 켜 두는 서버가 아니며, 작업 시간이란 실행 한 번의 시작부터 종료까지입니다. 중복 실행 가능성에 대비해 게시 여부는 DB에서 다시 확인해야 합니다.

**Q. 왜 분석·생성 모델로 Luna를 골랐나요?**

A. 같은 가상 뉴스 6건에서 Luna와 Mini 모두 기계 검사를 6건 통과했고, 실제 API 사용료는 Luna **$0.0005432**, Mini **$0.0051210**으로 Luna가 약 9배 저렴했습니다. [공식 토큰 단가](https://developers.openai.com/api/docs/models/gpt-6-luna)도 낮아 월 5만 원 예산에 유리합니다. 다만 이 결과는 짧은 가상 표본이므로 Marketaux 실기사의 사실·한국어 품질은 별도로 검증합니다. [모델 비교 기록](../../docs/research/OpenAI_활용.md)

**Q. 뉴스는 어디서 가져오나요? BLS·SEC는요?**

A. 현재 첫 제품의 뉴스 후보는 Marketaux 한 곳에서 조회합니다. BLS CPI 파서와 SEC 공시 비교는 이전 기술 시험으로 남기지만 필수 수집 경로에는 넣지 않습니다. Marketaux가 운영에 충분하다는 판정은 아직 전입니다.

**Q. 왜 뉴스를 최대치만큼 꼭 게시하지 않나요?**

A. 중요도와 근거를 통과한 서로 다른 사건만 게시하기 때문입니다. 정상적으로 조회했는데 적격 뉴스가 한 건이면 한 건만 쓰고, 없으면 아침에는 지수 글만 게시합니다.

**Q. 기업 뉴스는 아예 제외하나요?**

A. 아닙니다. 특정 5개 회사를 따로 감시하는 제한만 없앴습니다. 구성기업의 실적·사업 변화라도 두 지수와의 연결과 중요성을 근거로 설명할 수 있으면 같은 뉴스 흐름의 후보가 됩니다. 단순히 지수 구성기업이라는 이유만으로 게시하지 않습니다.

**Q. 두 지수 관련 뉴스는 어떻게 찾고 중요도를 판단하나요?**

A. Marketaux의 지수·엔터티 필터와 검색어를 표본 비교해 후보를 찾고, 발표·결정의 확정성, 두 지수와의 연결, 영향 범위, 새 사실과 원문 근거로 고릅니다. 실제 API에서 지수 심볼이 어떤 기사에 붙는지는 아직 검증 전이므로 필터만 믿고 누락이 없다고 주장하지 않습니다. 이미 아침에 게시한 사건은 이후 감시에서 다시 올리지 않습니다.

**Q. 5만 원으로 정말 되나요?**

A. 표는 Free 뉴스 API, 월 22일, 매일 최대 다섯 글, 기존 예약 횟수, 정해진 환산율에 따른 조건부 계산입니다. 3분 작업 가정은 예비비가 약 3천 원뿐이고, Free가 조회량을 감당하는지도 확인되지 않았습니다. 안 되면 게시 범위나 예산을 다시 정해야 합니다.

**Q. Luna를 확정했는데 실기사 요약 품질은 검증했나요?**

A. 가상 여섯 건의 형식·기계 검사를 통과했습니다. Marketaux 실기사에서 사실과 한국어 표현을 충분히 검증한 것은 아니므로 실패 문안은 게시하지 않습니다.

**Q. X 웹사이트에서 수동으로 쓰는 비용도 포함되나요?**

A. 아닙니다. 이 비용은 X API로 자동 게시하고 게시 결과를 확인하는 가정입니다.
