# 4주차 발표 대본 · 5분 기준

- 발표: 2026-11-01 / 갱신: 2026-10-30, Asia/Seoul
- 화면: [4주차 개발 계획](4주차_개발_계획.md). 표 전체를 읽지 않고 각 절의 굵은 문장과 그림을 짚는다. 실제 리허설은 미실행이다.

## 0:00~0:40 · 01 서비스 기획

XFolio는 미국 시장의 전일 마감과 주요 뉴스를 한국어로 전달하는 개인 프로젝트입니다. 아침 8시에 SPY, QQQ, DIA 세 ETF의 종가와 등락률을 묶은 한 글, 주요 뉴스 최대 세 글을 게시합니다. 오후 게시를 없애고 아침 한 번에 집중하도록 바꿨습니다. 뉴스는 적격한 사건만 넣고 없으면 ETF만 게시합니다. ETF 가격은 달러 기준이며 지수 포인트와 구분합니다.

## 0:40~1:15 · 02 서비스 흐름

그림은 수집, 초안과 검사, 운영자 승인, 예약 게시의 네 단계입니다. AI가 한국어 초안을 만들고 코드는 수치와 길이, 중복을 검사합니다. 운영자는 원문과 초안을 비교해 정확한 버전을 승인합니다. 7시 30분까지 근거를 확보하고 7시 45분 검토 준비, 7시 55분 승인, 8시 전송을 목표로 합니다. 9시부터는 새 전송을 하지 않습니다.

## 1:15~2:35 · 03 기술스택

화면은 React와 TypeScript를 쓰고 Vite로 빌드합니다. TanStack Query는 조회 상태와 승인 후 재조회를 맡습니다. API는 FastAPI와 Pydantic으로 요청 형식을 검사하고, Google OIDC와 Authlib로 운영자를 확인합니다.

데이터 수집은 Python입니다. yfinance가 ETF 가격을 가져오고 거래소 달력으로 완료 거래일을 판단합니다. Exa가 뉴스와 본문 근거를 찾고 기존 BLS CPI 파서를 연결합니다. OpenAI SDK와 Responses API로 Luna의 구조화 초안을 받습니다. 숫자 계산과 사실 확인은 AI 출력과 별도로 처리합니다.

PostgreSQL에는 근거, 초안 버전, 승인과 발행 결과를 함께 저장합니다. SQLAlchemy Core와 psycopg로 접근하고 Alembic으로 스키마 변경을 관리합니다.

기술 구조 그림의 위쪽은 수집과 게시를 맡는 worker, 아래쪽은 운영자의 검토 화면과 API입니다. 둘은 같은 DB에서 승인 버전을 확인합니다. worker는 APScheduler를 쓸 예정이며 아직 구현 전입니다. 운영 배포는 Docker Compose, Lightsail, Caddy를 계획하고 X와 Telegram 연결도 후속으로 진행합니다.

## 2:35~3:25 · 04 개발 일정

5주차는 Exa와 ETF 입력, 6주차는 근거 검사와 아침 초안입니다. 7주차는 관리자 승인과 worker, 8주차는 모의 전송과 통합 시연입니다. 앞의 두 주 30시간은 확정이고 뒤의 두 주는 30시간을 가정합니다.

오후 편성 작업을 빼고, 기존 아침 최대 세 글 제한을 네 글로 바꾸는 API와 DB 제약 점검을 더했습니다. 핵심 56시간과 여유 4시간으로 총 60시간입니다. 11월 15일에 실제 남은 양을 다시 계산하겠습니다.

## 3:25~4:10 · 05 현재 성과

현재 두 지수 조회, React 검토와 승인, API 여덟 개와 DB 여덟 테이블, 로컬 Google 로그인을 확인했습니다. BLS의 제한된 수치 검사와 Exa 표본도 있습니다. ETF 전환과 Exa 제품 어댑터, 네 글 승인, worker는 이어서 구현해야 합니다.

10월 29일 시험 기록은 Python 419건, UI 10건, Playwright 2건입니다. 당시 조건의 결과이고 실제 X 게시나 새 편성의 성공을 뜻하지 않습니다. 로그인 callback과 HTTPS 문제를 해결했고, AI의 형식 검사만으로 사실을 보증할 수 없어 사람의 의미 확인을 나눴습니다.

## 4:10~5:00 · 06 비용·준비

월 22일에 최대 네 글을 올리면 X 게시와 확인 비용은 13.97달러입니다. AI, 1GB 서버, 예비액을 더한 부분 견적은 약 4만 5천9백 원입니다. 무료 조건과 ETF 글에 URL이 없다는 가정이며 도메인과 백업 비용도 확인해야 합니다.

계정과 API 키 준비는 일부 확인했지만 공개 이용 조건과 실제 연결은 별개입니다. 발표 전에는 5분 리허설을 하고, 차주에는 Exa와 ETF의 입력 계약부터 구현에 연결하겠습니다.

## 예상 질문

| 질문 | 답변 요점 |
| --- | --- |
| API와 worker를 왜 나누나요? | API는 로그인·조회·승인에 응답하고 worker는 오래 걸리는 수집·AI·예약을 수행한다. 공통 DB에서 정확한 승인 버전을 읽는다. |
| APScheduler만으로 중복을 막나요? | 스케줄 시작만 맡는다. DB 사건 키·원자적 점유·비용/한도 예약이 중복 발행을 차단한다. |
| 왜 PostgreSQL인가요? | API와 worker가 버전·승인·발행 상태를 공유하고 경쟁 요청을 트랜잭션으로 처리하기 위해서다. |
| 3글에서 4글은 숫자만 바꾸면 되나요? | store의 AM 한도와 DB reserved_count 제약, 편성·UI·worker를 함께 바꾸고 4글 허용/5글 거절·동시 승인을 시험해야 한다. |
| 오후 기능은 지우나요? | 새 PM 생성·승인·전송은 차단한다. 기존 CPI 시험과 PM 이력은 보존한다. |
| ETF 등락률은 배당 포함인가요? | Close 가격 등락률이다. 배당 재투자 총수익률과 구분하며 배당락·분할·수정치의 기준을 확인한다. |
| 공개 게시 권한은 확인됐나요? | 개발 채택·표본과 공개 허가는 별개다. ETF·요약·출처 표기만으로 허가를 단정하지 않는다. |
| 운영비가 5만 원 안에 확정됐나요? | 1GB·무료 잔액·ETF URL 없음의 부분 견적이다. ETF URL 포함이면 약 53,985원이며 실제 부대비용도 확인해야 한다. |
