## ❶ 확정한 기획안

### 만들 서비스의 큰 그림

**미국 시장의 지수와 공식 자료를 모아, 운영자가 근거를 확인한 한국어 브리핑을 X에 게시합니다.**

```mermaid
flowchart LR
    A["세 지수 · 공식 발표/공시"] --> B["근거 저장 · AI 초안"]
    B --> C["관리자 검토 · 승인"]
    C --> D["예약 게시"]
    D --> E["발행 결과 · 오류 확인"]
```

- **독자에게:** 아침 08시 세 지수 1글 + 중요 뉴스 최대 2글. 후속으로 18시 새 뉴스 최대 2글.
- **운영자에게:** 대시보드에서 상태 확인 → 원문과 초안 비교·승인 → 발행 내역 확인.
- **운영 기준:** 하루 최대 5글·월 5만 원. 정상 수집 후 뉴스가 없으면 생략하고, 수집 실패는 보류.

### 미결정이었던 내용은 이렇게 정했습니다

| 결정할 주제 | 확정한 내용 | 선택 이유 |
| --- | --- | --- |
| 지수 범위 | S&P 500 · Nasdaq-100 · **다우 포함 3개** | 세 지수의 종가·등락률을 한 글로 전달 |
| 뉴스 수집처 | **Fed·BLS·BEA·SEC 유지** | 공식 발표와 공시의 근거를 직접 확인 |
| 첫 지원 자료 | **FOMC 성명·CPI·PCE·8-K 실적/인수합병** | 처음 구현하고 검증할 자료를 구체화 |
| SEC 기업 | **업종 분산 10기업으로 고정** | 기술 분야에 금융·헬스케어·에너지 추가, 20기업 확장은 삭제 |
| 첫 완료 목표 | **아침 브리핑 → 승인 → 모의 전송** | 입력부터 결과 확인까지 하나의 흐름을 먼저 검증 |

**SEC 10기업:** NVIDIA · Apple · Microsoft · Amazon · Alphabet · Meta · Tesla · JPMorgan Chase · Johnson & Johnson · ExxonMobil.

기업 구성은 확정했습니다. 공식 법인명·CIK·공시 표본·감시 시작일은 개발 착수 때 대조합니다. 고용·GDP·해외기업 공시·복잡한 표/PDF는 후속 범위입니다.

### 구체적으로 개발할 기능과 기술

| 개발할 기능 | 사용할 기술 |
| --- | --- |
| 대시보드·콘텐츠 검토·발행 내역 **3개 메뉴** | React · TypeScript |
| 로그인·승인·결과 조회 API | FastAPI |
| 원문 근거·초안 버전·승인·발행 이력 저장 | 기존 Neon PostgreSQL |
| 수집·수치 검사·AI 초안·예약 실행 | Python worker · OpenAI Luna |

기존 API 8개와 DB 8개 테이블을 재사용하고 필요한 계약을 확장합니다. 발행 목록·상세 API 2개를 추가해 **1단계 API는 총 10개**를 목표로 합니다.

**후속 운영 개발:** 실제 X 게시, 18시 편성, Telegram 알림, Docker·AWS Lightsail 배포. DB는 기존 Neon을 유지합니다.

## ❷ 개발 일정과 주차별 완료 기준

**5~6주차는 각 15시간 확정. 7~8주차는 각 15시간을 가정합니다.**

### 5주차 · 11/2~11/8 — 입력 기반 만들기 · 15h

1. **공통 입력·계약 대조 · 5h:** 출처·발표/확보 시각·원문 버전·수집 상태를 정의하고 기존 API·DB와 연결할 필드를 대조합니다.
2. **BLS·Fed 연결 · 6h:** 기존 CPI 파서를 공통 입력에 맞추고, FOMC 성명에서 정책 결정과 금리 범위를 추출합니다.
3. **다우 추가 · 3h:** 기존 두 지수에 `^DJI`를 추가하고 거래일·누락·세 지수 한 글 길이를 검사합니다.
4. **기업 목록 설정 · 1h:** 확정 10기업의 공식 법인명·CIK·티커·감시 시작일을 대조하고 목록 버전을 저장합니다.

**주차 말 결과:** BLS·Fed와 세 지수를 공통 형식으로 조회하고, 정상 0건·수집 실패·지수 누락을 구분하는 시험 결과.

### 6주차 · 11/9~11/15 — BEA·SEC 수집과 아침 편성 착수 · 15h

1. **BEA PCE 수집 · 4h:** 대상 기간·전월/전년비·개정 여부와 원문 근거를 추출합니다.
2. **SEC 10기업 수집 · 7h:** CIK별 공시를 발견하고 8-K 실적·인수합병의 관련 문단·첨부를 연결합니다. 10기업 전체 조회·누락·중복을 검사합니다.
3. **아침 편성 착수 · 4h:** 세 지수 1글과 뉴스 0~2글을 만드는 입력·초안·검증·저장 경로를 연결합니다. 나머지 2h는 7주차에 이어갑니다.

**주차 말 결과:** 4기관의 지원 자료·근거와 아침 편성의 중간 결과. **11/15에 실제 지원 범위와 잔여 작업량을 재산정**합니다.

### 7주차 · 11/16~11/22 — 관리자 승인과 예약 연결 · 15h 가정

1. **아침 편성 마무리 · 2h:** 근거·길이·부분 수집 검사를 마무리하고 저장된 버전을 승인 대상으로 연결합니다.
2. **화면·조회 API · 7h:** 관리자 3개 메뉴를 연결하고 발행 목록·상세 **조회 API 2개**를 추가합니다. 모의 결과·실제 결과·결과 불명을 구분해 표시합니다.
3. **아침 worker · 3h:** 승인 버전·게시 시각·중복 점유를 확인하고 재시작 후 상태를 복구합니다.
4. **결함 수정 · 3h:** 연결 과정에서 발견한 오류를 수정하고 관련 시험을 실행합니다.

**주차 말 결과:** 브라우저에서 원문과 초안을 대조해 승인하고, worker가 정확한 승인 버전을 예약 처리하는 흐름. 발행 조회는 시험 자료로 확인한 뒤 8주차 전송 결과와 연결합니다.

### 8주차 · 11/23~11/29 — 모의 전송·통합 검증·발표 · 15h 가정

- **11/23~24 · 8h:** 모의 전송과 글별 결과 기록 5h + 통합 검증 착수 1h + 추가 여유 2h.
- **11/25~29 · 7h:** 통합 검증 마무리 3h + 회귀 검사·결함 수정·실행 안내·최종 발표 4h.

**주차 말 결과:** 실제 로컬 DB·API·브라우저와 모의 송신을 연결해 정상·중복 차단·부분 성공·결과 불명을 시연합니다. **11/24 기능 동결은 제안**이며, 후반은 검증과 발표에 집중합니다.

총 60h 가정에 **핵심 58h + 추가 여유 2h**를 배치했습니다. 후속 운영까지 포함하면 기준 78h이므로 실제 게시·배포 일정은 핵심 완료 후 조정합니다. [작업별 시간·의존성·완료 조건](../../docs/planning/작업_분해_WBS.md)

10/29 기록: **pytest 419건 · UI 10건 · Playwright 2건 통과**. 당시 구현과 모의 조건의 결과이며, 전체 제품 완료나 이번 문서 작업에서 재실행한 결과는 아닙니다.

**차주 첫 작업:** 공통 입력 계약 → BLS 재사용·Fed 연결 → 다우·10기업 설정. 위 5주차 계획으로 이어갑니다.
