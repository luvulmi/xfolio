# 1주차 발표 메모 · Codex 개발 환경 세팅

- 발표일: 2026-10-11

> **발표 흐름:** 프로젝트 골격 → `docs/` → `AGENTS.md` → `.codex/`
> **발표 시간:** 약 1분 30초

## 1. 프로젝트 골격을 먼저 구성

이번 주에는 Codex가 파일을 어디에 만들고 무엇을 기준으로 작업할지 정했습니다. Python 3.12와 `uv`를 사용하고, `pyproject.toml`과 `uv.lock`은 루트에 두었습니다.

- `src/xfolio/`: 애플리케이션 코드
- `tests/`: 기능 테스트
- `dashboard/`: 대시보드 코드
- `docs/`: 지속해서 참고할 프로젝트 문서
- `tasks/`: 작업 계획과 날짜별 진행 기록

현재 파이프라인 코드는 **역할을 표시하는 골격**입니다. 수집·분석·게시는 아직 구현하지 않았습니다.

## 2. `docs/`에 작업 기준 정리

- [프로젝트 개요](../../docs/프로젝트_개요.md): 프로젝트 목표와 범위
- [스터디 일정](../../docs/스터디_일정.md): 주차별 작업과 발표 주제
- [기술 구성](../../docs/기술_구성.md): 폴더 구조, 기술 선택, 남은 결정 사항

이 문서들을 먼저 정리해 **확정된 내용과 설계 초안**을 구분했습니다. Codex도 이 구분을 따르도록 했습니다.

## 3. `AGENTS.md`에 Codex 지침 작성

문서를 바탕으로 Codex가 이 저장소에서 지킬 규칙을 적었습니다.

- **소통:** 진행 상황과 답변은 한국어로 작성
- **작업 위치:** 코드·문서·테스트를 정해진 폴더에 작성
- **검증:** `uv` 명령으로 확인하고 변경 후 결과를 보고
- **안전:** 비밀 키는 Git에 넣지 않고, 실제 X 게시와 Git 커밋은 명시적 요청이 있을 때만 실행

## 4. `.codex/`에 실행 권한 설정

`.codex/config.toml`에는 저장소 안에서 작업할 수 있는 `workspace-write`와 요청 시 승인 설정을 넣었습니다.

`.codex/rules/xfolio.rules`에는 자주 쓰는 **`ruff` 검사와 `pytest` 실행은 허용**하고, **`git commit`과 `git push`는 승인 절차를 거치도록** 설정했습니다.

## 마무리

프로젝트 문서를 기준으로 `AGENTS.md`와 룰 파일을 연결한 것이 제 1주차 Codex 환경 설정입니다. 다음 주에는 미정인 요구사항을 구체화하겠습니다.
