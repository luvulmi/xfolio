## 현재 실제 사용

현재는 OpenAI SDK·Responses API·Structured Outputs를 **가상 뉴스 실험에서 사용**한다. `src/xfolio/`와 `dashboard/`에는 OpenAI API 호출이 연결되지 않았다.

| 의존성 | `pyproject.toml`의 `openai`·`pydantic`, `uv.lock`의 OpenAI SDK 3.26.0 |
| 실제 요청 | [news_summary_probe.py](../../scripts/experiments/news_summary_probe.py)의 `responses.with_raw_response.parse(...)` |
| 모델·설정 | `gpt-5.4-mini`, `reasoning.effort=none`, 출력 최대600토큰, `store=False`, `tools=[]`, timeout30초·자동 재시도0 |

| 구조화 결과 | 선정 여부, 선정/보류 이유, 한국어 요약, 출처 ID, 입력에서 인용한 근거 |

## 가이드와의 대응

가이드의 1절·3.1~3.2절·5.1절·12.1절의 기본 방향은 현재 선택과 맞는다. 일반 Python 코드가 실행 순서를 관리하고, Responses가 정해진 자료를 읽어 구조화된 결과를 내며, 앱이 검증·승인·게시를 책임지는 구조다.

| 기능 | 현재 적용 판단·추천 |
| --- | --- |
| Responses + Structured Outputs | 계속 사용. 기존 실험을 실제 입력 계약에 맞는 앱 분석 모듈로 연결하는 것이 우선 |
| Web search | 공식 거시 발표의 근거를 찾는 제한된 보조 실험을 추천. 뉴스 공급처의 확정 대체는 아님 |
| 저비용 모델 비교 | 현재 Mini와 가이드의 Luna를 동일 사례로 비교한 뒤 결정 |
| Prompt caching | 공통 지시·스키마를 앞에 두는 정도부터 적용. 캐시 적중·절감은 usage로 확인 |
| Function calling | 앱이 이미 아는 고정 조회는 일반 Python 함수로 수행. 모델이 추가 조회를 선택할 필요가 생길 때 검토 |
| Decisions·Embeddings | 분류량·사건 중복 문제가 실제 병목일 때 검토. 현재는 호출 경로·평가 항목을 늘리는 비용이 큼 |
| File search·Vector store | 검색할 과거 문서가 쌓일 때 검토. 현재 적은 기사 후보와 SQLite 기록에는 우선순위 낮음 |
| Agents SDK/API·MCP | 도구를 반복 선택하는 긴 조사에 필요할 때 검토. 첫 버전은 기존 고정 순서 유지 추천 |
| Batch | 대량의 과거 사례 평가에 적합. 24시간 처리 창이므로 아침 마감 경로에는 사용하지 않는 안을 추천 |
| Background·Webhooks·Conversations | 현재의 짧고 독립적인 처리에는 우선순위 낮음. Windows 예약·SQLite 승인/게시 기록을 대신하지 않음 |
| Code Interpreter·ChatKit·이미지/음성 | 고정 지수 계산·현재 Streamlit·텍스트 게시 범위를 유지하면 도입할 이유가 적음 |

공식 근거: [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs) · [Web search](https://developers.openai.com/api/docs/guides/tools-web-search) · [Prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching) · [Batch](https://developers.openai.com/api/docs/guides/batch). 나머지는 제공 가이드의 기능 설명을 현재 작업 규모에 대입한 설계 판단이다.

## 제안 1 · 기존 구조에서 불필요한 반복 호출 줄이기

추천 흐름은 `자료 확보 → Python으로 기간/ID/명백한 중복 필터 → 후보의 선정 이유·사실·근거·초안을 구조화 생성 → 코드/의미 검증 → 미리보기·승인 → 게시`다.

- 초기 분석에서 분류·근거 추출·번역·초안 작성을 가능한 한 같은 구조화 요청으로 묶는 안을 평가한다. 가상 시험도 선정과 요약을 한 번에 받았다. 전체 후보 간 중요도 비교와 여러 기사 근거 혼합 위험은 별도 시험이 필요하다.
- 지수 글, 출처·원문 링크·시간 표시는 Python 템플릿으로 만든다. 같은 입력을 번역·문체 정리·최종 조립 때문에 반복 전달하지 않도록 한다.
- 앱의 공통 분석 함수 한 곳에서 요청 설정·usage·실패·프롬프트 버전을 기록한다. 기존 검증 정책과 제한된 재생성 절차를 없애자는 제안은 아니다.
- 같은 자료·기준 시각·선정 규칙·모델·프롬프트 버전의 성공 결과만 재사용하는 앱 캐시를 검토한다. 새 기사/정정/새 기준 시각에는 재평가하고 게시 직전 자격은 다시 확인한다. 현재 가상 버전 중복 방지와 실제 AI 결과 캐시는 별개다.
- 현재의 pytest 검사에 조건부 발표·정정·동일 사건과 후속 사건·날짜 혼동 등의 평가 사례와 사람의 기대 판단을 더한다. 처음부터 별도 평가 서버를 추가할 필요는 없다.

## 제안 2 · Web search로 공식 거시 근거 보충 시험

Responses의 `web_search`는 도메인 제한과 출처 URL 반환을 지원한다. 연준·BLS·BEA 등의 공식 발표를 대상으로 최신 발표 후보를 찾는 안을 시험할 수 있다. 별도 뉴스 구독을 늘리지 않고 기존 OpenAI 연결을 활용한다는 장점이 있다. 현재 Mini도 공식 모델 문서상 Web search를 지원하지만 계정·요청 설정·실제 결과는 이번에 시험하지 않았다. [검색 기능](https://developers.openai.com/api/docs/guides/tools-web-search) · [Mini 지원 기능](https://developers.openai.com/api/docs/models/gpt-5.4-mini)

검색 성공이 전체 사건 수집이나 시점 적합성을 보장하지는 않는다. 발행·수정·대상 기간·정보 기준 시각을 대조하고, 출처/인용을 표시하며, 발견한 자료의 이용 조건도 확인한다. 일정이 정해진 공식 발표를 직접 수집하는 방식과 같은 사례로 비교한다. 현재 막힌 Marketaux 근거 문제를 검색 기능만으로 해결했다고 간주하지 않는다.

공식 단가는 검색 도구 호출당 $0.01에 모델 입력·출력 비용이 더해진다. 예를 들어 **실제 과금 검색 호출이 하루2회·월22일이면 도구 비용만 $0.44, 약799원**이다. 응답 요청 한 번에서 검색을 여러 번 할 수 있으므로 요청 수와 도구 호출 수를 구분해 제한·기록해야 한다. 기존 부분 예산의 잔여 약2,824원에 토큰·재시도·자료 이용료까지 합산해야 한다. [도구 가격](https://developers.openai.com/api/docs/pricing)

## 제안 3 · Mini와 Luna를 같은 평가 사례로 비교

100만 토큰당 Standard 일반 입력/출력은 현재 Mini $0.75/$4.50, Luna $0.10/$0.50이다. Luna는 구조화 출력을 지원하며 기본 추론 강도가 `medium`이므로 비교할 때 `none` 등 조건을 명시해야 한다. 계정 접근·한국어 품질·실제 출력량은 아직 확인하지 않았다. [Mini](https://developers.openai.com/api/docs/models/gpt-5.4-mini) · [Luna](https://developers.openai.com/api/docs/models/gpt-6-luna)

기존 월 가정인 입력704,000·청구 출력105,600토큰을 **똑같이 사용하고 캐시·도구·재시도가 없다면** AI 비용은 Mini $1.0032에서 Luna $0.1232로, 계획 환산 약1,821원에서 약224원으로 내려간다. 약1,597원의 차이는 단가를 바꾼 산술 비교다. 실측 절감이나 전체 운영비 확정이 아니며 실제 출력량과 실패 재처리까지 측정해야 한다.

우선 기존6사례와 조건/정정/후속 사건 사례를 함께 평가해 수치·기간·근거 보존과 보류 판단, 한국어 문장, 지연, 성공 건당 비용을 비교한다. 통과하면 기본 모델 교체를 결정한다. 현재 모델은 유지한다.

## 가이드에서 적용 전에 다시 확인할 부분

1. **Decisions 과금 설명 차이:** 원자료는 출력·캐시 읽기·쓰기 요금이 없다고 설명하지만, 10/24 재열람한 공식 문서는 출력 무료, 캐시 읽기 할인·쓰기 과금을 명시한다. 해당 기능을 쓸 때 현재 공식 단가로 계산해야 한다. [Decisions 과금](https://developers.openai.com/api/docs/guides/decisions#pricing-and-availability)
2. **캐시 단가의 적용 범위:** 가이드의 GPT-6 예시 캐시 쓰기 배율을 현재 Mini에 그대로 적용하지 않는다. 모델·보존 시간별 가격을 구분하고 `usage` 필드를 반영한다. 현재8건은 캐시 사용량0이어서 기존 산식에 이 문제가 없었다. [캐시 안내](https://developers.openai.com/api/docs/guides/prompt-caching)
3. 가이드의 `../../../CONTEXT.md`는 현재 저장소에서 연결되지 않는 외부 프로젝트 참조다. 운영 기준은 이 저장소의 요구사항·운영 정책·기술 구성이다. 원자료의 기능 목록 전체를 도입 목록으로 취급하지 않는다.

이번 검토는 적용 후보에 필요한 공식 기능·가격을 확인한 것이며 가이드에 나온 모든 API·종료 일정을 전수 검증한 결과는 아니다. 원본은 리더 제공 자료로 보존했다.
