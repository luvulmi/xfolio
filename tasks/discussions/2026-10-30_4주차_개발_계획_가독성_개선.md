## 요청과 확인한 사실

사용자는 현재 4주차 개발 계획의 가독성이 낮아 문서를 다시 다듬고, 보완·확정이 필요한 사항은 질문하면서 진행해 달라고 요청했다. 이번 범위는 문서 편집과 계획 논의다.

확인 당시 발표 편집본에는 BEA·SEC 축소안이, 기준 문서에는 공식 4기관·SEC 10→20기업이 섞여 있었다. 관련 문서도 작업 중 갱신되고 있어 최신 내용을 대조했다. 사용자 답변을 최종 기준으로 삼아 기관 범위·기업 수·지원 유형을 일치시킨다.

## 제안과 대안

- **최신 구성:** 확정 기획의 큰 그림·결정 결과·개발 기술 → 주차별 작업·시간·완료 기준 → 현재 성과·차주 계획·시행착오 → 11/1까지 계정·API 준비의 4개 구간으로 편집한다. 이전 6개 구간 편집안은 사용자 제공 발표 기준으로 대체했다. 상세 검증 조건·시간 산식·공시 지원 조건은 대본에 둔다.
- **미채택:** BEA·SEC에 집중하는 축소안, 기술 분야 기업 10개 집중안, 7~8주차 각 20시간 확보안.
- **일정 제안:** 11/15 실제 지원 범위·잔여량 재산정, 11/22 승인·worker 연결 점검, 11/24 기능 동결. 동결일은 사용자 확정이 아니다.
- 20기업 확장 시험 1시간을 제거해 핵심 기준 58시간, 후속 포함 전체 기준 78시간으로 재산정한다. 가용 60시간 가정의 추가 여유는 2시간이다. 핵심 58시간에는 별도 결함 수정 3시간이 포함돼 있다.
- 7~8주차 실제 시간이나 소스별 구현 난도가 달라지면 재산정한다. 여유가 적다는 이유로 근거·승인·중복·마감 검증을 생략하거나 전체 제품 완료를 약속하지 않는다.

## 미결정 질문

발표 형식·기관·기업 구성·초기 자료에 대한 질문은 답변을 반영했다. 다음 항목은 개발 착수 전 확인 과제로 남긴다.

- 공식 법인명·CIK·티커 매핑·지원 공시 표본·감시 시작일.
- 실제 원문 표본의 이용 범위와 최소 추출 필드·지원 문형.
- 7~8주차 실제 가용시간, 11/24 기능 동결 가능 여부.
- 실제 발표 제한 시간. 발표일은 11/1로 확정했으며 대본 약 5~6분은 편집 기준, 리허설 측정값이 아니다.

## 11/1 발표 기준에 맞춘 후속 편집

사용자가 발표일을 11/1로 확정하고 확정 기획·주차별 구체적인 일정·진행 상황/차주 계획/시행착오·계정과 API 준비사항을 포함하도록 요청했다. 후속 정정에서 준비 기한도 **11/1까지**라고 명시했다. 준비 목록의 잘못된 11/2~11/8 표기를 11/1 마감으로 수정하고 제목·대본·일정·연결 앵커에 반영했다.

- 화면과 대본을 사용자 기준의 4개 구간으로 재구성했다. 5~8주차마다 실제 작업·배정 시간·주차 말 결과를 명시한다.
- 기존 WBS의 15·15·15·8·7시간 배정과 총 58시간·여유 2시간은 유지한다. 신규 발행 조회 API 2개·목표 총 10개, 관리자 3개 메뉴, 모의 전송의 검증 사례를 구체화했다.
- 현재 성과는 10/30 기준으로 작성하고 callback 불일치·HTTPS 연결 지연의 해결, AI 형식 검사와 의미 검증의 구분을 실제 기록으로 연결했다.
- GitHub·X 계정·X 개발자 콘솔/API Key·OpenAI·Neon/Google OAuth·수집 설정·AWS/Telegram의 준비 조건과 기록상 상태를 넣었다. 이후 사용자 확인으로 X 계정은 보유, 개발자 콘솔·API Key는 미설정으로 갱신했다. 후속 서비스 상태는 확인 필요로 남긴다.
- 사용자가 제시한 AWS DB/API 10개는 구체성의 예시다. 기존 Neon·8API·8테이블 재사용과 발행 조회 API 2개 추가라는 실제 프로젝트 계획을 유지한다.
- 이번 요청은 문서 수정이다. 서비스 가입·키 발급·실제 외부 호출을 수행한 것으로 기록하지 않는다.
- 후속 검증: 발표 자료·대본의 11/1 날짜와 필수 4개 구간, 5~7주차 각 15시간 배정, WBS의 15·15·15·8·7시간과 총합, 현행 OpenAPI 8경로를 대조했다. 변경 Markdown 34개·상대 링크 356개·앵커 18개·JSON 예시 4개와 UTF-8/BOM·코드 블록·`git diff --check`를 검사해 통과했다. 제품 테스트와 실제 계정·키 유효성 조회는 수행하지 않았다.

## X 계정 이름 추천과 개발자 설정 안내

- 사용자 확인: X 계정은 있고, 개발자 콘솔·API Key는 아직 설정하지 않았다. 발표 화면과 대본의 상태를 갱신했다.
- 이름·아이디 추천 1순위: **XFolio | 미국시장 브리핑 / `@XFolioBrief`**. 사용 가능 여부 미확인·사용자 선택 전이며 프로필을 변경하지 않았다.
- [X 설정 가이드](../../docs/research/X_게시_API.md)에 가입 목적 예시, 앱 생성, Read and write, 본인 계정용 키·토큰 4개, 요금·보관·11/1 준비 기준을 정리했다. OAuth 1.0a는 초기 설정 추천이며 확정된 구현 선택은 아니다.
- 공식 공개 문서에서 10/30 기준 등록·권한·사용자 인증·선불 과금·URL 글 단가를 확인했다. 기존 조사와 이전 편성의 비용 예시는 별도 보존본으로 옮겼다.
- 실제 계정 로그인·가입·약관 동의·앱 생성·키 발급·충전·API 호출·외부 게시를 수행하지 않았다. X callback·게시 연동은 후속 구현 대상이다.
- 검증: 변경·신규 Markdown 37개, 상대 링크 381개·앵커 18개, UTF-8/BOM·코드 블록·기존 일정 산식 검사와 `git diff --check`를 통과했다. `.env`의 Git 제외도 확인했다. 문서 변경으로 제품 테스트는 실행하지 않았다.
