## 사용자가 확정한 사항

- 추가 기업 뉴스는 하루 최대 2건으로 변경한다. 중요한 기업 소식을 더 전달하려는 요청이며 매일 2건을 채우라는 뜻은 아니다. 한 사건당 1개 글과 기존 시간·중복·예산 조건을 유지한다.
- 처음에는 아침 최대 5개 글을 줄일 방법과 비용 비교를 요청했다. 이후 A안을 선택해 두 지수 종가·등락률 요약 1개 글 + 최우선 뉴스·원문 링크 1개 글, 최대 2개 글로 확정했다. 반복되는 AI 총평을 생략하고 확인된 변화 1건을 충분히 설명한다.
- 정상 수집 후 선정 뉴스가 0건이면 수집 범위 내 선정 뉴스가 없음을 표시한 지수 1개 글만 발행한다. 수집 실패·불완전 수집·지수 누락은 전체 보류한다. 기존 시각·단위·조건·출처·280 가중 글자 기준을 유지한다.
- 발표 내용 확정 전에 실제 지수 조회 → 뉴스 샘플·이용 권한 확인 → 한국어 요약 품질·실제 AI usage 확인 → 구현 계획 구체화 순서로 검증을 진행한다.
- 가능한 병렬 작업을 요청했다. 아침 구성 검토와 기술 설명을 별도 에이전트에 맡기고 비용·문서 정리는 주 에이전트가 수행했다.
- 이후 두 키를 등록하고 추천1·2·3의 실제 시험·결과 반영을 요청했다. Marketaux는 실제13회 조회·고유29기사 제한 표본을 확보했다. OpenAI6건은429였고 진단에서 `credit_balance_exhausted` / `insufficient_quota`를 확인했다.
- 사용자는 잔액·프로젝트 예산 확인 뒤 $5 결제 완료를 알리고 동일6건 재시험·Marketaux 근거/증분/무료 한도 검증·결과 기반 확정을 요청했다. 생성6건과 의미 오류 교정2건을 실제 시험했다.

## 실제 시험 후 결정

- Mini 가상6건은 요약4·보류2, 입력1,866·출력804토큰, $0.0050175였다. 범위 누락·부정확한 보류 사유2건을 발견해 프롬프트를 보완했고 해당2건 재시험에서 개선을 확인했다. 합계 $0.00677325(계획 환산 약12원), 운영자 검토·실뉴스 품질은 별도다. 실제 생성으로 사용 가능은 확인했으나 잔액 금액 자체는 조회하지 않았다.
- Marketaux는 짧은 증분9GET·평일 재생31GET·아침 첫 페이지2GET을 추가했다. 전체55GET 시도 중54성공·속도제한429 1이다.429는일일 한도 소진과 다르며 응답 헤더의 일일100회·60초30회,21:39 KST 잔여46회를 확인했다.
- 아침24시간의 넓은 거시2질의는138페이지 추산이라 무료100회/일에 맞지 않는다. 발췌의 혼입·절단도 있어 현재 검색식을 그대로 운영 채택하지 않는다.
- 결과를 바탕으로 **Marketaux 단일 개발 연동·30시간 구현 순서·3주차 조사 발표를 확정**했다. 공개 운영 전에는 좁힌 질의의 완전 수집·근거·최초 수록/수정, 외부AI·한국어 X 요약·보관 이용 범위, 실뉴스 품질/운영자 검토와 예산을 확인한다. 신규 구독·문의 발송·실제 게시를 수행하지 않았다.

근거와 원본 결과는 [시험 문서](../verification/뉴스_샘플과_요약_시험.md), 현재 실행 순서는 [개발 일정](../plans/개발_일정.md)을 따른다.

## 제안과 대안 · 선택 당시 비교 기록

아래는 선택 전 검토한 대안과 당시의 부분 견적이다. 현재 편성은 A로 확정했으며 최신 비용·전제와 샘플 검증 결과는 [월 비용](../../docs/research/월_비용.md)과 후속 검증 기록을 따른다.

**지수는 S&P 500과 Nasdaq-100 두 개를 모두 유지한다.** 아래의 ‘지수 1개 글’은 두 지수의 종가·등락률을 게시물 하나에 함께 담는 뜻이다. 기존 아침안도 두 지수를 한 글에 담는다.

| 대안 | 아침 구성 | 이점·제약 | 추가 뉴스 2건 포함 월 부분 견적 |
| --- | --- | --- | --- |
| 기존 유지 | 지수 1 + 뉴스 최대 3 + 정리·출처 1 | 정보량은 많지만 읽는 단계가 많음 | 29,572원 |
| A · 추천 | 지수 1 + 최우선 뉴스·원문 링크 1 | 총 2개 글로 핵심 집중. 두 번째 거시 사건을 놓칠 수 있음 | 27,176원 |
| B | 지수 1 + 뉴스 최대 2건 요약 1 + 출처 모음 1 | 총 3개 글로 시장 맥락을 더 유지. 요약과 출처를 오가야 함 | 27,975원 |

아침 검토 담당은 정보량 보존 면에서 B를 우선 추천했고, 최종 제안은 사용자의 게시 수 축소 의도를 더 반영해 A를 우선한다. B도 정보량을 원할 때 적합한 대안으로 남긴다. 월 22일·매일 최대 발행·일반 조회 글당 1회·AI $1.0032·1,815원/USD 가정이다. 단가·AI 산식·예산 초과 위험은 [월 비용](../../docs/research/월_비용.md) 한 곳에서 관리한다.

### 글을 줄이면서 유용성을 높이는 방법

1. 아침은 ‘두 지수의 마감 결과 + 오늘 알아야 할 확인된 시장 변화’에 집중한다. 거시·정책·업종을 매일 한 건씩 채우지 않고 기존 중요도 순으로 고른다.
2. A는 가장 중요한 새 사건 1건을 주체·변화·시점/기간·출처로 설명한다. 독자에게 의미가 있는 적용 대상·범위를 원문 근거 안에서 덧붙이고 가격 방향을 추정하지 않는다.
3. B는 서로 다른 새 사건 최대 2건을 같은 요약 글에 담고 `[1]`, `[2]`를 마지막 글의 출처명·URL과 대응한다. 같은 사건의 재해설 두 개를 선정하지 않는다.
4. 독립된 ‘AI 총평’ 글은 생략한다. 검토 당시 공통 변화 한 줄을 첫 글에 덧붙이는 방법도 제안했으나, 최종 선택에서는 반복되는 총평 없이 뉴스 글에서 확인된 변화 1건을 충분히 설명한다. 지수 등락 원인을 추정해서 채우지 않는다.
5. 아침 제외 기사는 추가 기업 뉴스로 자동 이동하지 않는다. 관찰 기업·기업 사건 기준을 따로 만족해야 한다. 실적 발표 하나의 매출·이익·전망을 두 사건으로 나누지 않는다.

### 짧은 글에서도 남길 정보

- 지수 글: 미국 거래일, 두 종가·등락률, 데이터 출처, 정보 기준과 실제 게시 시각. 지수 가격은 Python 계산·원문 대조 결과를 사용한다.
- 뉴스 글: 주체, 확인된 변화, 사건 시점/기간, 필요한 단위·조건, 매체명과 대응 원문 링크. A는 같은 글에서 원문 확인이 가능하다.
- 뉴스 0건: 정상 수집 범위에서 선정 뉴스가 없음을 지수 글에 표시하고 1개 글로 끝낸다. 수집 실패·지수 누락은 정상 0건과 구분해 전체 보류한다.
- 길이 초과: 반복 설명·부가 수치부터 줄이고 핵심 조건이 훼손되면 해당 뉴스를 제외하고 다음 순위 후보를 검토한다. 정상 수집 후 적격 뉴스가 없으면 지수 1개 글 규칙을 적용한다. 필수 지수 정보 또는 기업 사건이 각각 한 글에 들어가지 않으면 해당 발행을 보류한다.

X의 기본 한도는 280 가중 글자이며 한글은 보통 2, URL은 23이다. A는 뉴스와 링크를 같은 글에 넣으므로 뉴스 1건을 우선한다. B도 뉴스 2건을 억지로 넣지 않는다. 완성 문안은 NFC·URL·이모지를 처리하는 규칙으로 확인해야 한다. [X 공식 글자 수](https://docs.x.com/fundamentals/counting-characters)

## 사용자 확인과 결정 과정

- 2개 글 A와 3개 글 B를 선택하도록 질문했다.
- 사용자: “지수를 1개만 하자는 거야? 아님 그냥 지수 두개를 게시물하나로 하자는건가?”
- 답변: 두 지수를 게시물 하나에 함께 담으며 종가·등락률을 모두 유지한다고 설명했다. 이 질문은 A/B 선택으로 간주하지 않는다.
- 위 설명 이후 사용자가 A(아침 최대 2개 글·뉴스 1건)를 선택했다. 기준 문서의 기존 최대 5개 글·뉴스 3건은 이 확정안으로 대체한다. B는 검토 이력으로 남긴다.
- 추가로 발표 확정 전에 실제 조회·뉴스 샘플/권한·한국어 품질/실제 usage를 순서대로 확인하고 구현 계획을 구체화하도록 요청했다. 편성 선택 완료와 실제 샘플 검증 완료를 구별한다.

## 기술 설명과 현재 상태

발표용 정의·비유·현재 구현 상태·30초 대본은 [3주차 발표](../presentations/3주차_기술_조사.md)에 모았다. httpx는 요청·응답, Pydantic은 형식 검증, SQLite는 기록, Streamlit은 관리자 화면이다. Pydantic 형식 통과가 사실 정확성을 보장하지 않는다.

## 반영 결과와 검증

- 요구사항·운영 정책·README에 추가 뉴스 최대 2건과 아침 최대 2개 글·뉴스 최대 1건을 반영했다. 아침의 독립 출처 모음 글·반복 AI 총평을 생략하고 정상 수집 후 뉴스 0건이면 지수 1개 글만 발행한다.
- 월 비용을 재계산하고 3주차 발표의 비용·기술 설명·지수 실제 조회 상태를 갱신한다. 과거 발표와 비용 보관 이력은 당시 기록을 유지한다.
- 공식 가격과 실제 코드·검증 기록을 대조했다. Decimal로 네 편성의 생성·조회·AI 합계와 원화 반올림, 운영일 민감도·AI 증가 가정을 실행 검산했다.
- 최초 편성 검토 당시 변경 문서 12개의 BOM 없는 UTF-8·표 열 수, 상대 링크 95개, `git diff --check`를 검사해 모두 통과했다(검증 명령 종료 코드 0). 이는 당시 검증 기록이며 이번 확정 반영의 검증 결과와 구별한다. 애플리케이션 코드는 변경하지 않았다.
- 아침 A안 확정 반영에서는 요구사항·운영 정책·README·본 세션 문서 4개의 BOM 없는 UTF-8·표 열 수, 상대 링크 30개, `git diff --check`를 검사해 통과했다(각 검증 명령 종료 코드 0). 뉴스 샘플·실제 모델 출력·실제 usage 검증 완료를 뜻하지 않는다.

## 다음에 확인할 일

후속 요청에서 사용자는 기업 API 분리 여부를 질문하고 좁힌 질의·이용 범위·News Pipeline/미리보기 구현을 요청했다. 검색8+앱4GET을 추가해 고정 아침 창4요청 완료를 확인했지만, 표본4기사는 근거가 부족했다. 기업 API 즉시 분리는 채택하지 않고 운영 입력 전략을 다시 검토한다. 실제 기사 AI·공개 권한은 미확인이다.

자동화 에이전트와 관리자 사이트 배포 방식도 정하도록 추가 요청했다. 접속 범위 질문에 사용자는 **현재 Windows PC에서만 접속**을 선택했다. 이를 기술 구성·연구 문서·README에 반영했다. 구현 방식은 기존 SDK의 제한된 AI 단계와 Python 고정 워크플로, Windows 작업 스케줄러의 예약 시작, localhost Streamlit과 공통 SQLite로 구체화했다. 실제 앱 인증·승인과 제품 예약 등록까지 완료한 결정은 아니다.

1. 미국 지표·확정 정책/공식 발표 중심으로 좁힌 질의의 근거·완주·누락·지연을 확인한다.
2. 외부AI·공개 요약·보관 조건을 확인하고 허용된 실제 뉴스의 한국어 품질·운영자 검토·usage를 시험한다.
3. 확정한 입력/실패 계약을 News Pipeline·SQLite·아침 미리보기에 구현한다.
