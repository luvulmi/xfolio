## 2주 MVP의 구체적 설계값

아래는 위 범위를 구체화하기 위해 채택한 구현 기준이며 사용자 발언을 그대로 인용한 값은 아니다.

- UI는 React·TypeScript·Vite의 목록/상세 2화면, 인증과 승인 API를 포함한 FastAPI 8개 endpoint로 제한한다. 수집·AI·게시 도메인 코드는 재사용한다.
- AWS는 Lightsail Linux VM 한 대의 `web`/`api`/`worker` Docker Compose, DB는 기존 Neon PostgreSQL을 사용한다. 1GB $7 플랜은 초기 시험값이며 메모리·총비용 확인 전 적합 판정이 아니다. RDS·ECS·ALB·S3/CloudFront·Terraform은 후속이다.
- worker 한 프로세스의 APScheduler가 고정 시각을 관리한다. API 서버 안에 중복 스케줄러를 띄우지 않는다. DB 고유 키·원자적 상태 점유로 중복 실행/게시를 막는다.
- 추가 뉴스는 09:00~17:00 매시간과 17:30 최종 확인. 17:30까지의 발행 기사와 그때 시작한 마지막 수집 결과를 17:45까지 확보·동결해 18:00 발행 대상으로 삼는다. 필요한 구간이 partial이면 발행 보류다.
- 18:00에 최대 2건의 게시를 시작하고 **18:10부터 신규 전송·자동 재시도 금지**로 한다. 18시 전 즉시 게시와 별도 5분 승인 대기 Job은 제거한다. 단일 worker가 아침/저녁 발행 창 안에서만 60초 간격으로 due 작업을 확인해 늦은 승인도 마감 내 처리한다. 아침 08:00 목표·09:00 마감은 유지한다.
- Telegram은 단일 운영자 chat의 발신 전용이다. 승인 명령·웹훅·대화형 봇·유료 방송을 넣지 않는다. 동일 장애 중복 억제와 제한 재시도는 DB에 기록한다.
- 개발 기본 모드는 dry_run→reviewed다. auto gate는 구현·실패 시험을 하지만 활성화는 기존 5거래일/장애 시험 뒤다. 2주 MVP 완료와 무인 운영 안정화 완료를 구분한다.

## 미결정·착수 전 확인

- Marketaux의 지수 관련 질의·충분한 근거·공개/외부 AI/보관 권한, 지수 공개 이용 조건
- X 게시 대상·사용자 인증·실제 전송 승인, Telegram bot token/chat ID, AWS 계정·HTTPS용 도메인 준비
- Lightsail 메모리와 도메인/백업까지 포함한 월 5만 원 충족 여부. 2GB 자동 증설이나 예산 증액은 하지 않음

조건이 없는 경우 허용된 가상 입력과 모의 전송으로 구현하되 실뉴스·실제 게시·운영 성공으로 표시하지 않는다.
