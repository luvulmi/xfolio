| 스크립트 | 입력·실행 방식 | 결과·해석 |

SQLite 실험은 독립 연결을 가진 두 스레드이며 서로 다른 OS 프로세스나 강제 종료·부하 시험을 대신하지 않는다. 백업 결과에는 가짜 게시물 ID와 승인 버전을 넣어 복원 여부를 확인했다. 실제 X 전송과 DB 기록이 원자적으로 처리된다는 검증은 아니다.

재현 명령:

```powershell
.venv/Scripts/python.exe scripts/experiments/openai_contract_probe.py
.venv/Scripts/python.exe scripts/experiments/sqlite_probe.py
```

필요한 라이브러리·검증 환경과 상세 결과는 아래에 기록한다. 기술 선택 근거는 [AI](../../docs/research/OpenAI_활용.md)·[저장](../../docs/research/저장소와_관리자_화면.md)·[예약](../../docs/research/예약_실행.md)을 참고한다. Windows 임시 디렉터리 권한이 제한된 실행 환경에서는 SQLite 실험 실행에 도구 승인이 필요할 수 있다. 실험은 임시 폴더만 사용하고 종료 시 정리한다.

## 현재 결론

로컬 기술 구성과 출처 통합 형식의 가능성은 추가로 확인했다. 그러나 실제 운영으로 넘어가는 가장 큰 의존성은 여전히 **정확한 두 지수와 한 뉴스 제공처의 공개 사용 권한·자료 확보**다. 계정·키가 없다는 사용자 답변에 따라 현재 가능한 공개 조사와 로컬 실험을 마쳤으며 실제 서비스 품질·권한·요금을 확인 완료로 표시하지 않는다.

다음 준비 순서는 데이터 이용 조건 확인 → 해당 제공처 키/허용 샘플 확보 → OpenAI 소량 시험과 X 콘솔 확인 → 로그인·예약을 포함한 실제 앱 검증이다. 키나 토큰은 문서·채팅·Git에 기록하지 않는다. 이번에 새 구독이나 편성 변경을 확정하지 않았다.


## OpenAI 계약 시험 상세

- 시험일: 2026-10-22. 기존 조사 문서의 결과를 이곳으로 이동했다.

[오프라인 검증 스크립트](../../scripts/experiments/openai_contract_probe.py)를 기존 `.venv` Python으로 실행했다. `httpx.MockTransport`가 모든 요청을 메모리에서 처리하므로 외부 API와 실제 키를 사용하지 않는다.

```powershell
.venv/Scripts/python.exe scripts/experiments/openai_contract_probe.py
```

| 확인 항목 | 실행 결과 |
| --- | --- |
| 설치 버전 | openai 3.26.0, pydantic 2.13.5, httpx 0.28.1 |
| SDK 계약 | responses.parse·text_format·strict JSON Schema 생성과 모의 결과의 output_parsed 확인 |
| 요청 제어 | store=False·reasoning none·출력 상한·도구 없음·SDK 재시도0 설정이 요청에 들어감 |
| 형식 오류 | boolean 문자열·허용 범주 밖 분류·미승인 필드 등 3개 입력 거부 |
| 사실 오류 | 10 billion을 999 billion으로 바꿔도 스키마는 수용. 스키마가 사실 검증을 대신하지 못함을 확인 |
| 근거 연결 | 가상 근거가 입력 자료에 없음을 별도 검사로 탐지. 완전한 의미 검증기는 아님 |

모의 응답의 usage=100/40은 시험용 숫자이며 실제 토큰 측정값이 아니다. 한국어 생성 품질·모델 지연·요금제별 접근·실제 usage는 키 없이 검증하지 못했다.

## SQLite 기능 시험 상세

- 시험일: 2026-10-22. 기존 조사 문서의 결과를 이곳으로 이동했다.

외부 API 없는 [재현 스크립트](../../scripts/experiments/sqlite_probe.py)를 추가해 임시 DB만 생성·삭제했다. 실행 명령은 저장소 루트 기준 `.\.venv\Scripts\python.exe scripts/experiments/sqlite_probe.py`다. 처음 샌드박스 임시 경로 권한 때문에 열기에 실패했으며 허용된 권한 재실행에서 아래 결과를 얻었다. `uv run`도 캐시 권한 오류가 있어 실제 실험은 기존 가상환경 실행 파일을 사용했다.

| 항목 | 실제 환경·방법 | 결과 |
| --- | --- | --- |
| 실행 환경 | Windows 11 build 26200, Python 3.12.10, SQLite 3.49.1, WAL | 전체 0.1996초. 처리량 측정값은 아님 |
| 중복 발행 키 | 두 스레드 각각 독립 연결, barrier 이후 같은 PRIMARY KEY INSERT 시도 | 예약 1건 성공, 나머지 1건 `IntegrityError`로 거절 |
| 승인 버전 조건부 갱신 | 현재 v2에 대해 v1 승인, v2 승인, v2 재승인 | 갱신 행 수 각각 0·1·0 |
| 트랜잭션 롤백 | 후보 변경·발행 예약 INSERT 후 의도적 예외 | 후보 v2 유지, 롤백 대상 예약 0건 |
| 백업·복원 | `Connection.backup`으로 사본 생성, 원 DB 수정 뒤 사본에서 새 DB 복원 | 후보 v2·승인 v2·가짜 게시물 ID 보존, `integrity_check=ok` |
| 데이터 처리 | `TemporaryDirectory` 안의 가짜 기사/게시 ID만 사용 | 성공 실행의 임시 디렉토리 정리 완료, 실제 앱 데이터 변경 없음 |

이는 **SQLite 기능의 작은 독립 실험**이다. XFolio 승인·게시 파이프라인은 아직 이 로직을 구현하지 않았다. 두 프로세스 강제 종료·전원 차단·OS 재부팅·X 전송·동시 한도 예약·월 저장량·운영 백업까지 검증한 것은 아니다. 일관된 DB 복원만으로 X에 이미 게시한 결과까지 되돌릴 수 없으므로 복원 뒤 외부 게시 결과 대조가 필요하다. 실행 코드의 Ruff 검사·형식 검사를 통과했다.
