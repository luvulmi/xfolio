## 입력·출력과 시각

`MorningInputs`는 T02 `Collection`/관심목록 revision/종목 메타데이터/한국 개장일과 T03 `NewsResult`를 받는다. 07:50 설정과 뉴스 발행 기준을 고정하고 수집 종료 이후 `build_morning(inputs, now=...)`로 구성한다. 07:58은 완료 목표이고 08시 이후라도08:10 전이면 편성할 수 있다. 저장/비교는 UTC, 표시 날짜·시각·예산 월은 KST다.

출력 `MorningEdition`에는 본문·출처별 오류 코드·가격/뉴스 건수·입력 해시·revision·원본 run/자료 ID·보존 만료가 있다. `ready`는 정상 자료, `partial`은 사용 가능한 자료와 실패 안내, `failed`는 개장 미확인/입력 오류/사용 자료 없음, `skipped`는 한국 휴장 평일/주말 정상 건너뜀이다. 실패·건너뜀 본문은 관리자용 설명이며 Telegram으로 보내지 않는다. 휴장 여부는 가격/뉴스 유무와 무관하게 전체 발송을 막는다. T06은 제공처 수집 전에 개장 여부를 확인해 불필요한 휴장일 호출도 건너뛰어야 한다.

가격은 코드/순서/revision·최근 완료2거래일·예정 마감·실제 조회시각을 대조하고 종목별 누락/다른 날짜는 확인 불가로 표시한다. 일부 가격 실패는 나머지 가격/뉴스를 막지 않는다. Decimal 등락률을 재사용하고 분할/미확인 기준/DB 정정 버전은 등락률을 보류한다. 소수 가격을 임의로 정수 반올림하지 않는다. 실제 가격 기준시각 미제공과 예정 마감을 구분하고 제공 지연은 관측 없이 정상으로 단정하지 않는다.

일반/공식 합계최대3건, T03의24/96시간·중복 선정 결과를 사용한다. 원본 출처/내용 버전 일치, 권한, 수집 기준07:50, 공식 요약이 근거별 허용 한국어 문형과 정확히 일치하는지 다시 검사한다. 실패 출처 자료는 제외하며 일반 기사 제목을 번역/요약하지 않는다. 정상0건·일부 수집 실패·전체 수집 실패·검사 탈락을 구별한다. 24h 밖 보완 자료는 발행일과 안내를 표시한다.

## 저장 계약 · 0005

`NewsletterStore.save(inputs, now=...)`는 이미 같은 DB에 저장한 T02/T03 자료를 대조한다. 원본 run/가격 관측·해시·최신 가격 버전·종목 이름/ISIN/지원 여부·달력·뉴스 run/최소 메타데이터가 일치해야 한다. 종목/설정 API와 worker는 별도이며 수집·저장 코드는 새 송신 기능을 포함하지 않는다.

`newsletter_editions`의 수신자 scope+KST 날짜+`morning` 유일 키와 트랜잭션 advisory lock이 동시 생성을 직렬화한다. 동일 입력 재호출은 최초 행 반환, 다른 입력은 `edition_input_conflict`다. 저장 행과 본문은 DB trigger로 불변이며, 실패 행을 새 입력으로 자동 덮어쓰는 계약은 제공하지 않는다. 발송 재시도/outbox 점유는 T06이다. 기존 `publication_jobs`/AM 승인/0001~0004의 제약은 유지한다. 저장만으로 기발송 뉴스나 전송 성공 기록을 생성하지 않는다.

payload에는 원문·`facts`·`evidence_span`을 넣지 않는다. 만료는 편성 생성+90일, 가격/뉴스 조회+90일, 원본 DB 만료 중 가장 이른 시각이다. 동일 입력 재호출은 연장하지 않는다. 만료 시점부터 `get`은 반환하지 않으며 `purge_expired`가 본문과 가격/뉴스 참조를 삭제한다. 정기 실행·백업 복원 후 삭제는 T08이다. 발송 결과1년 보존은 가격 없는 T06 메타데이터의 별도 계약이다.

## 발송 직전 검사

`check_send(edition, SendContext)`는 순수 검사, `NewsletterStore.check(key, context)`는 DB 원본·현재 관심목록·개장일·최신 가격 버전·뉴스 전달 상태까지 재검사한다. `SendContext`는 신뢰하는 서버가 실제 전송 직전에 읽은 값을 공급해야 한다.

| 검사 | 차단 조건 |
| --- | --- |
| 편성·날짜 | 준비 자료 없음, 실패/건너뜀, dry_run/합성, 주말/휴장/개장 미확인, 미래 생성/보존 만료 |
| 시각 | 대상 KST 날짜08:00 이전 또는08:10 이상,07:50 고정 기준 불일치 |
| 설정·종목 | 일시 중지/아침 비활성, 고정 설정과 현재 값/revision 불일치, 관심목록 코드/순서/revision 변경 |
| 수신자 | 본인 scope와 다름, allowlist가 정확히 본인1명이 아님, private chat 아님 |
| 예산 | KST 월 불일치·편성 이전/미래 예산 확인, 확인+예약+추가 예상액이 한도 초과. 한도 최대50,000원·NaN/무한/음수 거절 |
| 이력 | sending/confirmed/partial/failed/unknown. 별도로 안전 판정한retryable_failure만 마감 내 허용 |
| DB 자료 | 원본 삭제/만료·정정으로 대체된 가격·뉴스 전달confirmed/unknown·현재 개장일 미확인 |

검사 통과와 발송 DB 원자 점유 사이의 경쟁 조건은 T06 트랜잭션에서 해결해야 한다. 현재 설정·월 예산·수신자·전송 상태를 신뢰하는 서버/원장에서 읽는 연결도 T05/T06의 책임이다. 로컬 JSON이 검사에 통과했다는 사실은 서버 운영 발송 허가가 아니다. `newsletter-preview`는 항상 실제 `can_send=false`이며 `send_check`에만 판정 결과를 표시한다.
