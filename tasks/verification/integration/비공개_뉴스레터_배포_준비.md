## 입력·출력과 경계

입력은 통합한 T05/API·T06/worker 소스, 고정 lockfile, 서버별 비밀 파일 경로다. 이미지 build는 저장소에서 허용한 코드/manifest만 보내며 `.env`·cache·DB·Git을 build context에서 제외한다. runtime 이미지에 비밀을 COPY하지 않는다. API/worker는 같은 Python 이미지의 독립 프로세스이며 web은 frontend build+Caddy다.

Compose 기본 기동은 API/web, 포트 게시 한 건은127.0.0.1:8088이다. API8000·DB5432·worker는 host에 게시하지 않는다. worker profile은 기본 mock·live accepted=false이고 `--live`가 없다. 외부 HTTPS는 Tailscale Serve에서 종료하며 본인 Google 세션/CSRF를 유지한다. 실제 공개 차단·TLS/OAuth·PC/휴대폰은 별도 실측 조건이다.

## 보존과 복원 gate

`maintenance.py plan`은 DB 무접속, `verify`는 읽기, `purge --execute`는 명시한 유지보수 DB의 저장 서비스만 호출한다. expires_at<=현재 UTC는 만료다. T04 편성→T02 가격→T03 뉴스→T05 감사→T06 outbox 순으로 삭제한다.90일 본문과365일 가격 없는 결과를 분리하며 설정 singleton은 유지한다.

모든 신규 보존 테이블이 있고 만료 행0건·legacy 본문 행0건이어야 can_resume=true다. legacy 이력은 자동 삭제하지 않고 정책 검토를 요청한다. DB/권한/schema 오류1, 재개 차단2, 통과0이며 비밀/원문/예외 응답을 로그에 넣지 않는다. 원격 DB는 TLS verify-full을 요구한다.

백업은 암호화 stdout만 저장하고 컨테이너 logging=none, 최대7일이다. 복원은 격리 DB에서 삭제→검사 후 노출한다. journald30일 보존 설정은 실제 호스트에 설치·실측해야 한다. 로컬 도구 시험은 운영 삭제·백업 복원 시험을 대신하지 않는다.

## 판정 방법

- `docker compose ... config --quiet`와 전체 profile JSON 정규화로 loopback 게시·worker profile·live OFF·API 비밀 분리를 확인한다.
- Caddy validate와 가능한 이미지 build를 실행한다. 다운로드/엔진 미사용이면 실패/미실행으로 기록한다.
- [무통신 시험](../../../tests/test_newsletter_deploy.py)은 정확 만료 경계·미완성 schema·legacy 복원 gate·명시 삭제·원격 TLS·오류 비밀 비노출을 검사한다.
- 실제 PostgreSQL 삭제·복원은 T05/T06 통합 DB에서 별도 확인하며 이번 SQLite 검사와 구분한다.
