- 관련: [병렬 계획](../../plans/뉴스레터_후속_병렬_개발.md) · [T04 계약](아침_뉴스레터_편성과_발송_검사.md)

## T04 인수

기준 HEAD는 `c1b1b1f`이며 T04·11/4 휴장 정책의 미커밋 변경을 검토한 파일 스냅샷으로 각 worktree에 전달한다. 임의 커밋 없이 동일 파일 해시를 대조한다. T04 공개 계약은 `MorningInputs`, `MorningSettings`, `MorningEdition`, `SendContext`, `NewsletterStore.save/get/check/purge_expired`다. 0005까지 단일 migration 계보를 유지한다. T04 결과의 전체898건·격리 DB 검증 기록을 인수하고 후속 변경에 맞춰 회귀를 실행한다.

한국 휴장 평일/주말에는 뉴스만의 알림도 발송하지 않는다. 준비 전 개장 확인과 전송 직전 재검사를 모두 수행한다. DB UTC·표시/대상일/예산 월 KST,07:50 동결·08:00 발송·08:10 마감이다. `ready/partial` 편성과 실제 전송 성공은 서로 다른 상태다. 동일 날짜 실패 편성은 새 입력으로 덮어쓸 수 없다.

## 설정 저장 · T05 소유

- `src/xfolio/notification_settings.py`의 `NotificationSettingsStore(engine)`를 공용 서비스로 사용한다.
- `get(*, conn=None, for_update=False) -> MorningSettings`: 서버 DB의 singleton 현재 설정. `conn`이 있으면 해당 트랜잭션을 사용하고 별도 commit하지 않는다. `for_update=True`는 기존 트랜잭션에서만 허용한다.
- `update(*, expected_revision, changes, actor, now) -> MorningSettings`: 트랜잭션에서 revision 검사·증가·감사를 함께 처리한다. 허용 변경은 네 boolean뿐이며 T09 인수 전 오후 두 설정의 true 변경은 거절한다.
- 설정 기본값은 T04와 동일하며 revision1, morning true, paused false, 오후 false다. migration `0006_notification_settings`가 초기 행을 생성한다. 실제 자동운영은 worker live 실행 설정과 운영 인수가 추가로 필요하다.
- `src/xfolio/db/notification_settings.py` metadata와 0006 DDL은 T05가 작성한다. `migrations/env.py`의 metadata 등록은 통합 담당이 수행한다.
- T06은 서비스를 import해 읽는다. 설정 테이블/기본값을 복제하거나 worker가 설정을 쓰지 않는다. 전송 claim과 설정/관심목록/예산 검사를 같은 DB 트랜잭션으로 묶고 메시지 조각마다 직전 재검사를 수행한다. 이미 진행한 외부 전송을 원격 취소할 수 있다고 표시하지 않는다.

## 발송 상태 · T06 소유

- `src/xfolio/jobs/`와 `src/xfolio/db/telegram.py`를 사용한다. migration `0007_telegram_outbox`는 `0006_notification_settings`를 부모로 한다.
- outbox에는 `id`, `edition_id`, `recipient_scope`, `target_date`, `slot`, `transport_mode`, `status`, `created_at`, `updated_at`, `expires_at` 및 조각별 시도/message_id/안전한 오류를 제공한다. 본문은 편성에서 읽고 별도 장기 payload에 복제하지 않는다.
- 상태는 `pending/sending/confirmed/partial/failed/unknown/retryable_failure/skipped`. 실패·불명·부분 성공을 confirmed로 집계하지 않는다. sending 상태에서 재시작하면 중복 송신 없이 보수적으로 unknown으로 정리한다. mock/live를 구분한다.
- `TelegramOutboxStore(engine).list_deliveries(*, now, limit=50)`와 `.get_delivery(id, *, now)`는 비밀 없는 JSON 호환 dict를 반환한다. T05는 이 서비스를 조회하며 쓰지 않는다. 모듈은 `xfolio.jobs.outbox`다.
- 결과 메타데이터 보존은1년, 가격/뉴스 본문은 원본의 더 이른90일 만료를 따른다. 만료된 편성 본문을 결과 메타데이터에 보존하지 않는다.

## 실행 구성 · T08 준비 범위

- API 진입점은 `uvicorn xfolio.api.app:app --host 0.0.0.0 --port 8000`.
- worker 진입점은 `python -m xfolio.jobs.worker`, 기본 모의 모드이며 live는 명시 옵션·서버 비밀/본인 수신자 확인·운영 인수가 필요하다.
- 신규 구성은 `deploy/newsletter/`에 둔다. 공개 포트/Funnel 없이 loopback proxy와 Tailscale Serve를 사용한다. T08은 자원 생성·유료 실행·운영 migration·실제 Telegram 송신을 실행하지 않는다.
- 공통 의존성/CLI/README/목차/WBS/CI와 `migrations/env.py`는 통합 담당이 갱신한다. 각 담당은 필요한 패치를 인계한다.

## 작업 공간과 검증

T05/T06/T08은 독립 worktree·브랜치, 별도 시험 DB schema/포트와 cache를 사용한다. 비밀 파일·`.env`·기존 DB 데이터는 복사하지 않는다. 각 담당은 자신의 파일과 작업별 계획/계약/로그만 수정한다. 공통 기준 스냅샷 대비 변경 목록으로 통합해 이전 사용자/T04 변경을 보존한다. 커밋/푸시는 이번 착수 범위에 포함하지 않는다.
