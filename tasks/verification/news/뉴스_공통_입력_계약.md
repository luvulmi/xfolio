## 범위와 기존 자료 인수

[Exa 표본](뉴스_API_재검토_표본과_예산.md)의 검색 3회(각 상위 5결과, auto/news, 본문 상한 20,000자)와 캐시 Contents 1회(2 URL, maxAgeHours=-1)를 인수한다. 고정 조회창은 10/28 00:00~10/30 08:00 UTC다. 응답 비용 합계 $0.023은 표본의 응답값이며 실제 청구·무료 잔액·월 운영비 검증이 아니다. 이를 제품 질의나 고정 단가로 확정하지 않는다. 실기사 본문은 원본에 없으며 복원하거나 합성 본문을 실자료로 표시하지 않는다.

Exa 개발 채택과 용도별 허가는 별개다. collection/storage/ai_transfer/summary_publication은 기본 pending_review로 보존한다. 기존 메타데이터 인수만으로 허가 상태를 올리지 않는다. 약관 재조사·문의 발송·새 실호출은 이번 범위 밖이다.

## 입력과 시각·개정

- `news_common_input_v1`: Exa/BLS 수집 입력용 schema 식별자. 승인·생성·AM 프로필이 아니며 기존 CPI/official/Marketaux 모델을 자동 변환하지 않는다. 모르는 schema와 추가 필드는 거절한다.
- 제공처 `source_id=exa|bls`와 원매체 `publisher`·`publisher_url`, 제공처 레코드 ID·원문 URL을 구분한다. 인증 정보가 든 URL은 기존 규칙으로 거절한다.
- 발행/접수 시각은 원래 문자열·시간대·정밀도(date/minute/second/unknown)와 확인 여부를 보존한다. UTC 값이 있어도 날짜형/미확인 시각은 시각 검사에 사용하지 않는다. 날짜를 임의 자정으로 승격하지 않는다.
- retrieved_at은 해당 버전 최초 조회 완료, available_at은 본문 사용 가능 확보(본문 없으면 null), last_checked_at은 마지막 재확인이다. retrieved_at ≤ available_at ≤ last_checked_at이며 timezone-aware UTC로 정규화한다. 같은 버전 재확인은 최초 시각을 보존하고 last_checked_at만 전진시킨다. 07:30 cutoff는 후속 편성에서 available_at을 비교한다.
- content_hash는 확보한 텍스트 그대로의 UTF-8 SHA256이다. 본문 미보관 메타데이터는 hash/available_at이 없을 수 있으며 충분성 합격으로 승격하지 않는다. 원천 개정 ID가 없으면 content_hash 기반 source_revision을 명시한다. event_key/fact_version은 아직 추출되지 않았으면 함께 null이며 URL/본문 hash로 사건을 자동 확정하지 않는다. 새 본문은 새 입력 버전으로 만들며 사건 단위 중복 게시/정정 재승인은 N09/A04에서 연결한다.
- data_origin(live_capture/permitted_fixture/synthetic_fixture)와 synthetic을 교차 검증한다. 이 모델은 전송/생성을 수행하지 않으므로 transport_mode/generation_mode와 승인 상태를 부여하지 않는다.

## 본문 충분성

text_chars·요청 상한·절단 여부·title_only와 충분성(not_assessed/insufficient/sufficient)을 분리한다. 길이 임계값으로 합격시키지 않는다. 충분 판정에는 실제 텍스트·그 안의 근거 구간·판정 주체/시각/이유가 필요하며 절단/제목 의존/상한 도달은 충분 판정을 막는다. 이는 의미 승인이나 이용 허가가 아니다. 텍스트는 공백을 임의 정규화하지 않아 hash와 근거 구간을 유지한다. 메타데이터만 있는 표본은 충분 판정 불가다.

AP 297자 절단, 20,000자 상한, Seeking Alpha 2,273자 도입부 절단과 CNBC 5,706자 사례를 메타데이터/합성 시험으로 구별한다. 원매체 기사 유형(article/press_release/live_updates/unknown)과 발행 시각 확인도 독립된 정보다.

## 수집 결과와 정상 0건

완료된 실행만 다룬다(running 저장/migration은 A01). collection_run_id·제공처·adapter/query/watchlist 버전·조회창·scope·필수 scope ID·요청 결과·선택적 응답 USD 비용을 기록한다. 요청 결과는 complete/partial/failed, 호출 수와 안전한 오류 코드를 가진다. 설정 질의/본문 확보의 각 필수 단계를 scope로 명시하며 제품 질의·상한 설정 자체는 N08에서 결정한다.

전체 status는 보고서로부터 기대값을 계산해 입력값과 대조한다. normal_zero/no_updates/new_version_count/응답비용 합계는 Python property로 계산하며 JSON에 저장하지 않는다. 일부 비용이 없으면 전체 비용은 null이고 0으로 가정하지 않는다.

- 모든 필수 scope가 complete여야 전체 complete다. 누락/부분 실패가 있고 일부 진행이 있으면 partial, 필수 scope 진행이 전혀 없거나 모두 실패면 failed다. 오류가 있는 complete 보고·성공 scope 없이 정상 완료를 허용하지 않는다.
- 발견 입력과 scope 결과의 참조·제공처·run ID·시각을 교차 검증한다. 검색과 본문 요청에서 같은 입력을 참조할 수 있으나 입력 개수는 중복 계산하지 않는다.
- `normal_zero`는 complete이면서 발견 입력 0건일 때만 true다. `no_updates`는 complete이면서 새 버전 0건일 때만 true다. 기존 버전만 발견한 경우와 선정 0건을 구별한다. 충분성/권리로 탈락한 후보를 지워 정상 0건으로 만들지 않는다.
- Exa complete은 설정한 질의·기간·상위 결과와 필수 본문 요청의 완료다. 시장 전체 포괄을 뜻하지 않는다. partial/failed에서 커서를 진행시키거나 게시하는 기능은 이 모델에 없다.
