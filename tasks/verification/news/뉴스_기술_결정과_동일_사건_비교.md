## 이번에 확정한 구현 결정표

아래는 후속 구현의 계약이다. 기존 수집기·가상 AI 외에 이 구조가 모두 구현됐다는 뜻은 아니다. 게시 편성·관찰 기업 상한·현재 실패 보류 정책은 기존 기준을 따른다.

| 결정 | 구현 기준 | 이유·미완료 경계 |
| --- | --- | --- |
| 수집과 근거 확보 분리 | 제공처별 어댑터가 후보를 찾고, 허용된 원자료에서 사실 근거를 확보한 뒤 AI 입력으로 전달 | API 검색 결과와 충분한 발췌는 다름. 임의 원문 크롤링 자동 우회 금지 |
| 수집 범위 | 아침: 거시·정책·시장/업종. 기업: 목록에 속하는 기업의 실적/전망/확정 사업 변화 | 공식 거시+기업 전용 API만으로 시장/업종 범위가 충족됐다고 보지 않음 |
| 공통 자료 | SourceRecord→EvidenceClaim→NewsEvent의 경계 정의. 제공처의 고유 스키마는 어댑터 내부에 둠 | 신규 제공처별로 전체 파이프라인을 다시 만들지 않음. 아래 필드 계약은 후속 구현 |
| AI 이전 제외 | 시간·기업 목록·명백한 전망/홍보·동일 기사·근거 누락을 Python으로 먼저 판정 | 불필요한 AI 호출 감소. 필터 탈락은 사유 코드로 남김 |
| 근거 판정 | 주체·확정 사실·대상 시점 필수. 수치는 값·단위·기간·비교 기준, 조건부 사건은 조건을 같은 근거로 대조 | 제목에만 수치가 있으면 요약 근거 합격으로 세지 않음 |
| 사건 중복 | 기존 R03의 주체+사건 유형+대상 기간/거래ID로 묶고 근거 버전을 별도 관리 | 같은 실적의 8-K·10-Q를 별도 발행으로 자동 증가시키지 않음 |
| 선정 | R03 우선순위로 비교하고 AI는 사실·분류·선정 이유·초안을 구조화. 모호한 중요성/같은 사건 여부는 검토 보류 | 임의 AI 점수나 문자열 포함만으로 중요도·진실성을 확정하지 않음 |
| 수집 진행 | SQLite에 제공처·질의버전·범위별 정상 완료 시각을 기록. 전체 필수 범위 완료 후만 전진 | 게시 성공과 수집 성공 분리. 겹침 폭은 수록 지연 관측 뒤 결정 |
| 실패와0건 | complete/partial/failed와 eligible/excluded/review_required를 분리. 실패를 선정0건으로 바꾸지 않음 | 현재 R07의 회차 보류를 유지. 복수 경로 채택 시 편성별 필수 목록은 별도 결정 |
| 첫 공식 어댑터 후보 | BLS의 허용 HTML 발표문부터 시험. 발표 일정/버전/시각 파싱을 확인한 뒤 확대 | HTML과 PDF를 처음부터 모두 처리하지 않음. DOL·기업 IR·SEC는 비교 출처이며 운영 연동 미확정 |

## 입력·출력 계약과 사유 코드

| 객체 | 최소 필드·검증 |
| --- | --- |
| SourceRecord | provider, source_id, source_url, published_at, updated_at(없으면null), retrieved_at, timestamp_precision, content_version, permission_scope, collection_run_id. 원문/발췌는 허용 범위에서만 보관 |
| EvidenceClaim | source_id+content_version, subject, event_type, action, certainty, event_time/period, value+unit+comparison_basis(수치가 있으면), conditions, evidence_span. 모르는 필드는null이며 추정값으로 채우지 않음 |
| NewsEvent | stable event_key, claim_refs, subject_id, event_type, period/transaction_id, fact_version, prior_event_version, eligibility_status, reason_codes. 출처 변경과 사건 변경을 구별 |
| CollectionRun | source/query_version/window, cursor_before/after, requests/pages, complete/partial/failed, quota snapshot. 성공한 경로만 취사선택해 전체 완료로 표시하지 않음 |

초기 사유 코드: `not_in_watchlist`, `not_released`, `title_only_fact`, `truncated_condition`, `missing_period`, `missing_unit`, `source_time_unknown`, `rights_unverified`, `same_event_no_new_fact`, `event_scope_uncertain`, `partial_collection`. 코드별 실제 사례와 기대 판정을 테스트 fixture에 옮기는 것이 다음 구현이다. 현재 시험의 어휘 단서4개는 이 근거 계약 전체를 구현한 검사가 아니다.

## 고정 비교 방법

- 공식 원자료로 사건·발표일을 먼저 확인한 **12검증 사례**다. 완료 사건8개, 같은 사건의 후속 공시1개, 발표 전 대조2개, 기간 밖 대조1개로 구성한다. 12개의 독립적인 완료 사건을 뜻하지 않는다.
- [사례 목록·질의·공식 URL](../assets/news_cases/events_20261025.json). 검증용 기업은 실제 관찰 목록에 추가하지 않았다. 지수 편입·기업 우선순위 확인은 별도다.
- 같은 API 조회 창: `2026-10-18T16:00Z`~`2026-10-24T15:00Z`. 10월25일00:51 KST에 실행. 영문·group_similar=false·관련도 정렬·도메인/기업 태그 제한 없음·최대3기사의 첫 페이지다.
- 기간 밖 CPI는 API 조회를 생략했고, 미래 실적2건은 최근 기간에 나오는 관련 기사/전망을 제외할 수 있는지 비교한다. 발표 안내문의 과거 발행일을 새 실적 발표일로 바꾸지 않는다.
- 이미 아는 사건의 이름/분기, 실업수당은 알려진194,000 수치까지 검색에 넣었다. 독립적인 신규 사건 발견·전체 커버리지·정밀도·재현율 측정이 아니다.
- 공식 원문 읽기와 httpx GET 접근성을 구별한다. [공식 GET 결과](../assets/news_cases/official_fetch_20261025.json)는12주소 모두HTTP200, HTML8/PDF4다. Netflix 리디렉션1회가 있어 HTTP 왕복은13회이며 자동 내용 파싱은 모두 `parsed=false`다. TI 10-Q 주소는 공시 상세 페이지이므로 본문 파싱까지 완료한 것으로 세지 않는다.
- Marketaux는11GET·최소3초 간격·자동 재시도0, 모두200. 고유25기사의 최소 메타데이터와 단서 일치 여부만 저장했다. [API 결과](../assets/news_cases/marketaux_events_20261025.json)

### 어휘 단서가 모두 맞은3건의 추가 판독

주체·기간·값/행위 단서가 모두 나온3개UUID만 다시 조회했다. 추가3GET 모두200이고 [요청 기록](../assets/news_cases/marker_review_requests_20261025.json)에 상태만 저장했다. 본문·발췌를 저장하거나 OpenAI API로 전송하지 않았다.

- 실업수당: 설명에 대상 주와 감소 사실이 있으나194,000은 제목에만 있었다. 설명만으로 수치를 생성하지 않는다.
- IBM: 설명은8-K 공개·분기를 알리지만 매출은 제목에만 있었다. 제목의 평가·EPS 해석을 그대로 합치지 않는다.
- TI: description은 단위 중간에서 잘렸으나 snippet에는 매출$6.06billion이 남았다. 공식 자료와 좁은 매출 사실을 대조할 수 있지만 완결된 기간 연결·조건·라이선스 검증을 대체하지 않는다.

따라서 **어휘4개 일치3/25를 근거 합격률로 쓰지 않는다.** 다른22건은 같은 의미 판독을 모두 수행한 것이 아니므로 전부 부적합이라고 집계하지 않는다. 제공처가 긴 원문 검색에서 찾은 기사가 짧은 반환 발췌에도 필요한 근거를 포함한다는 보장이 없다는 점은 [API 문서의 검색·description/snippet 정의](https://www.marketaux.com/documentation)와 일치한다.

## 제공처 합격 기준과 최종 판단

| 항목 | 채택에 필요한 근거 | 현재 |
| --- | --- | --- |
| 필수 사건 발견 | 미리 정한 사건 목록의 발견/누락 이유를 설명 | 과거 이름 지정 검색만 확인. 시장/업종 긍정 표본 부족 |
| 근거 | 게시할 모든 사실에 완결된 기간·단위·조건의 허용 근거 | 일부 제목 의존/절단 확인. 운영 합격 미충족 |
| 시점 | 발행·수정·수록/수집 시각과 기준 전 버전 | 과거 조회라 최초 수록 지연 미측정 |
| 범위 완주 | 실제 운영 창의 전 페이지+복구·재확인 포함 한도 충족 |11첫 페이지+3재조회는 하루 운영량이 아님 |
| 이용 범위 | 제공처/출처별 AI입력·요약공개·근거보관 확인 | BLS 공공 자료 근거 확인, Marketaux·기업 원자료는 별도 미확인 |
| 품질 | 정정/조건·미발표·동일 사건의 기대 판정과 사람 검토 | 실제 예외 사례 확보, 새 판정기 구현은 후속 |

**선택:** 공통 계약과 필터·사건/근거 분리 설계를 확정하고 BLS HTML 어댑터를 다음 구현 대상으로 둔다. 공식 예정 발표+시장/업종/기업 탐색 API는 우선 검증할 조합으로 유지한다. Marketaux는 개발 연결 상태이며 공개 운영 채택은 보류한다. 회사별 IR 전수 연동·유료 제공처 추가·Luna 기본 모델 전환은 이번에 확정하지 않는다.

[BLS 이용 안내](https://www.bls.gov/bls/linksite.htm)는 자체 공공 자료 사용과 출처 표기를 안내하고 일부 사진·그림은 예외로 둔다. 이 범위를 기업 IR·SEC에 올라온 제3자 문서·Marketaux 전체에 확대 적용하지 않는다. [Marketaux 약관](https://www.marketaux.com/tos)의 제3자 콘텐츠 조건도 남아 있다.

마지막 API 응답의 일일잔여20은 당시 스냅샷이며 현재 잔액이 아니다. 이번14GET으로 유료 뉴스 구독이나 OpenAI 비용은 추가하지 않았다. 기존 X+AI 월 견적은 제공처 비용 미포함인 조건부 견적으로 유지한다. 예정된5운영일 실시간 관측·정정/업종 표본 추가·운영 라이선스 확인은 완료하지 않았고 예약 작업도 등록하지 않았다.
