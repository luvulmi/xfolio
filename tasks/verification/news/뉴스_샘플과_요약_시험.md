## 입력·출력·시각·실패·중복 계약

- 뉴스 조회 실험은 Marketaux 공식 API의 GET만 사용하며 키는 `MARKETAUX_API_TOKEN` 환경변수에서 읽는다. 기본 실행은 질의 계획만 보여 주고 `--run`에서만 요청한다. 기본 4질의×1페이지, 명시한 경우 최대 4×2=8요청이다. 자동 재시도·유료 플랜 구독·X 게시를 수행하지 않는다.
- 기준은 실행 시각의 UTC이며 조회 시작·끝과 수집 시각을 남긴다. 기본 최근 2일, 최대 7일까지만 조회한다. 이 조회 범위가 게시 유효 기간을 뜻하지는 않는다. 저녁에 얻은 표본은 그날 07:30 이전에 확보한 버전으로 취급하지 않는다.
- 거시 질의는 `search`로 정책·물가·고용을 찾고 기업 필터를 강제하지 않는다. 기업 질의는 예시 티커 AAPL·MSFT·NVDA와 사건 키워드를 함께 쓴다. 이 세 회사는 시험용이며 관찰 기업 목록의 최종 확정이 아니다.
- 저장 출력은 UUID·출처·원문 URL·UTC 발행 시각·기업 식별 정보·페이지 메타·필드 길이 등 최소 메타데이터다. 내용 충분성 판독에 필요한 제한된 제목·description·snippet은 메모리에서 읽어 검토하되 원문 응답·기사 전문·발췌를 디스크·Git 결과물에 보관하지 않는다. 키, 토큰 포함 요청 URL, API 오류 원문은 출력하지 않으며 반환 문자열에도 토큰 값이 포함되면 노출하지 않는다. 실제 기사 내용을 별도 OpenAI 호출로 전송하지 않는다.
- UUID로 중복 제거하되 서로 다른 UUID가 같은 사건일 수 있다. 이 실험이 사건 중복 게시 방지를 구현한 것은 아니다.
- `meta.found/returned/limit/page`와 기사 배열, 필수 ID·URL·출처·시간을 검사한다. 부분 페이지만 확보하면 제한 표본으로 표시한다. 인증·429·통신·JSON·스키마 오류는 정상 0건과 구분해 실패로 종료하고, 발행 시각이 불명확한 기사는 충분성 검토와 별개로 게시 후보에서 제외한다.
- 공개 웹 응답 표본은 사이트에 표시된 예시이며 계정의 인증 API 응답이 아니다. 표본이 동적으로 바뀔 수 있으므로 열람 시각·페이지 URL·UUID·판정 이유를 기록한다. 원문 전체 JSON·기사 전문은 보존하지 않는다.

## 한국어 요약·usage 시험 계약

실제 기사 전달 권한과 모델 키를 구분한다. 첫 모델 시험은 직접 만든 가상 영어 자료 6건만 사용한다. 충분 4건은 거시·업종·실적·확정 사업 변화, 보류 2건은 기간 누락·조건절 절단을 다룬다. Marketaux 원문을 모델에 자동 전달하지 않는다.

- 기본 실행은 가상 입력·기대 판정·설정만 출력한다. 실제 호출은 키와 `--run`이 모두 있을 때만 수행한다.
- 모델은 GPT-5.4 Mini, Responses 구조화 출력, `store=False`, reasoning none, 자동 재시도0, 도구 없음, 출력 상한으로 최대6회만 호출한다.
- 출력에는 한국어 요약·선정/보류 이유·입력 source ID·해당 입력 안에 실제 존재하는 근거를 요구한다. 부족한 조건을 추정하지 않는다. 불완전·거절·빈 응답·usage 누락은 실측 성공으로 세지 않는다.
- 실제 호출마다 모델·실행 시각·지연·input/output/total 토큰·상태를 기록한다. 가격표의 단가로 계산한 토큰 비용과 실제 카드 청구를 구분한다. 모의 usage는 실측으로 집계하지 않는다.
- 기계 검사는 존재하지 않는 ID·빈 근거·영어만 있는 출력·보류인데 남은 요약을 탐지한다. 단순 문자열 포함은 사실 정확성 검증을 대신하지 않는다.

사람은 주체·변화·시점/기간·수치·단위·조건·원문 근거를 판정하고 하나라도 핵심 오류가 있으면 해당 초안을 불합격으로 둔다. 가독성은 별도 0~2로 평가해 사실 오류를 평균에 숨기지 않는다. X 완성본은 필수 시각·출처·링크를 포함한 가중 길이로 별도 검사한다.

스크립트는 현재 환경변수만 읽는다. 프로젝트 `.env`를 사용할 때는 `uv run --env-file .env python scripts/experiments/news_summary_probe.py --run`처럼 uv에서 로딩한다. API/통신 오류는 첫 실패에서 배치를 중단하고 계획·실행·미실행·usage 미확인 건수를 남긴다. 키·오류 본문은 출력하지 않는다.

## 공개 운영 활성화 조건

1. 거시·기업 유형별 표본에서 선정 가능한 근거가 확보되는지 확인한다. 회사 태그 오탐·절단·홍보·의견 제외를 처리할 수 있어야 한다.
2. 자료 전달·공개 요약·보관 조건이 적용 용도에 맞는지 확인한다.
3. 실제 모델의 핵심 사실 오류·보류 판단·한국어 품질과 usage를 측정해 월 비용을 보완한다.
4. 내부 개발 대상·30시간 순서·조사 발표는 확정했다. 위 조건 미충족이면 공개 운영을 보류하고 제공처/입력 범위 대안을 검토한다. 개발 선정과 운영 적합성 확인을 구분한다.
