| 기능 | 구현·경계 |
| --- | --- |

| 수집 커서 | 제공처+질의 설정 해시+범위별 완료 시각. 필수 질의 전부 완료 때만 전진. 부분/실패·공백·동시 갱신 충돌은 전진 금지 |

`SourceRecord`, `EvidenceClaim`, `NewsEvent`, `CollectionRun`을 구현했다. 숫자·단위·기간·비교 기준 및 조건부 사건의 조건을 검사하고 근거 문단을 출처 버전에 연결한다. 이 검사는 형식·출처 연결 검사이며 의미와 중요도의 자동 판정기가 아니다. 첫 CPI는 사람이 검토할 상태를 유지하며 실제 게시 기능으로 연결하지 않는다.

현재 BLS 일정 페이지는 미래 일정만 제공한다. 최신 CPI 한 건 조회를 과거 7일 전체 수집으로 표시하지 않으며 BLS 조회가 운영 커서를 전진시키지 않는다. 발표 지연·정정의 과거 전체 이력 복원도 미구현이다. 동일한 추출 수치라도 다른 문단이 바뀌면 `same_claims_new_source_review_required`로 남긴다.

SQLite 커서는 `news-check --run --save-run`에서 연결했다. 최초 성공은 명시한 시작점 이후의 완료 구간만 의미한다. 이후 공백은 `gap_requires_recovery`, 경쟁 실행은 `stale_cursor`로 실행 기록에 남는다. 조회 범위를 자동 생성하는 스케줄러·7일 초과 공백 해소·클라우드 DB 이식은 별도다.

## 실제 BLS 확인

- 기본 httpx 요청은 CPI·주별고용·일정 3주소에서 HTTP 403이었다. 식별용 `XFolio-Research/1.0` User-Agent의 CPI·일정 요청은 HTTP 200이었다. 수집기는 이 식별값을 사용하고 403을 받으면 우회나 자동 재시도 없이 실패 처리한다.
- 01:20 KST 두 번의 관측에서 CPI 2026-09, 발표 `2026-10-14T12:30:00Z`, 월간 0.6%·연간 3.7%를 추출했다. 현재 새 뉴스가 아니라 기존 자료의 파싱 시험이다.
- 겨울과 여름의 향후 발표 시각을 각각 13:30/12:30 UTC로 변환했다. 일정의 다음 CPI는 11월 10일이므로 10월 26~30일 관측만으로 새 CPI 발표 지연을 측정할 수 없다.
- 저장 결과는 첫 조회 `new_event`, 재조회 `same_source_version`이었다. 첫 설명문·일정 표를 [외부 API 없는 fixture](../../tests/fixtures/bls/)로 보존했다.

근거: [BLS CPI](https://www.bls.gov/news.release/cpi.htm) · [발표 일정](https://www.bls.gov/schedule/news_release/cpi.htm) · [BLS 자료 이용 안내](https://www.bls.gov/bls/linksite.htm). BLS 자체 공공 텍스트와 출처 표기를 사용하며 사진/삽화 예외를 다른 제공처에 확대하지 않는다.

## 시장·업종 표본

[실패 기록](assets/provider_observations/observation_20261025_1.json) · [정규화 후 표본](assets/provider_observations/observation_20261025_2.json)

첫 실행은 소수 초가 있는 조회 시각으로 HTTP 400·1요청이었다. 관측 시각을 초 단위로 정규화한 뒤 6요청이 모두 HTTP 200이었다. 오류 응답 본문은 보존하지 않았으므로 400의 서버 측 원인을 확정하지 않는다. 합계 Marketaux 7요청, 성공 표본 고유 18건, 마지막 일일 잔여 13은 당시 스냅샷이다. OpenAI 호출은 없다.

고정한 사건 이름 없이 최근 24시간의 시장/업종 키워드로 검색했다. 각 질의 최대 3페이지이며 시장 found 49, 업종 found 53으로 둘 다 partial이다. 정적 페이지 수는 17+18=35요청 추산이며 실제 완주량·하루 총량이 아니다. 미국 지역/관찰 기업 필터가 없는 의도적인 범위 시험이라 인도·기타 시장 기사가 섞였고, 이 표본으로 제공처 전체 품질을 일반화하지 않는다.

## 5운영일 관측 계약

- 목표 날짜: 2026-10-26~30, KST 07:20와 07:29. 지연 실행은 실제 시각을 기록하며 07:30 이전 확보로 소급하지 않는다.
- 명령: `uv run --no-sync python scripts/experiments/provider_observation.py --run`.
- 기본은 무통신. 실제 실행에서 환경변수 또는 로컬 `.env`의 키를 사용한다. 회당 BLS 최대 2GET·Marketaux 최대 6GET, 날짜별 예약 파일 최대 2개로 재시도를 제한한다. 이미 예약한 슬롯은 실패해도 삭제하지 않는다.
- 기록: UUID별 최초 관측 시각, 발행→관측 간격, 같은 날짜 두 표본의 차이, 페이지 추산·부분 수집·HTTP 오류. 이 간격은 API 최초 수록 지연 자체가 아니다. 원문은 저장하지 않는다.
- 한계: 시장/업종의 제한 표본이며 기업 매30분 조회·전 페이지·장애 복구까지 포함한 하루 운영량 시험이 아니다. 5일 후에도 권한·근거·범위 완주가 미충족이면 일반 제공처를 합격 처리하지 않는다.
- 예약 관측 완료와 제품 예약 배포는 다르다. PC/Codex 미실행·네트워크 문제로 놓친 회차는 누락으로 기록한다. 현재 0/5이며 당일 주말 시험을 운영일 수에 넣지 않는다.
- Codex 이 대화의 후속 관측 예약을 등록했다(자동화 ID `5`, 10회). 운영용 Windows/클라우드 예약 배포와는 별개다.

## 이용 조건 확인용 문의 초안

다음은 Marketaux에 확인할 구체적인 용도이며 **발송하지 않았다**.

> 미국 시장·기업 뉴스의 제목/description/snippet을 OpenAI API에 전달해 건별 한국어 요약을 만들고, 하루 최대 3건의 뉴스 글을 출처명·원문 링크와 함께 공개 X 계정에 게시하려 합니다. 전문을 복제하지 않습니다. 반환 근거와 사용 버전을 내부 SQLite 및 백업에 30일 보관하고 게시 기록은 유지하려 합니다. Free 또는 유료 플랜에서 외부 AI 전달, 자체 요약의 공개, 근거/백업 보관, 서비스 종료 후 이미 게시한 요약의 존치가 각각 허용되는지와 적용되는 API 라이선스를 확인 부탁드립니다. 원매체별 추가 허가가 필요하면 그 범위도 알려주십시오.

5일 관측은 이용 허가를 대신하지 않는다. 답변이 없을 때 허가로 간주하지 않고 현재의 공개 운영 불채택 판정을 유지한다.
