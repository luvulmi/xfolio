`SourceRecord`, `EvidenceClaim`, `NewsEvent`, `CollectionRun`을 구현했다. 숫자·단위·기간·비교 기준 및 조건부 사건의 조건을 검사하고 근거 문단을 출처 버전에 연결한다. 이 검사는 형식·출처 연결 검사이며 의미와 중요도의 자동 판정기가 아니다. 첫 CPI는 사람이 검토할 상태를 유지하며 실제 게시 기능으로 연결하지 않는다.

현재 BLS 일정 페이지는 미래 일정만 제공한다. 최신 CPI 한 건 조회를 과거 7일 전체 수집으로 표시하지 않으며 BLS 조회가 운영 커서를 전진시키지 않는다. 발표 지연·정정의 과거 전체 이력 복원도 미구현이다. 동일한 추출 수치라도 다른 문단이 바뀌면 `same_claims_new_source_review_required`로 남긴다.

SQLite 커서는 `news-check --run --save-run`에서 연결했다. 최초 성공은 명시한 시작점 이후의 완료 구간만 의미한다. 이후 공백은 `gap_requires_recovery`, 경쟁 실행은 `stale_cursor`로 실행 기록에 남는다. 조회 범위를 자동 생성하는 스케줄러·7일 초과 공백 해소·클라우드 DB 이식은 별도다.

## 실제 BLS 확인

- 기본 httpx 요청은 CPI·주별고용·일정 3주소에서 HTTP 403이었다. 식별용 `XFolio-Research/1.0` User-Agent의 CPI·일정 요청은 HTTP 200이었다. 수집기는 이 식별값을 사용하고 403을 받으면 우회나 자동 재시도 없이 실패 처리한다.
- 01:20 KST 두 번의 관측에서 CPI 2026-09, 발표 `2026-10-14T12:30:00Z`, 월간 0.6%·연간 3.7%를 추출했다. 현재 새 뉴스가 아니라 기존 자료의 파싱 시험이다.
- 겨울과 여름의 향후 발표 시각을 각각 13:30/12:30 UTC로 변환했다. 일정의 다음 CPI는 11월 10일이므로 10월 26~30일 관측만으로 새 CPI 발표 지연을 측정할 수 없다.
- 저장 결과는 첫 조회 `new_event`, 재조회 `same_source_version`이었다. 첫 설명문·일정 표를 [외부 API 없는 fixture](../../tests/fixtures/bls)로 보존했다.

근거: [BLS CPI](https://www.bls.gov/news.release/cpi.htm) · [발표 일정](https://www.bls.gov/schedule/news_release/cpi.htm) · [BLS 자료 이용 안내](https://www.bls.gov/bls/linksite.htm). BLS 자체 공공 텍스트와 출처 표기를 사용하며 사진/삽화 예외를 다른 제공처에 확대하지 않는다.
