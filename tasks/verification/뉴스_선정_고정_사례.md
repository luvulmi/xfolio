# 뉴스 선정 고정 사례 · 초기 구현 계약

- 기준일: 2026-10-28, Asia/Seoul
- 상태: 사용자 위임에 따라 상세화한 **초기 인수 기준**. 합성 fixture·순수 선정 정책·회귀 시험 구현. 근거 추출·AI 중요성 판단·생성기·실뉴스 품질 검증은 별도다.
- 기준: [요구사항](../../docs/요구사항.md) · [운영 정책 R01~R04·R07·R09](../../docs/운영_정책.md) · [MVP 구현 계약](2주_MVP_구현_계약.md)
- 범위: 허용 입력의 관련성·새 사실·근거·중복·선정 순서·글 구성을 외부 API 없이 평가한다. 검색 재현율·제공처 이용 조건·실제 X 길이 검증은 별도다.

## 공통 입력과 판정 순서

아래 기관·기업·수치·사건·문구·URL은 **전부 합성 자료**다. 실제 미국 발표나 기업 편입 사실을 뜻하지 않는다. 가상 출처 `Fixture News`는 Marketaux 응답 형식에 넣을 수 있는 시험용 매체명일 뿐 실제 공급자가 아니다. 모든 자료는 `synthetic=true`, `can_publish=false`로 고정하고 실제 X adapter에 전달하지 않는다. `https://example.invalid/`는 원문 위치의 자리표시자다.

시험일 `D=2026-10-28`은 고정 달력 fixture에서만 AM·PM 운영일로 지정한다. 아래 시각은 모두 `D`의 KST이며 저장 시 UTC로 변환한다. 실제 거래소 달력을 검증한 결과로 사용하지 않는다. AM 정보 기준은 07:30, PM 기사 발행 기준은 17:30·근거 동결은 17:45다. 기본 수집 상태는 `complete`다.

- 입력마다 `article_id`, `source`, `url`, `published_at`, `updated_at`, `collected_at`, `evidence_version`, `event_key`, `fact_version`, `claims`, `index_relation`, `rights`를 둔다. 없는 수정 시각은 `null`로 명시한다.
- `claims`의 각 주장은 `claim_id`, 허용 근거의 `evidence_id`·문장 위치, 주체·변화·사건일/대상 기간, 수치의 단위·비교 기준·조건을 연결한다. 없는 항목은 추정하지 않는다.
- `rights`는 수집·보관·AI 전송·요약 공개 권한을 각각 구분한다. 합성 자료의 시험 내 사용 허용을 실제 기사의 권한으로 전용하지 않는다. N09의 권한 미확인은 AI 호출 전에 차단한다.
- 순서는 **권한/시간 → 필수 근거 → 확정된 새 사실·관련성 → 사건/사실 중복 → 중요도·영향 범위 → 편성 한도**다. 채택은 선정 후보 합격이며 발행 승인이 아니다.
- `exclude`는 개별 기사 제외, `duplicate`는 기존 사건/사실에 근거만 연결, `hold`는 이미 구성/승인된 편성의 발행 보류로 구분한다. 정상 수집 뒤 개별 기사 제외를 편성 전체 수집 실패로 확대하지 않는다.

대표 URL은 `https://example.invalid/news/N01`처럼 ID를 붙인다. 각 `E{번호}`는 해당 ID의 수집 당시 허용 근거 버전이고 원자료 전문 저장을 전제하지 않는다. N05는 E02를 대체해 더 좋은 근거라고 가정하지 않는다. N07~N09는 개별 기사 제외의 이유를 각각 검증하기 위해 다른 모든 조건은 통과하도록 둔다.

N03의 경계 변형은 **회사 공식 가이던스 변경 발표**다. A가 다음 분기 매출 가이던스를 기존 90~100억 달러에서 95~105억 달러로 변경했다고 공식 발표하고 기간·이전/새 범위·조건이 허용 근거에 있으면 `ELIGIBLE_OFFICIAL_GUIDANCE`로 N02의 같은 실적 사건에 묶을 수 있다. '회사가 전망 범위를 변경했다'는 현재 발표 사실만 서술하고 다음 분기 매출 실현을 단정하지 않는다. 애널리스트 목표가·주가 전망·루머를 제외하는 N03/N04와 구별한다. 새 글 한도를 추가로 차감하거나 별도 사건으로 중복 발행하지 않는다.

## 선정 순서와 통합 시나리오

중요도는 설명 가능한 질적 비교로 정한다. 관련성과 확정 사실의 중요성을 먼저 검토하고, 동급이면 영향 범위 → 새 사실 발표 시각 내림차순 → 기사 ID 오름차순을 적용한다. 비교할 수 없는 수치의 크기로 순위를 만들지 않는다. 아래 순위는 이 fixture의 명시된 사실에만 적용되며 모든 거시 기사가 모든 기업 기사보다 항상 앞선다는 규칙이 아니다.

| 시험 | 입력·전제 | 기대 결과 |
| --- | --- | --- |
| AM-2 | N01~N04·N07~N09, 정상 두 지수·완전 수집 | N01→N02 선정. 미국 전체 발표가 개별 구성기업 변화보다 영향 범위가 넓다는 이유 기록. 지수 1글→N01→N02의 최대 3글 스레드 |
| AM-1 | 위에서 N02를 제거 | 지수 1글→N01. 남은 자리를 N03/N04로 채우지 않음 |
| AM-0 | N03·N04·N07~N09만 있고 정상 두 지수·완전 수집 | 지수 1글에 '이번 수집 범위에서 선정 뉴스 없음' 표시. 시장에 뉴스가 전혀 없었다고 표현하지 않음 |
| AM-P | AM-2와 같지만 필수 뉴스 수집 `partial` 또는 두 지수 중 하나 누락 | AM 전체 보류. AM-0으로 처리하지 않음 |
| PM-2 | AM에 N02 게시 완료, PM은 N05·N06·N10·N12, 최종 완전 수집/동결 완료 | N12→N06의 독립 글 2개. N05 중복·N10 기준 이후 제외. 두 사건을 한 스레드로 묶지 않음 |
| PM-0 | N05·N10만 정상 수집 | 게시 0개·정상 0건 기록·푸시 생략 |

| FROZEN | N06이 포함된 미전송 PM 편성 승인 뒤 N11 발견 | 기존 버전 승인 해제·해당 편성 보류. 문제 기사를 제외해 우회 재개하거나 나머지 글을 독단적으로 이어 보내지 않음. 이미 전송된 요청은 결과 대조하고 partial/unknown 보존 |

N06b는 순위 시험을 위한 N06의 별도 거래 T2 변형이며 기존 T1과 다른 독립 사건이다. 후보 탈락·미선정은 사건/사실 게시 이력으로 기록하지 않는다. 게시 성공/예약/unknown 중복 차단과 기사 중복은 별개다.

## 구현 후 판정과 남은 검증

- 위 12건의 기본 판정·이유 코드, AM/PM 구성·순서·사건/사실 구분이 기대값과 일치해야 한다. 모델 형식 성공만으로 통과시키지 않고 문장별 근거를 운영자가 대조한다.
- 거짓 양성(제외 대상 채택), 중요 새 사실 누락, 기간/단위 변조, 기준 이후 포함, 동일 사건 재게시, 근거 없는 인과/예측은 각각 따로 집계한다. 이 작은 사례 집합 통과는 실뉴스 전체 품질을 보장하지 않는다.
- 기계 판독 [12건 fixture](../../tests/fixtures/news_selection/cases.json), [순수 선정 정책](../../src/xfolio/news_selection.py), [회귀 테스트](../../tests/test_news_selection.py)로 전환했다. fixture의 입력과 기대값은 분리하고 구현에는 기대값·사례 ID별 판정표를 전달하지 않는다. 기존 `EvidenceClaim`의 숫자/기간/조건 검증을 재사용한다.
- `index_relation`의 관련성·중요성·영향 범위·검토 근거와 `material_new_fact`는 사전에 검토된 입력이다. 코드가 기사에서 중요성을 스스로 추출하거나 근거의 진실성을 증명한 결과가 아니다. `critical/material`은 질적 순위이며 의미 없는 수치 점수를 생성하지 않는다. 출력은 합격 후보도 항상 `can_publish=false`다.
